# Documentation Maintenance Sync

## 目标与适用范围

让文档跟随真实工程行为更新：按变更影响选择文档，核对代码与配置，做最小必要同步并检查遗漏。

工程变更可能同时影响使用说明、架构说明和接口约定，应分别更新受影响内容，不能以去重为由漏掉必要说明。科研文档的修订见下文“科研文档”，不默认套用工程同步清单。

## 工程触发规则

以下变化涉及现有说明时，使用本 Skill 同步：

1. 修改 Agent／开发者约定、依赖边界、配置或测试方式。
2. 修改 CLI 参数、环境变量、默认值、错误行为或输入／输出格式。
3. 新增、删除、移动源码、脚本、测试或配置入口，导致目录和使用说明不准确。
4. 修改数据库表、存储契约、数据模型或迁移方式。
5. 修改切块、编码、召回、融合、指标或报告模块的职责、流程及扩展方式。

仅修复内部 bug、调整测试 Mock、注释、格式或日志，且未改变已描述行为或使用方式时，通常不需要同步文档。

## 同步步骤

1. 识别变化的接口、配置、数据结构或流程，选择受影响的文档。
2. 对照实际代码、配置和已有验证结果；区分当前实现与尚未实现的计划，不从记忆补写行为。
3. 更新失效段落，保留仍适用的结构和说明；不同读者所需的示例与使用解释不视为必须删除的重复。
4. 新增、移动或删除文件时，修正受影响的导航、引用和目录说明；`CLAUDE.md` 指向根 AGENTS.md，无需维护第二份正文。
5. 用 `rg` 和 `git diff` 检查旧路径、旧字段与描述是否仍有遗漏；只运行与本次影响相符、当前仓库实际具备的检查。

## 科研文档

研究计划、讨论、评测设计和实验记录遵循 [AGENTS.md「科研文档维护」](../../../AGENTS.md#十三科研文档维护)。纯科研修订无需套用上面的工程映射；同时涉及代码时分别处理。研究假设和方法选择以当前决策为依据，不能由已有代码反推它们已经定案。

涉及报告索引时，使用[现有脚本](../../../scripts/build_report_index.py)更新并以 `--check` 检查。科研内容归属规则只在 AGENTS.md 维护，本 Skill 不再复制。

## 约束与分工

- 不写入密钥、Token 或其他私密配置；核对变量名和格式时使用公开样例。
- AGENTS.md 保留稳定约定，工程细节放对应说明；不为文档同步扩展架构或修改无关代码。
- 一次性测试、排障过程通常放 PR 描述，不写入稳定架构；需要独立保存的实验实证仍按研究用途保留。
- 本 Skill 负责文档改写；接口兼容性判断和跨配置取值核对是另外的工作，文档更新不能替代它们。已有审查清单可供参考，不默认增加固定的前置 Skill 链。
- 路径、命令与 CI 门槛以本仓库为准，不继承上游 MySQL／MQ／HTTP 文档映射或不存在的检查脚本。

## 最终回复

说明同步了哪些文档、为何需要同步，以及实际运行的检查和未解决事项；不为普通修订另建维护报告。
