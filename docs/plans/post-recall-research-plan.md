# 三路召回后的关键差异：研究思路与暂定计划

> 2026-09-07。本文维护研究问题、候选假设与实验设计。当前阶段先确认研究边界内的错排现象是否存在且可复现；NevIR 是受控检验材料，尚未被确定为正式主评测集。T2 的已有资产和原探索安排保留，恢复全量编码不是当前核查的前置条件。正式查询划分、标注规模、方法和正式实验参数仍未冻结；已执行探索的范围与参数有独立记录，实际进度以 CURRENT_STATUS 为准。
> 项目进度只维护在 [CURRENT_STATUS](../CURRENT_STATUS.md)；历史判断及其来源见[独立审查与回应](research-direction-review-2026-09-06.md)。本文不恢复旧 R1／R2／Gate 流程。

## 1. 要研究什么

原始问题是：**在三路召回形成的固定候选集合中，近似候选之间决定查询适用性的关键区别，是否被现有排序表示保留并有效利用？**

候选可能都是真实文本，错误发生在“这段话是否适合回答这个问题”。区别可以涉及时间、对象、单位、版本、否定、条件及其对应关系，不以列全场景为研究任务。

边界保持不变：

- 固定 Dense、Learned Sparse、BM25 召回后的完整候选集合，以及当时已有的正文、逐路分数、顺序和元数据。
- 不修改召回、切块或查询，不补检索，不在排序时读取父文档或补充上下文。各方法看到的候选和正文范围一致。
- 当前 38 维 LambdaMART 是工程起点；它已有词语／数字覆盖、部分词序和候选上下文，不能描述成完全不使用这些信息。
- 排序输入没有提供的区别，不要求方法凭空恢复；但这类查询不能为了使方法显得有效而从评测总体中消失。

投稿目标仅为 IEEE BigData Undergraduate。研究逻辑由问题和证据决定；不因投稿目标降低证据要求，也不预先保证方法创新成立。

### 1.1 当前阶段：先验证问题存在且可复现

负责人已明确：当前寻找数据集，是为了获得独立、可信、可复现的问题证据；本阶段不要求先提出新方法，也不要求证明候选比较优于单候选匹配。完整对齐原文保存在[讨论记录附录 E](research-direction-review-2026-09-06.md#附录-e2026-09-07-当前阶段目的对齐原文)。

要检验的现象是：**在三路召回后的固定候选中，正文已经包含区分所需的信息，但现有排序器仍把不符合查询要求的近似候选排在适用候选前面。** 证据需连接三项事实：

1. 适用与近似但不适用的候选实际共同进入三路去重并集，不要求每一路都召回两段；不补入标准答案，也不人为固定真实三路分数。
2. 关键区别如何影响查询适用性，有可靠、可复核的正文与标签依据；针对准备作为错误证据的具体实例核实，不要求先重标整个数据集。有歧义的判断保持未决，不算确定反例。
3. 保存查询、完整候选及正文、三路分数／排名、基线版本与配置，在相同输入上能够重现该错误。

少量明确反例可以证明现象存在，不能估计发生频率、自然总体影响或任意场景能力。反例也不自动证明错误由“38 维表示遗漏关键关系”造成；表示、训练、分数证据或其他原因要另行区分。既有手工特征交换只证明一个表示盲点，不代替这条实际错排证据链。

**现有数据是否够用：足以开展这一阶段的受控检验。** NevIR 提供近似正文、查询及成对偏好，不必先继续寻找覆盖所有场景的完美数据集；实际共同召回、具体错误与重放仍需实测连接，数据格式本身不能保证结果。英文基础能力是执行条件，通道或模型的语言限制需要单列，不能全部归因于关键差异处理。当前已取得的实测证据及其范围见[实测报告](../reports/nevir_controlled_retrieval_2026_09_07.md)，项目下一步只在 CURRENT_STATUS 维护。

T2 保留自然搜索背景的用途，其现有前缀和标签观察尚不足以支持自然发生率。本阶段不需要先恢复 T2 全量，也不需要先实现 B1、D 或训练新模型。若受控检查未观察到目标错误，只能说明在已检查范围没有复现，不据此证明问题不存在。

## 2. 当前依据与候选假设

| 已有依据 | 能支持的判断 | 仍然不知道什么 |
| --- | --- | --- |
| 手工交换“版本—年份—权限”对应关系、固定三路输入后，38 维特征不变 | 存在一个具体的表示盲点 | 自然发生频率、真实错排规模，以及何种补充有效 |
| Qwen 直接重排，以及将其分数加入历史 LambdaMART，均有负收益记录 | 重新引入文本模型需要具体新理由 | 不能断言所有文本模型或接入方式都无效，也不能确定历史失败的唯一原因 |
| 现有基线包含覆盖率和候选统计 | 新方法必须解释比这些已有信息多了什么 | 加入局部信息或比较候选是否有可泛化收益 |
| NevIR 实际三路候选与冻结基线的[受控错排重放](../reports/nevir_controlled_retrieval_2026_09_07.md) | 正文包含关键条件及主体区别时，现有系统仍可能错排；本阶段无需继续等待大库才能获得反例 | 不能据此确定表示成因、自然频率、新方法收益或跨场景适用性 |

这些依据的原报告、代码入口与限制集中保留在[独立审查](research-direction-review-2026-09-06.md#3-已找到的项目证据及其限度)，此处不另建证据台账。

以下属于后续方法研究，不是 §1.1 问题复现的前置条件。目前保留的候选方向是：**用近似候选的差异位置，帮助选择检查查询匹配证据的位置。** 若继续研究这个方向，只检验一个核心假设：

> 在相同输入和可比计算预算下，差异位置引导的局部匹配，能否比充分的单候选局部匹配提供额外排序收益？

这是待验证的假设，不是已经确定的方法。它把“候选比较是否有必要”本身交给实验检验。窗口宽度、文本对齐、近邻选择、聚合方式和启用条件均未定案，不沿用上一轮举例时的数值。

暂不把文本比较器、特殊三路门控或局部交换设为必需组件。局部匹配不等于理解任意对应关系；例如“甲收购乙”和“乙收购甲”，某些词项集合或邻近统计仍可能无法区分。经典局部匹配、差异分解和候选协作思想也不能直接作为本项目的创新主张；后续须针对实际机制核对[已有文献线索](robust-fusion-literature.md)。

### 2.1 下一轮交接范围：已有错误的机制分析与方法候选

受控存在性与固定输入重放已取得证据，下一轮先利用现有结果缩小值得改动的范围。当前有两个竞争解释：现有特征没有充分表达查询条件及其对应对象，或已有信号存在但训练／组合方式没有有效利用。具体案例的 13 维差异不能区分这两个解释，特征变化或重要性也不能单独证明因果。

本轮交接的建议工作是：

1. 使用已有 20 组配套查询、完整候选和冻结模型结果，比较查询条件改变后文本特征与模型偏好的变化。正确组同样保留，逐路分数及候选池变化另列，避免把自然变化误当作严格控制后的查询理解效应。输出最值得检验的缺口，不要求先证明完整因果关系。
2. 围绕缺口筛选最多两个有文献依据的方法候选，逐个解释如何计算、如何可能处理现有反例、会丢失什么信息、有哪些现成实现及必要对照。不先冻结差异窗口或融合结构；若引入文本模型，需要具体新理由，不能将先研制一个通用可靠细节理解器作为前提。
3. 候选确定后再讨论最小实现与统一实验。正式效果比较须区分针对性训练／语言适配、新增表示及候选比较的收益；普通基线与新方法应有可比训练条件。已看过的 20 组用于开发，效果确认所需的独立数据和监督隔离另行确定。

当前交付目标是“已有错误的机制分析＋最多两个方法候选”，不是启动训练、扩库或实现某套算法。该范围不改变 §6 的公平对照要求，也不将普通重训或单纯发现旧模型低分视为方法创新。

## 3. 评测集怎样避免偏向方法

**数据来源按证据用途区分。** 原始 T2Ranking 保留为真实搜索候选来源；当前以英文 NevIR 承载范围较窄的受控差异与三路衔接检验，见 §3.4。后者不能替代自然查询的发生率或总体收益证据，也尚未被确定为正式主评测集。英语、中文或两者兼用均可，语言选择与结论范围须如实说明。医学数据不承担主结论，不开展医学专项清洗；历史 LLM 构造材料也不混入自然错误率与真实查询收益的汇总。

在查看增强方法结果前，先定义各实验所用查询总体、语料范围和抽样方式。按查询抽样，保留完整候选池；不能按差异明显、基线排错、判断依据充足或方法成功来挑查询。算法仍暂定，不能为了差异窗口方案而筛选数据。负责人已选择完整原始 T2 语料；查询划分及正式样本尚未选定。

下列情况都应有明确去向和数量，不能静默丢弃：

- 没有近似候选、候选比较不触发，或基线原本已经正确。
- 候选池中没有可用答案，或者全部候选为空。
- 真实适用性已知，但排序输入缺少判断所需信息。
- 标签未完成、真值仍有争议、候选正文缺失或某一路召回失败。

其中，正文缺失和召回失败属于输入问题，应单列并保留在抽样统计中，不能用空文本或伪造分数补齐。与“信息不足”“没有可用答案”也不能混为一类。是否存在可用答案须有相应判断覆盖支持；只检查部分候选后未发现答案，应记录“在已检查范围内未发现”，不能直接判为全池无答案。完整候选输入与实际标注范围分开，具体安排见 §4.1。

相似程度可以作为分析分层，定义应在比较方法效果之前明确，不能根据新方法的表示、置信度或成功情况划分。若为了研究少见情况而增加某类样本，必须说明抽样方式；没有适当的抽样权重时，只能报告该样本集的结果，不能称为真实总体发生率。

查询及其相关性监督的划分见 §3.2；检索语料允许共享。手工交换例子只用于检查程序和表示，不混入自然数据的效果或频率统计。

还有两项会直接影响复用的历史事实：

1. [既有正文审计](../reports/sqlite_share_restore_and_asset_reconciliation_2026_08_28.md)记录 SQLite 的 `990126/990127` 各 800 条正文存在乱码，与原始下载内容不一致。本轮未重做正文审计；后续应优先使用原始公开文件，不能直接沿用这两组入库正文及其编码结果。

优先 T2 的理由是自然查询来源、分级标签和与排序任务的契合，不是它是否容易产生适合差异方法的例子。上述其他材料只说明已有库存，不构成多数据集并行研究计划。有关医学材料重合和查询重复的判断沿用 2026-08-28 的既有审计，本次文档修订没有新增全量扫描。

负责人已明确优先使用现有 RAG 基础设施，**不再把全量索引成本或基础设施准备列为当前研究阻塞项**。这是工作优先级的决定，不代表已经核实原始 T2 全量三路索引或候选缓存就绪。后续仍须说明实际使用的语料和召回配置，不能只拼接抽中查询的正例，再声称测得自然候选分布。候选取得后对所有排序方法固定，不因方法改变而补检索或补正文。

公开 qrels 可减少相关性标注，但不能自动标出“关键条件错排”；补充判断围绕实际评价需要安排。本节记录数据优先级与已有材料，没有抽取查询、划定正式测试集或生成新数据。

### 3.2 查询划分与共享语料

可以从原始公开数据自行划分训练、开发和留出验证查询，不必使用官方命名的 Test。明确每组查询及其相关性监督用于训练、调参还是最终评价，处理跨组的重复、等价查询及同一问题的模板改写。检索 corpus 可以由各组共享，不要求把训练查询涉及的文档从测试索引或候选池中删去。近似但关键细节不同的候选正是研究对象，不能被通用语义去重一并清除。

若旧模型已经用过新留出部分的监督，正式对照须在共同的新划分下重新训练；旧冻结模型只能另作工程参考。仅改名或重新划分文件不能产生独立性。历史使用范围依据已有记录说明，无法确认的部分保留限制，不新增全局哈希或封存台账。用于观察错误、修改方法的探索样本归入开发材料，不再充当独立的最终确认。论文须明确报告自定义划分，不能将其成绩称为官方 Test 成绩。

### 3.3 探索输入准备与交接

**本节保留已确定的 T2 探索安排；当前不自动续跑，也不是 NevIR 核查的前置条件。** 原安排为完整原始 T2 collection，以及首次从原始 Dev 随机抽取 20 条查询。 查询总体取 §3.1 本地目录中的 `queries.dev.tsv`，按来源查询 ID 无放回随机抽样，固定种子 `20260906` 并记录抽取顺序，不按正例是否存在、标签覆盖、基线错误或差异明显程度筛选；无标签、空池或失败的查询保留，不补抽。保留原始查询，记录重复／已识别等价查询的关联，分析时不把它们当独立证据，后续划分按 §3.2 同组处理。Dev 有公开分级标签，且历史曝光可明确归入开发，适合尽快了解候选和标注成本；代价是这些观察不能提供独立的最终确认，也未知其现象能否推广。这 20 条只用于检查官方标签覆盖和估算人工工时，全部归入开发材料。历史子集上的单题连通检查只验证工程链路；正式 train／dev／test、评价数量和判断深度仍待确定。

语料使用同目录完整 `collection.tsv` 的原始 passage；[t2_ingest.py](../../src/linkrag_eval/runners/t2_ingest.py) 流式读取并复用 [index_passages](../../src/linkrag_eval/store/indexer.py) 的一 passage 一 chunk 路径，不重新切块、补父文档或只拼抽中查询的正例。该路径会保存 `source_passage_id` 和运行 `chunk_id`，但不证明已有旧子集可直接复用，或全量三路索引已就绪。语料范围一经用于本轮候选生成，各排序方法共用其结果。

三路装配可复用 [recall_factory](../../src/linkrag_eval/retrieval/recall_factory.py)，其中 BM25 需 `sqlite_fts5`；完整响应可复用 [execute_candidate_contract_once](../../src/linkrag_eval/retrieval/recall_adapter.py) 的 `route_hits`／`candidate_hits` 契约。交接保留固定配置下各路**融合截断前的全部返回项**及去重并集，不只保留融合 Top-k；完整不表示扩大召回深度或取消阈值。记录输入／结果位置、代码版本，以及实际编码器、语料范围、逐路深度与阈值等运行参数，不把代码默认值或历史配置当作本轮已确认值。

接入接口与 [§4.2](#42-标签接入边界与修订范围) 对齐，不新增通用格式框架：

| 内容 | 最小交接信息 |
| --- | --- |
| 来源与查询 | 文件级记录原始 T2 下载目录及所用 query／qrels 文件；逐查询保留字符串 `source_query_id` 与原样 `query`。运行 `sample_id` 不同时显式保存对应，不能从正文或前缀猜回来源 ID。 |
| 固定方法输入 | 每路完整有序 `routes.{dense,sparse,bm25}[]`，含 `dataset_id/chunk_id/doc_id/score/rank`，保留并列时的返回顺序并注明排名起点；去重候选的已有正文及 `dataset_id/chunk_id ↔ source_passage_id` 映射。`doc_id` 保留为现有同文档统计的排序输入，不据 passage 猜父文档；`ordinal` 仅作入库映射辅助。各路失败状态与成功返回空列表分开。 |
| 独立评价输入 | 原始四级 qrels 按来源查询／passage ID 连接；显式 0 与未判断分开。标签、人工解释及信息充分性说明均不进入上述方法输入，详见 §4.2。 |

**全量入库。** [t2_workflow.py](../../src/linkrag_eval/runners/t2_workflow.py) 使用独立 eval Qdrant collection、本地 SQLite 与 BM25 文件，按原始顺序分批处理正文；原始读取器只保留 PID 集合以检查重复，不把全量正文装成字典。续接核对来源、编码器和存储配置，并逐批核对原文、身份及三个实际存储；缺数据补写，身份或正文冲突报错。Qdrant 初始化中断时，须先确认已有向量 schema、索引配置及归属一致，才补建缺失的必要 payload 索引。正常读到文件末尾、输入计数符合声明且逐批核对完成后，再对三处独立存储的真实总数与范围做末尾计数检查，排除额外旧行；全部通过才记录 `completed`。中断保存已确认进度并释放资源，续接不凭进度数字跳过原文，不增加哈希台账。BM25 通过有索引的 chunk ID—FTS rowid 映射执行批量更新，避免每批扫描全库。

负责人已授权仅限制 Dense／Sparse 编码输入副本，保留完整原始段落集合、PID、正文与 qrels，BM25 继续按全文建索引。当前采用显式策略：只有服务返回已核实的结构化长度错误时，逐条将当前前缀长度减半后重新请求；普通错误不触发截断，Dense 批错误先逐条原样检查，避免缩短本可完整编码的短文本。两路分别从原文开始处理，不级联截断，也不增加摘要或提示后缀。实现与真实服务验证的进度见 CURRENT_STATUS。

每条成功文档产物记录实际请求发送的 Unicode 字符数，随当前成功入库行保存；它不是 token 数，也不能证明服务端内部未做其他处理。续接不能把未记录长度当作未截断，当前索引受影响的唯一段落数从已完成行聚合，避免把重复编码条次冒充段落数。查询侧采用同一策略，当前运行记录保存策略而不保存逐查询发送长度。可以表述为“覆盖完整 T2 原始段落集合，超限编码输入采用截断”，不能声称全部全文都参与了两路向量编码。截断可能改变召回结果，必须作为共同召回环境披露；候选形成后对各排序方法固定，不属于排序方法创新。

**候选入口。** [exploration_input.py](../../src/linkrag_eval/runners/exploration_input.py) 每题只执行一次候选契约，[exploration_workflow.py](../../src/linkrag_eval/runners/exploration_workflow.py) 负责随机抽样、文件输出和覆盖编排。沿用实际配置的阈值与深度，rank 从 0 开始；不使用覆写阈值为 0、混写 `expected_*` 的旧缓存。仓储按 `(dataset_id, chunk_id)` 读取现有正文和来源关系，不补检索。`source_rows` 保留关联所需的原始三元行，歧义不能压成一个看似确定的 PID。

CLI `exploration candidates` 输出 `run.json`（实际参数与路径）、`queries.jsonl`（事先抽中的查询）、`inputs.jsonl`（每题候选和状态）、`summary.json`（完成汇总），拒绝覆盖已有输出。覆盖入口核对同目录的抽样清单；中断后尚未执行的题标为 `not_executed`，不会从查询分母消失。使用 `--corpus-run` 时核对成功入库记录与当前编码配置，绑定该目录的独立存储。手工指定 `--collection/--dataset-id` 仅记录已有索引的声明范围，不自动建索引，也不证明全量覆盖；两种模式互斥。

**完成标准。** 抽中查询全部有状态，能够追到三路完整列表、去重并集及每个候选的已有正文。`ranking_input_ready` 独立表示排序需要的输入是否齐全；纯来源映射缺口不阻止本可运行的基线。正文／三路契约有问题时仍保留已观测候选并报告异常，不能伪装为成功空池。标签连接是否完整由 §4.2 另行统计。实际索引范围、服务可达性和真实候选覆盖必须据运行记录判断；离线接口测试不能代替这些事实。实施与核查结果只维护在 [CURRENT_STATUS](../CURRENT_STATUS.md)。

### 3.4 NevIR 的候选用途与最小衔接检查

本节的首要用途是承载 §1.1 的受控问题复现；材料已经足以开展检验，但没有预先保证实际会出现目标错误。负责人已授权独立子任务实测现有三路英文能力，并在能力得到支持后推进 NevIR 召回检查；不切换正式主评测集、不翻译构建中文版、不把课题改为训练否定理解模型。[适用性核查报告](../reports/nevir_suitability_2026_09_07.md)保存作者来源、六组固定样本、跨划分重复及代码观察；执行结果另见 CURRENT_STATUS，本节维护设计。

**使用边界。** 原版每组有两个段落、两个查询，标签支持组内偏好。受控双文档诊断可以单列，但主要研究边界仍要求共享语料中实际取得的三路候选：两条查询独立运行，保留完整三路并集，不补入漏召回的标准段落；方法不读取官方配对 ID、来源家族、修改位置或配套查询。完全相同正文可共享存储与匿名运行 ID，近似但不同的版本全部保留。官方配对、编辑 ID、WorkerId 及来源关联只用于评价／监督映射，不能伪装成同文档输入激活候选特征。

**本轮最小实测范围。** 使用 Validation 全部 **340 个完全不同正文**形成共享语料；不按所抽查询的正例或方法表现选文档。从原始 Validation 顺序以独立 `random.Random(20260907).sample(rows, 20)` 固定抽 20 组，q1/q2 分别执行，合计 40 条查询。这是新的 NevIR 探索安排，与 T2 Dev20 不混淆。原固定六例和该探索组均属于开发材料，正式 Test 保留独立用途。

按负责人的要求，先由独立子任务用事先固定的普通英文多主题正文和字面／释义查询，检验当前模型、实际索引及三路召回。不能只以非空向量认定支持英文，也不要求先通过否定区分才允许研究否定错排。每路目标出现、严格第一名、成功空结果与调用失败分别报告；若存在基本英文主题辨别证据但部分释义失败，可在明确限制的情况下继续受控检验，不把严格检查的部分通过改写为全部通过。额外的旧 LambdaMART 普通英文检查只消费已保存候选，不新增远端请求，也不能替代目标任务的语言适用性评价。

只在英文能力得到支持后接入上述 NevIR 共享语料；模型、逐路深度、阈值和去重方式在运行前记录。按本轮外层入库批量 25、Dense 编码批量 10、40 条查询分别执行一次计算，340 段的 Dense 文档请求为 13×3＋2＝41 次，首次完整接入与查询共 **Dense 81 次、Sparse 380 次**。外层批量若取 100，Dense 可为 74 次。以上不含重试或独立英文前置探测；查询编码当前没有缓存，若重跑查询，额外请求也须计入。这是请求量估算，不是费用或时长承诺，实际请求以运行记录为准。

此规模只检查通道、标准对是否共同出现及成对错排实例，不能检验小幅方法增益。340 段背景较小，按历史较深召回配置可能覆盖大部分库；共同召回率高不能外推到大语料。若需训练和较充分背景，后续可增加 Train 的正文，Train＋Validation 共 1,761 个完全不同正文；扩容时应重新生成统一候选、BM25 统计和池特征，不能混用不同语料范围的结果。是否扩展至全部 225 个 Validation 配对，应由需要的覆盖精度／误差空间决定，不能追着新方法显著性追加样本。

**问题复现与后续方法实施分开。** 当前先核实通道、实际计算口径及被测基线的语言适用性，不为了复现错误而预先重训或实现新方法；英文不适用导致的失败不能直接解释成关键差异错排机制。以下英文共享特征、训练监督及 B0／B1／D 公平比较要求属于后续方法阶段，并非当前存在性验证的全部前置项。英文分句和否定特征的处理必须由各方法共享；不得拿新适配方法与未适配的中文冻结模型直接归因。本次观察现有系统时保留 BM25 当前实现，分别记录配置权重 2／1 与实际文本列权重 1／1，不声称已修复或使用标准词频 BM25。当前旧训练包装把非正例全部设为零，不能直接使用：完整池计算特征后，只有已判断关系进入训练损失；未判断背景继续参与排序但没有虚构负标签。第一轮记录冻结模型在受控输入中的行为，不能据其低分认定候选比较有效。正式比较 B0、B1、D 时须公平重训并沿用 §6 的对照逻辑。

**指标与未决项。** 先报告全部 40 条查询中标准对的共同召回覆盖；在可评单查询上报告相对次序，在两条查询都共同覆盖的配对上报告条件双查询正确率。所有方法共用由召回确定的分母，同分、缺失、失败和空池单列，不补抽；无可评组则不可估计。模型分数采用严格大于，最终排序若另行破平局则单独报告。保存现有在线策略的实际 mode／最终次序，另用同一个 Booster 在相同完整池取得原始分数；超时、延迟预算及短查询回退与模型排序分开。离线重放核对完整模型分数和确定性次序；时延引起的在线模式变化另列，不要求墙钟耗时完全一致。官方双文档成绩与共享候选条件成绩不能互换，也不能据成对标签计算全列表 nDCG 或宣称 Top-1／自然答案质量改善。

正式监督与测试边界尚须决定：官方来源前缀跨划分互斥，但四个原始正文跨入 Test；Train、Test 各有一个同查询要求反向排序的结构冲突。保留原始文件，先按来源前缀及相同正文关联监督家族，再在看方法结果前确定隔离与冲突报告规则。可以从训练／调参监督排除与 Test 连接的家族，保留官方 Test 原样并披露改变；若已观察过同源开发反馈，不能靠事后删文件恢复独立性。任何规范化或有效标签子集成绩都须单列其规则和分母，不能冒充未改动的官方成绩。不同配套查询和同源改写不当作独立样本。少量事件限定与措辞疑点还需不看模型输出的独立阅读复核；本轮 AI 阅读不等于人工金标验收。

**本阶段如何解释结果。** 通道正常、候选共同在场、有可靠适用性依据且基线错误可重放，才形成一个范围明确的存在性证据。只有数据或共同召回尚未证明错排；没有复现也不能证明总体不存在。可评对很少时，先区分通道故障与检索缺失，不补标准对制造覆盖。

**后续方法研究的继续或停止条件。**若必须引入新可靠语义模型才能产生差异信号，重新评估研究范围；若充分 B1 已处理绝大多数情况，或 D 没有额外收益，收缩／停止候选比较主张。标签疑点若足以影响优劣且预算内无法解决，不作效果确认。不能因几条样本或对照分数低就宣布方法可行性已经成立。

## 4. 评测判断与排序机制分开

两者使用的信息和职责不同：

| 层次 | 要回答的问题 | 信息边界 |
| --- | --- | --- |
| 适用性判断 | 该候选实际上是否对应查询要求、能提供何种答案证据？ | 必要时可在评价侧依据可靠来源核实；记录判断依据和未决情况 |
| 运行信息判断 | 仅凭排序阶段已有输入，是否提供了区分所需的依据？ | 不把外部核实结果算成排序器已经知道的信息 |
| 排序决策 | 如何利用已有输入排列固定候选？ | 不读取相关性标签、错误类型、人工解释、信息充分性标签或额外来源 |

标注材料不展示方法身份、预测分数和排序结果；显示顺序不能默认沿用基线排名。适用性与信息充分性可在同一次标注中记录，不拆成多层资格审核。不需要穷举业务规则，必要复核保留分歧，允许未决。

**“未判断”不是“不相关”，“信息不足”也不是“不相关”。** 即使外部来源确认某候选适用，排序输入仍可能不够判断。若实际适用性标签可靠，该案例可以进入相应评价，同时单列信息缺失情况；若真值未知，就不能假装它有确定的正负标签。

相关性采用二值还是分级、跨 chunk 才能回答时如何标注，以及区分“有帮助的证据”与“可独立回答”的方式，仍须在试标与正式设计中统一。标签说明可以描述年份、对象等具体理由，但这些说明不能变成排序运行时的逐场景判断规则。

### 4.1 先看标签覆盖和工时，再决定判断范围

**完整候选池是排序输入约束，不是全池人工标注要求。** 未标注候选仍留在每个方法的相同输入中；缺少评价标签与排序输入缺少判断依据分别记录。撤回此前讨论中的“默认 100 条查询＋全池标注”，也不把“小规模随机样本必须逐池全标”设为新的默认任务。

按以下顺序推进：

1. 候选可用后，自动统计完整候选池和基线 Top-k 的已有标签覆盖，以及查询之间的覆盖差异。覆盖包含显式非相关标签，不能只计算正例；没有出现在 qrels 中的候选仍是未判断。
2. 先与负责人明确可投入的人工工时，再安排小规模随机试标。查询按预先确定的方式抽取，不按基线错误、差异明显或方法成功挑选。
3. 试标记录实际查看的候选范围、耗时、分歧与未决情况，以及观察到的现象。无需默认检查完整候选池；如需全池检查的小样本，另按研究需要和预算决定。
4. 根据实际成本与拟支持的结论，共同决定正式查询数、判断深度和补标方式。已确认的 20 条仅是覆盖与工时探索规模；正式数量、预算、主要指标、k 或相似度阈值仍待确定。

基线 Top-k 的覆盖统计用于了解标注缺口，不能替代后续多方法的公平比较。正式输出判断如何合并、判断深度能支持何种结论，见 §6.1。

### 4.2 标签接入边界与修订范围

本节规定读取、关联与覆盖计算的边界；对应入口为 [datasets.py](../../src/linkrag_eval/golden/opensource/datasets.py) 和 [coverage.py](../../src/linkrag_eval/golden/opensource/coverage.py)。候选准备见 [§3.3](#33-探索输入准备与交接)，运行结果和测试状态见 [CURRENT_STATUS](../CURRENT_STATUS.md)。

**最小接口。** 来源上下文记录原始 T2 下载版本及所用查询／qrels 文件，可在文件级保存；其下以原始字符串 `source_query_id`、`source_passage_id` 关联判断。查询清单来自所用 queries 文件，包含无判断及无正例查询；已有运行 `sample_id` 若不同于来源 qid，保留显式对应，不从查询正文或 ID 前缀猜回来源。运行候选用 `dataset_id`、`chunk_id` 关联 `source_passage_id`；`doc_id` 参与现有同文档特征，保留为排序输入并可辅助映射，`ordinal` 可仅作入库映射辅助，不由来源 passage 推断额外父文档身份。三路完整候选、正文、分数与顺序独立于标签，排序输入不带相关性、人工解释、错误类型或信息充分性标签。

| 情况 | 最小表达与消费边界 |
| --- | --- |
| 已有四级判断／未判断 | 单独保留来源 qid—pid 的原始 `grade ∈ {0,1,2,3}`；显式 0 计入已有判断覆盖，缺行表示未判断，不补 0，也不先设二值阈值。两列 retrieval qrels 没有等级，不能替代四级文件或补出零级。 |
| ID 未关联或关联歧义 | 保留来源判断、候选及关联失败原因；不冒充缺标或负例。所用 corpus 外的 PID 说明范围外，不要求所有原始 qrels 都映射到本次运行。现有专用入库路径是一 passage 一 chunk；实际关联须核对，其他路径一对多时不能直接把整段等级复制给每个 chunk。 |
| 重复、冲突／未决 | 同键同级只计一次；同键异级保留原始值及来源位置，另列冲突，不能后写覆盖或自动取最大值。实际补充判断的分歧／未决记录关联 ID、依据和待处理结论，未解决时不作为确定等级消费；人工或模型追加判断不覆盖或冒充官方原始标签。 |
| 正文缺失／现有正文依据不足 | 正文缺失属于输入异常，保留查询、候选与缺失记录；正文存在但不足以区分属于评价侧补充判断，按 §4 分别记录适用性及运行依据。两者均不改写原始 grade，不据此删候选或判负。 |

正常已判断／未判断由 qrels 的值或缺行表达，仅实际异常与补充判断留必要记录；不为每对候选另建重复布尔状态或空注册表。覆盖统计以固定完整候选为分母，已成功关联且无未决冲突的 0–3 级判断计入覆盖；映射异常、未判断和冲突分别列数，空池查询保留并说明分母为空，不能报告为完整覆盖。

新研究只改实际经过的入口与消费者：

- **原始读取。** `read_t2_queries` 保留完整查询清单和原文；`read_t2_qrels` 保留 0–3 级、同键冲突及来源行号；`iter_t2_collection` 可流式读取原始 passage。三个读取器识别官方表头，非法等级与格式明确报错。原有 `load_t2ranking` 同步按查询清单枚举，未知查询 ID 或冲突明确报错。覆盖入口用完整查询文件核对 qrels，再对照本次抽样清单，不能拿抽样子集去判定 qrels 中其他查询是错误。
- **标签与映射。** 可复用 [ingest.py](../../src/linkrag_eval/golden/opensource/ingest.py) 的 passage 映射和 [indexer.py](../../src/linkrag_eval/store/indexer.py) 写入的 `source_passage_id`。覆盖入口使用独立查询清单与原始 qrels；[convert.py](../../src/linkrag_eval/golden/opensource/convert.py) 当前只映射 `positive_pids`、丢 0 并跳过无映射正例查询，不能直接使用，其硬编码 `c-mteb-main` 来源版本也不适用于原始 T2。当前 [Golden schema](../../src/linkrag_eval/golden/schema.py) 及 [loader](../../src/linkrag_eval/golden/loader.py) 的非空正例引用约束不能成为新入口前置要求。
- **计算与正式消费端。** [experiment.py](../../src/linkrag_eval/retrieval/learning_to_rank/experiment.py) 的 `build_online_features` 不依赖标签，可复用；`_candidate_features` 将期望集合外全标 0、`_fold` 用 `expected_doc_ids` 计算折号及外部评价排除正例 chunk 重合的子集，均不是新研究默认。正式重训／评价若复用这些路径，只修订实际采用的监督连接、查询划分和汇总逻辑；[现有 NDCG](../../src/linkrag_eval/metrics/retrieval.py) 也会将缺失等级按 0 算增益，不能直接消费不完整 qrels。不为覆盖统计先改整套 runner、数据库或历史兼容层。

**验收要求。** 用小型明确输入验证：表头不入数据且非法等级明确报错；0、1、2、3 在读取和关联后原样保留，删去一条 qrel 后只变为未知；无判断、只有 0 或正例全未映射的查询均不消失；重复冲突、映射失败与正文问题有各自去向；增删标签不改变各方法的完整候选、正文、逐路分数、顺序及特征；不同组查询可共享 passage／chunk，查询重复及监督用途按 §3.2 处理，不以文档重合作删除条件。验收由新读取、覆盖、候选和编排测试承担；既有正例转换测试只保护仍在使用的旧消费者。

**覆盖输出。** `exploration coverage` 离线读取固定输入，分别报告完整抽样查询中已观测候选的覆盖、可运行基线的 Top-k 覆盖、输入状态和不能运行基线的查询；分母与范围明确列出。显式 0 计作已判断，未判断与映射／标签冲突互斥计数，空分母的比例为 `null`。基线可运行但标签映射不全时，其 Top-k 仍保留映射缺口。该报告不计算自然错误率或完整池的排序质量。指定 `--model-dir` 与 `--k` 时调用冻结 LambdaMART 的既有在线策略，并逐题记录实际模型／回退模式；不把回退结果叫作纯模型排序。

当前覆盖机制只需完整查询清单、原始等级、可核对的映射与异常计数；人工工时、随机试标和规模仍按 §4.1 推进。训练如何处理缺标签、最终等级或增益映射、指标及 k 留待正式设计，旧模型监督曝光与共同重训遵循 §3.2。Top-k 对称补标及未知 IDCG 的限制沿用 §6.1，不在接入阶段另定评价规则。

## 5. 用一个例子贯穿整个过程

查询：**“2026 年华东地区的利润是多少？”**

| 候选 | 排序阶段已有正文 |
| --- | --- |
| A | 2025 年华东利润 80 万元；2026 年华西利润 100 万元。 |
| B | 2025 年华西利润 80 万元；2026 年华东利润 100 万元。 |
| C | 华东地区利润 100 万元。 |

**数据选择。** 在真实研究中，这条查询必须通过预先确定的抽样方式进入评测，不能因为研究者发现 A／B 恰好适合新方法才选入。实际候选池的其余普通段落同样保留。这里的手写例子只是解释设计。

**标签建立。** B 在正文中提供“2026—华东—100 万元”的对应关系；A 没有提供查询要求的那组关系，不能把其中 2026 年华西的数值当作答案。C 没有年份，单凭现有输入不足以确定。若评价侧的可靠来源确认 C 属于 2026 年，可记录它的实际适用性，同时仍记录“运行依据不足”；未核实前保留未决，不能随意判负。

**排序决策。** 基线使用现有 38 维表示。后续单候选增强可能通过段内局部匹配就把 B 排到前面；候选比较只是尝试利用 A／B 的差异位置，帮助找到要检查的片段。它必须比充分的单候选对照多解决问题，不能把这个例子预先记为自己的优势。此处也没有声称当前 38 维特征在这个新例子上必然相同或必然排错。

**效果验证。** 假设基线把 A 排第一，增强方法把 B 排第一，比较 Top-1 就应同时判断 A、B，不能只判断基线输出；它们来自各方法输出的合并，而查询本身仍由预先抽样进入。记录改对和改坏，再在实际判断覆盖支持的范围内汇总全部抽样查询。若 C 仍未决，不将它当成负例，也不从只检查 A、B 推出完整池的质量。假如所有输入都删去年份，即使人工能从父文档查明年份，也不能把该信息交给排序器，或要求它稳定选对。

## 6. 对照逻辑与效果判断

原四／五版本设计不再沿用。若候选差异方向继续，比较逻辑暂定如下；这些是需要排除的替代解释，不是要求立即实现四套系统。

| 比较项 | 内容 | 要回答的问题 |
| --- | --- | --- |
| 现状参考 | 当前冻结的 v3 模型与既有回退策略 | 当前工程实际会怎样排序？ |
| B0 | 在相同新训练划分与预算下训练的 38 维 LambdaMART | 改善是否只是重新训练或换了数据？ |
| B1 | B0 加入充分的单候选局部匹配 | 局部信息本身能解决多少问题？ |
| D | 在可比局部计算基础上使用候选差异选择位置 | 候选比较相对于 B1 是否有额外作用？ |
| 辅助位置对照 | 查询命中情况、窗口规模和预算尽量匹配的其他位置选择 | D 的收益是否只来自多检查了查询词或更多正文？ |

不能将冻结的旧模型与新训练的增强方法直接比较，然后把全部差异归因于新表示。B1 仍保留基线已有候选统计，因此不是“完全不看其他候选”的系统；准确说法是“新增部分只使用单候选局部信息”。

B1 必须覆盖相同正文，并允许保留多个局部证据，不能故意只取一个容易受目录或公共模板干扰的窗口。D 采用替换还是增补局部信息尚未决定；用于归因位置选择的 D 与辅助对照需共享全部非位置选择信息，包括启用标记、近邻相似度等，只改变位置选择方式。位置、命中与预算无法充分匹配时，应说明剩余混杂，不直接宣称识别了差异定位的独立贡献。

各版本共享训练数据、划分、调参预算和候选集合；消融在训练时就去掉相应信息，避免仅在测试时破坏输入。当前没有新增文本模型，因此不承担“先训练一个可靠细节比较器”的课题。未来若有新证据重新引入，用于归因融合设计的文本增强对照需共享同一文本输出和调用预算，包括仅增加文本评分的接入方式；同时保留无文本模型的基线，分别测量文本信息与融合设计的增量。

### 6.1 判断覆盖决定指标与结论范围

比较实际 Top-k 质量时，在参与方法及参数确定后，合并各方法的 Top-k 输出，复用已有标签，并以同一规则对称补标。标注时隐藏方法身份、名次和分数。查询选择不依赖方法成功，合并输出只是公平确定需要判断哪些候选，不等于挑选有利样本。只判断基线 Top-k 不足以比较其他方法；新增方法输出了未判断候选，就须补足相应判断，不能把未判断当负例。

指标先明确用途和可计算条件，暂不冻结主要指标：

- 输出排序质量：各方法 Top-k 全部获得可靠标签后，可计算各自输出的 DCG@k；但 nDCG@k 还需要理想排序的增益 IDCG，仅判断输出未必知道完整候选池的理想值。若基于共同已判断池归一化，须明确该池及覆盖限制，不能称为精确的全候选池 nDCG。MRR@k 等指标也须具备其涉及位置的判断，明确相关性口径、k 和统计分母。
- 目标现象：观察“池内已有可用证据，却被违反查询关键要求的候选压在后面”。找到明确实例可以证明该查询存在这种现象；浅层检查没有发现，不能证明不存在，也不能直接估计全池关键差异发生率。全池结论需要足够检查覆盖，或适当的抽样和估计设计。
- 收益与损害：在实际判断覆盖范围内同时报告改对、改错、不变及不触发的数量；未知结果单列，不能混入不变或正确。额外收集的困难案例只作条件性的机制分析，与随机样本结果分别报告。
- 不确定性与成本：以查询为基本单位；存在相关的查询组时按组处理，不把同一查询的多个候选对当成独立样本。报告差异的不确定性、额外排序时间与比较规模。

未标注候选不能按零相关性参与完整指标；标签不足时报告覆盖情况及其限制。已判断池没有正例不等于全池没有正例；理想增益确为零的查询如何进入指标须另作说明。若数据不足以估计总体表现，就不输出看似完整的自然错排率。确认性比较的主要指标、可接受总体损失和分析规则应在查看验证效果之前确定，而不是不断增加前置流程。

### 6.2 现象存在、比较规模与方法有效分别判断

少量自然错误只能支持“现象存在，值得继续探索”，不能证明正式样本量充分，更不能证明方法有效。正式规模结合人工工时、关心的改善幅度、查询级差异的方差、判断分歧，以及需要的精度或比较能力决定。查询数和判断深度应一起权衡，可参考 [Topic set size design](https://link.springer.com/article/10.1007/s10791-015-9273-z)；不从文献中照搬固定数量。

方法尚未形成时，确切效果和方差无法事先知道，不要求先做精确功效计算才允许探索。探索所得用于后续设计，探索样本按 §3.2 归入开发材料。证据不足时可以增加样本、收窄结论或停止机制研究；不能一边查看正式效果，一边追加样本直到方法显著胜出。这些是解释证据的原则，不另建“研究可行性认证”流程。

## 7. 后续实现范围与停止条件

当前实现仅限于按 §4.1 获取并固定所用候选、核对已有标签覆盖的必要接入代码，再结合人工工时安排试标；所需离线入口复用现有候选与特征计算，独立接入评价标签，保留缺失与未判断状态。这一步不依赖最终窗口或融合算法，也不应扩展成插件系统、注册表、相似度校准项目或通用封存流程。

候选入口的可复用能力与缺口集中见 [§3.3](#33-探索输入准备与交接)，读取、标签及查询划分的有限修订范围见 [§4.2](#42-标签接入边界与修订范围)。此外，[当前排序器](../../src/linkrag_eval/retrieval/learning_to_rank/online.py)包含短查询、超时及延迟回退；覆盖入口记录其实际模式，正式比较仍须区分纯模型与运行策略，不能把回退造成的变化算成表示改进。

结合数据探索再决定是否需要局部匹配原型。适用的已有标签可以复用，必要错误说明可与相关性在同次判断中记录；但探索中用于修改方法的样本不再用于独立确认，不先建立多轮准入研究。

| 后续观察 | 相应判断 |
| --- | --- |
| D 稳定超过充分的 B1，辅助对照也支持定位增量 | 保留该机制，继续核对适用边界、泛化、代价与文献差异；不直接认定创新成立 |
| B1 有效，D 无额外收益 | 放弃候选比较主张；只能讨论局部表示增强，论文贡献另行评估 |
| 仅人工例子改善，自然数据无支持 | 只能说明机制检查通过，不能声称真实排序改善 |
| 判断覆盖或比较精度不足 | 不能因“未发现”认定现象稀少或方法无效；按成本增加证据、收窄结论或停止探索 |
| 有足够覆盖与比较精度后，自然可修复错误很少，或两种增强均无效 | 停止这条方法主线；不默认负结果足以独立发表 |
| 子集改善而总体受损 | 如实报告权衡，不能事后筛样本包装为稳健改进 |
