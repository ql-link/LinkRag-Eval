## 4. 对独立审查的接受与保留

### 接受的主要纠偏

1. 表示盲点不能直接推出特殊融合结构必要；逐候选表示也可能解决近似候选错排。
2. 重新引入文本模型必须解释相对历史尝试有什么具体变化；不能只诉诸“模型更懂语言”。
3. Qwen官方现成接口是 Query—单候选评分，不是已经验证的双候选差异比较器。[官方说明](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)
4. 相似度定义与标注应服务实际评测，不能扩张为必须先解决的独立研究。

### 尚需限定的建议

- **词序／邻近方案不能立即定案。** 字符n-gram已保留短片段内部顺序；新候选应说明新增的是出现位置、距离、次数还是较长对应关系。局部邻近只是可能有用的代理，不等于语义绑定。经典词项依赖工作可作为依据，不能作为新颖性证明。[词项依赖原始工作](https://figshare.com/articles/conference_contribution/A_Markov_random_field_model_for_term_dependencies/27377922)
- **B1“无序”必须明确。** 全文词频控制与无序局部窗口控制测量的增量不同；后者已经具有邻近信息。B1/M要共享词项、分词、正文范围及训练预算。
- **简单接入失败不是复杂结构不可能的定理。** 当前暂停是控制投入的合理选择；若将来有具体新证据，仍可重议，不能将一次负收益外推为全部结构无效。
- **评测真值与运行信息不能混同。** 可以用可靠来源核验真实适用性，再单独记录运行输入是否有区分依据；若只让标注者看chunk，研究目标必须明确为“仅凭该输入能否回答”。未决不是负例，也不是静默排除理由。
- **模型证据只限其任务。** 已核实Jina在NevIR复现中的65.2%配对准确率及约278M参数报告；不能外推为单位、版本绑定或本项目可靠性。[复现论文](https://arxiv.org/html/2502.13506v3)

## 附录 A：负责人交给独立审查的原始问题

以下按会话转录问题上下文，空白格式做了规范化，包含当时的事实、担忧与候选方案；其中提到的方案不因保存而被批准执行。

<details>
<summary>展开原始问题</summary>

请独立审查下面这项研究的方向，尤其检查我们是否在讨论过程中偏离了原始问题。**先分析，不实现；不必维护已有方案，请直接指出应保留、修改或放弃的部分。**

**研究目标与项目背景**

项目是一个 RAG 评测系统，采用 Dense、Learned Sparse、BM25 三路召回。**研究严格限定在三路召回之后，固定候选集合，只使用排序阶段已有的正文、分数、排名等信息。** 不修改召回、切块，不补检索或读取父文档。

目前使用 **LightGBM 实现的 LambdaMART** 进行融合／排序。它接收 38 个数值特征，包括三路分数、排名、缺失标记、数字及词语覆盖、部分候选池统计和同文档相似度。因此，不能简单声称它完全没有使用候选上下文。

**原始想法**

非常相似的 chunk 可能只在关键细节上不同，排序系统容易忽略区别，选中不适合回答问题的候选。差异不限于时间，还可能涉及对象、数值、单位、版本、否定、适用条件及其对应关系。

例如，查询问某年的利润，召回不同年份、格式类似的财报片段。各片段本身可能都真实，错误在于与查询不匹配。如果年份在全部排序输入中都缺失，就不能要求方法凭空判断。我们研究的是利用已有信息，不研究补全缺失信息。

此前做过一个**手工特征检查**：交换两段文字中“版本—年份—权限”的对应关系，同时人为固定三路分数和排名，LambdaMART 的全部 38 个输入特征不变。这说明存在一个具体的表示盲点，但不证明真实失败率，也不证明新增文本模型或融合结构有效。

**讨论中提出过的方案**

最初设想：比较近似候选的关键差异，根据这些关系调整三路相对分数的作用，再做有限的局部排序修正。

为了避免逐场景手写规则，又提出使用一个冻结的通用文本模型，读取“问题＋两个候选”，输出文本偏好和中间表示。各增强版本共用同一份输出，比较：

1. 现有 LambdaMART；
2. 增加文本判断；
3. 文本分支与三路分支分别算分，最后相加；
4. 相同输入下的普通非线性融合；
5. 专门让文本对表示调节三路证据的融合结构。

用意是区分“更强文本理解”“普通灵活组合”和“专门融合结构”的收益。但这个文本比较器是否有合适的现成实现、输出是否保留关键差异，都尚未确定。

已有 [monoBERT／duoBERT](https://arxiv.org/abs/1910.14424)、[HybRank](https://aclanthology.org/2023.findings-acl.880/) 等研究支持多阶段重排或候选协作，但它们不能直接证明我们的具体方案有效。

**一个刚补充、非常重要的项目事实**

## 1. 原始问题清楚，但“问题存在”与“方法成立”之间跳了几步

### 应保留的问题

可以将原始问题准确表述为：

> **在固定召回候选集合中，当候选整体相似、但决定查询相关性的局部内容或对应关系不同，现有排序表示能否保留并利用这些区别？**

这个问题有研究依据：NevIR 直接研究仅因否定而产生相关性差异的候选；数量感知检索研究则表明，数字、单位和比较条件需要区别于普通词面匹配来处理。但这些工作也意味着，**“排序模型可能忽略细节”本身不是新的发现**。你们的研究价值要来自实际失败规律、清楚的表示边界，或者可复现的改进证据。([ACL Anthology][1])

### 手工检查证明了什么

你们的检查支持一个严格但有限的结论：

**当关系交换前后的全部排序特征不变时，任何只读取这些特征的排序函数，都无法针对该交换改变判断。**

这首先是**表示不可区分**，不是 LambdaMART “不够非线性”。如果正确偏好应当随交换翻转，两个状态却得到相同表示，那么单纯换融合函数无法同时正确处理它们。

* 这是人为固定三路分数、排名后的检查；真实召回分数可能已间接编码部分区别。

* 它没有证明这种盲点造成了多少实际错排，更没有证明新增表示可以解决。

**因此，不能从“存在表示盲点”直接跳到“需要特殊融合结构”。**

## 2. Qwen 曾经负收益，应该提高重新引入文本模型的举证门槛

**我的建议是：暂时撤掉“必须有文本模型”这个前提，但不宣布所有文本模型无效。**

你提供的开发经历应当作为真实项目背景保留。论文中可以说明负责人回顾曾有负收益尝试；没有完整记录时，不能把它写成可复现的定量实验，也不能用新实验冒充历史结果。

重新尝试可以有以下具体理由，而不是“语言模型应该更懂语义”：

**第一，发现了可核实的旧实验问题。**例如关键内容确实被截断、输入格式确实不符合模型要求。必须有具体证据，不能默认“负收益一定是接错了”。

**第二，候选模型有与目标困难直接相关的新证据。**不是数学榜单或通用重排榜单，而是相近输入形式下的否定、数量条件或关系辨别证据。

确实存在部分这样的证据：NevIR 的复现研究报告，约 278M 参数的 `jina-reranker-v2-base-multilingual` 获得了 65.2% 的该基准配对准确率。这比泛泛声称“小模型也懂细节”更有根据，**但只提供否定任务上的证据，不能外推到数字、版本—年份绑定或你们的数据**；其官方接口仍是问题与单候选相关性评分。([arXiv][4])

**第三，存在可泛化的互补收益。**一个单独排序表现较差的模型，仍可能纠正 LambdaMART 的一部分错误；但必须同时统计它破坏了多少原本正确的排序。不能使用真实标签事后选择“这题听谁的”，然后将这种理想选择当成可实现收益。

真正进入主方案的门槛应该是：

> **在独立验证数据上，将冻结文本输出作为普通新增特征交给 LambdaMART，就能产生稳定净收益。**

不必先证明文本模型普遍可靠，也不必先设计门控。**如果最简单的接入没有信号，不能靠“也许特殊结构能救活它”继续扩张课题。**

还有一个需要直接纠正的前提：Qwen3-Reranker 官方用法是对“问题＋单候选”给出相关性判断，**不是现成的“问题＋两个候选→偏好＋差异表示”比较器**。读取隐藏状态，也不等于已经获得可靠的关键差异表示。([huggingface.co][5])

你们原来的五组对照有合理的归因意图，但启动得太早。以后真的研究融合时，普通融合基线必须获得专门结构使用的**全部相同文本输出**；只给基线一个偏好分数、却给专门结构完整中间表示，不能隔离结构收益。

## 3. 不训练新文本模型，还能走哪些有根据的方向？

先区分两种情况：

**信息已在 38 维特征中，但没有学好；或者信息根本没有被这些特征保留下来。**两者需要不同处理，不能都叫“融合不够好”。

### 方向 A：补充通用的局部词序与邻近信息

这是我认为**最贴近现有证据、又不需要第二个模型课题**的方法候选。

不是编写“年份规则”“权限规则”，而是在原 chunk 内，统一计算查询词的局部共同出现、相对顺序、短语覆盖等信息，再交给原来的 LambdaMART。**不改变 chunk，不改变候选集合，也不建立业务字段抽取器。**

其依据是：同一批词出现过，不等于它们以相同方式联系起来。经典词项依赖检索模型已经使用单词、有序短语和无序短语等证据，因此这是一条有基础的低成本方向，而不是必须依赖语言模型才能尝试的事情。([Figshare][6])

但必须明确边界：

**局部词序、邻近关系不是完整的语义绑定。**它们可能改善部分局部对应关系，却不能保证识别跨句指代、复杂否定作用域、单位换算或隐含适用条件。甚至你们现有的关系交换例子，也未必都能被这些简单表示区分。

所以，这只是值得测试的表示补充，不能先命名为“通用细节理解方法”。

### 方向 B：改善现有特征的训练覆盖，而不是增加表示

如果真实错误中，已有分数、排名或覆盖特征确实具有区分信息，那么训练集内的难例覆盖、查询级重加权，以及与实际 Top-k 目标一致的训练设置，可能比新增网络更值得检查。LightGBM 本身也提供控制排序训练关注范围的设置。([LightGBM Documentation][2])

但这个方向**无法消除严格的表示不可区分**。多训练一些关系交换样本，如果特征仍完全不变，只会要求模型用同一输入满足冲突目标。

因此，我会把它作为低成本对照或备选，不与方向 A 一起包装成多模块方案。

### 暂不建议继续的方向

仅对已有分数、排名做更复杂的三路门控，尚没有直接理由能修复你们发现的关系盲点；增加邻域一致性、相似候选投票，也不能自动辨别哪个条件满足查询。

**相似候选的多数意见，不等于正确条件。**在没有新区分信息时，这些结构可能改变排序，却未必是在解决原始问题。

## 4. 哪些验证不可省？怎样避免评测偏向方法？

### 不可省的是四件事

**一是自然错误的规模与可修复空间。**

从真实查询中随机或按预先固定规则抽样，保留原始候选、正文、分数和排名。首先回答：

> LambdaMART 选错时，候选池里是否已有可用答案？错排是否真的涉及查询关键条件？

不要只收集印象深刻的失败案例。对于只修复这一类错误的方法，其 Top-1 准确率最大收益，不会超过这类可修复错误在全部查询中的占比。

**二是独立于方法的样本定义与标注。**

相似度可以用一种固定的简单词面指标分层，不必先完成“真正语义相似度”的校准研究。但不能根据新增模型的表示、置信度或成功情况决定哪些样本进入评测。

标注者只看允许使用的问题和候选文本，不看方法输出、排名和模型身份。应允许“同样可用”“都不满足”“信息不足”，不能强迫每一对候选都有优胜者。

**“信息是否充分”应当是同一次标注中的字段，而不是提前筛出适合方法的数据资格。**不足或无法定标的样本单独报告数量与覆盖率，所有方法使用相同处理规则；不要偷偷删除，也不要直接当负例。

**三是既看纠正，也看破坏。**

同时报告总体排序表现、预先定义的关键差异子集表现，以及改对／改错数量。子集必须包含基线原本正确的样本，不能只测试“能救回多少失败”。

预算不足而采用分层抽样时，恢复总体估计需要考虑抽样权重；未标注候选不能直接视为不相关。

**四是公平训练和防泄漏。**

固定候选集合；基线和增强方法使用相同训练数据、调参预算及测试划分。共享来源文档、模板或问题改写的样本尽量分组划分。置信区间按查询或更高层共享来源分组计算，不把同一查询下大量候选对当成独立样本。

### 可以取消或合并的前置流程

| 原来的负担                 | 建议                              |
| --------------------- | ------------------------------- |
| 大量相似度校准、多个“高相似”定义反复筛选 | 固定一种定义作为分层工具，少量敏感性分析即可。         |
| 穷举时间、版本、权限、单位等全部场景    | 取消完整分类体系；必要错误类型作为描述性标签。         |
| 单独做数据资格、信息充分性和关系核验    | 并入一次相关性标注。                      |
| 反复标注直到全部达成一致          | 保留必要独立复核与分歧记录，允许不确定，不强行仲裁出确定答案。 |
| 先证明文本比较器通用可靠，再训练融合器   | 当前路线不引入比较器，整项取消。                |
| 大规模关系交换压力测试           | 保留少量表示单测，不用它估计自然失败率。            |
| 全链路生成评测               | 排序结论不依赖它；只有声称改善最终答案时才必须增加。      |

尤其不要把**修改正文却保留旧召回分数的人工样本**混进自然测试集。它适合检查表示是否响应变化，不代表真实三路召回会产生同样输入。

## 5. 建议的最小路线：一个假设，三个版本，不预设新结构

**现阶段证据不足以确定正式方法。**下面是一条值得验证的小实验路线，不是已经成立的算法方案。

### 唯一核心假设

> **在自然形成的固定候选集合上，查询相关的局部词序与邻近信息，能为现有 38 维特征提供可泛化的关键条件区分增益。**

注意，这不是“解决所有细节理解”，也不是“证明候选协作优于单候选排序”。

### 必要对照

| 版本 | 内容                               | 用途                 |
| -- | -------------------------------- | ------------------ |
| B0 | 现有 38 维 LambdaMART，在相同条件下合理调优    | 排除只是基线没有训练好。       |
| B1 | B0＋新增词面信息的无序版本                   | 排除收益只是来自多看了一些词或计数。 |
| M  | 同样的词面信息＋局部词序／邻近信息，仍使用 LambdaMART | 检验关系性表示是否提供额外价值。   |

若新增无序统计已完全包含在现有 38 维中，B1 可以与 B0 合并，不必为了凑对照再造一个模型。消融应从训练时就去掉相应信息，而不是只在测试时打乱，制造分布变化。

**这里没有文本比较器、双分支、特殊门控，也不需要局部交换图。**让原来的 LambdaMART 使用新增证据即可。

主实验同时完成自然错误测量和方法比较，不再建立多层独立前置项目。预先指定关键条件错排率作为目标指标，以总体 nDCG@k 等实际排序指标作为损害约束；具体改善幅度和可接受损失应在看测试结果之前确定。

### 可以主张的贡献

成功时，贡献应是：

**发现并量化真实多路召回候选中的一类关键条件错排，证明一种最小的表示补充能够改善它，并说明何时无效。**

不能将经典词序／邻近特征本身包装成新算法。**如果结果只是几个普通特征带来小幅涨分，未必足以独立成篇**；论文价值仍取决于自然现象、对照和边界分析是否提供了超出既有工作的认识。

### 失败时如何收缩

| 结果             | 应采取的结论                       |
| -------------- | ---------------------------- |
| 自然可修复错误很少      | 停止将它作为主要方法课题，保留工程单测。         |
| M 不优于 B1       | 不支持词序／邻近信息带来额外增益，不能归功于关系辨别。  |
| 只在人工交换样本上改善    | 只能声称通过了表示测试，不能声称改善真实排序。      |
| 子集改善、总体明显受损    | 报告权衡，不能称为稳健改进；不能事后筛子集掩盖损失。   |
| 自然错误明显，但上述增强无效 | 收缩为错误与表示边界的实证研究；不自动升级到更复杂模型。 |

**最终建议是：保留原始问题，撤掉“必须用文本模型”和“必须有专门融合结构”的承诺。先让最小表示补充接受自然数据检验；没有信号，就停止这条方法线，而不是继续为它增加前提。**

### 已执行：手工构造的特征表示检查

Query：`标准版在2026年是否允许离线导出？`

| 文本 | 正文 |
| --- | --- |
| A | 标准版：2026年适用，允许离线导出。专业版：2025年适用，不允许离线导出。 |
| B | 标准版：2025年适用，不允许离线导出。专业版：2026年适用，允许离线导出。 |

## 附录 E：2026-09-07 当前阶段目的对齐原文

以下完整保存主任务上一轮回应，作为阶段纠偏的讨论记录；不是新增运行授权。现行定义与后续修订统一见[研究计划 §1.1](post-recall-research-plan.md#11-当前阶段先验证问题存在且可复现)。

**对，当前找数据集的目的，应该是获得独立、可信、可复现的“问题存在证据”。** 我上一轮提前转向了“候选比较能增加什么”，把问题验证和方法设计混在一起了。

但这里需要明确：我们究竟要证明哪个问题存在？

不是仅仅证明“两个 chunk 很相似但意思不同”，而是：

> **在三路召回后的固定候选中，正文已经包含区分所需的信息，但现有排序器仍把不符合查询要求的近似候选排在适用候选前面。**

这条证据需要连起来：

1. **候选确实在场。** 适用段落与近似但不适用的段落，都在实际召回的候选集合里。
2. **错排有可靠判断依据。** 能说明关键区别怎样影响查询适用性，而不是仅凭我们觉得两个段落应该换个顺序。
3. **错误能够重现。** 保留查询、候选正文、三路分数／排名和基线版本，能够再次得到这个错误。

这时，数据集的作用就是提供查询、正文和判断依据，帮助我们检验这条证据链。**这个阶段并不要求先提出解决办法，更不要求证明候选比较有效。**

我们目前已有的证据还不完整：

- 手工交换对应关系、38 维特征不变，证明了一个具体的**表示盲点**，但没有证明实际候选中发生了错排。
- NevIR 提供了独立公开的近似段落与配套查询，**可以承载受控的问题复现**；但我们尚未获得本项目三路召回后、现有排序器上的实际结果。

另外，**“存在且可复现”与“经常发生”要分开**。少量可靠反例可以证明系统存在这种失败；发生频率、影响大小和自然场景推广，需要更多证据，不能顺带宣称。

所以，我们现在应当对齐为：**先确认这个具体问题在我们的研究边界内是否存在、能否稳定复现；方法如何解决、有没有创新，属于后面的讨论。**

## 附录 F：2026-09-07 机制讨论与最小验证的范围确认

本节整理问题复现之后的对话、负责人转交的 ChatGPT Pro 回复及本任务审视，属于讨论依据。F.1–F.4 记录设计前讨论，当时未新增训练、编码或方法效果实验；后续执行完成的解释见 F.5。现行设计和 session 分工只在研究计划 §2.1–2.3 维护。

### F.1 已对齐的判断

- **阶段变化。** NevIR 已提供受控错排存在性及可重放证据。下一轮要检验针对性训练是否改善未见样本，不再重复把“问题存在”当作待完成目标。
- **基线地位。** 负责人确认项目经历过 RRF、文本模型等负收益尝试，LambdaMART 是有正收益的第三轮工程进展。自行训练参数不削弱其工程基线地位；冻结模型与在共同新监督下重训的基线承担不同用途，不能把二者混同。不同历史数据／模型版本的绝对成绩不横比。
- **错误来源与修复位置。** 词项、编号或数字匹配能力不保证条件和对象的对应关系正确。Hosier 案例中正确段落已在池内，Dense 和 BM25 原本也偏向另一段，Sparse 成功返回空；因此是已有评分偏误未被重排纠正，不是漏召回，也不能说 LambdaMART 独自制造错误。[既有案例](../reports/nevir_controlled_retrieval_2026_09_07.md)
- **两种改进来源。** 同一 38 维经针对性训练可能更好地利用已有信号；新增局部／关系表示可能提供额外信号。前者失败不能直接证明后者必要，前者成功也不证明所有条件关系已经被表示。
- **候选比较和门控。** 充分单候选匹配是后续重要对照，但不把“先做成功一个全文语义模型”设为局部研究的逻辑前置。池依赖导致分数变化不自动等于有害污染。项目已有 [Top1／Top2 保护历史](../experiments/ltr-fusion-v1.md#54-hybrid-top1-保护优化)和短查询回退，不能把选择性重排一概当作未探索方向。
- **监督含义。** “证据适用性”必须具体说明比原有相关性监督增加了什么，不能只更名。问题问“是否获批”时，“未获批准”也可能完整回答；只给环比一般是未提供同比，不是与同比事实矛盾。支持、证据不足及不满足条件不能不看查询就排成统一标签等级。

### F.2 已有输入的扩展分析及限度

本轮对既有 20 组进行了更广的 AI 文本审视，并比较模型及逐路方向。这些观察不是独立盲审或新增人工金标，也没有改写已发布报告：

- 官方指定对上，固定加权与 LambdaMART 的偏好方向为 37/40 一致；18 条模型官方逆序中，17 条固定加权已经逆序。它支持关注“未纠正上游偏好”，不证明融合或表示的唯一因果。

- 英文样本的两个否定统计和两个同文档统计恒为零；前者与中文词表限制有关，后者来自匿名独立文档的实际接入，不使用官方配对伪造同文档关系。

- [Risk-Aware Selective Neural Refinement for Reliable Dense Retrieval，IEEE Access 2026](https://ieeexplore.ieee.org/document/11571775/)：官方记录及摘要支持预算门控和置信保护的存在。出版社全文本轮未取到，转载中精确头部锁定规则未完成一致核查，不将“必然锁定前两名”作为已核实细节。

这些来源是新线索，不是本项目方法收益或创新性证明。当前不把全文模型、蒸馏、风险门控或所有诊断项并列升级成必做任务。

### F.4 数据来源与范围纠偏

负责人认可 LLM 构造特定场景数据的价值。本任务明确：构造数据可以用于训练与受控验证，其可靠性取决于文本、标签和验证方式；不能估计自然发生率不等于不能用于研究。旧 2,000 条训练问题确有生成与质量判定记录，但在已知目录及重构备份索引尚未找到完整实体；现存模型、28 族合成 Dev 与旧训练包是不同资产。详情统一见[研究计划 §3.1](post-recall-research-plan.md#31-已找到的本地材料与使用建议)。

本任务曾建议新建约 150 个中文题族，负责人指出上一阶段用的是英文 NevIR。本任务撤回语言和数据来源切换：认可构造数据不代表授权替换本轮数据。中文方案及其数量不作为当前任务，后续可另议；本轮沿用 NevIR，对照冻结模型和同 38 维重训。

确认集暂提 50 组／100 查询，但尚未确定实际可用来源组、抽样或预算，不能将讨论数值写成执行事实。负责人随后要求先核对本对话改动、从 `origin/master` 新建分支并规划 session 分工。该要求只推进准备工作，未启动模型训练、候选采集或官方 Test 评测。

### F.5 最小验证后的解释边界

负责人随后要求协调任务接收三个 session 反馈并持续推进。有限设计采用剩余全部 187 个 Validation 配对确认，替代早先暂提的 50 对；数据、训练及一次独立确认现已完成，结果集中在[实证报告](../reports/nevir_same38_retraining_2026_09_07.md)，此处不复制指标表。

结果支持保留同特征训练的可纠正信号，但主要查询指标的收益方向尚未明确确认。双向全对增加的同时，双向全错也增加；次指标的正向结果不能代替主终点。它不证明模型已经掌握条件关系，不证明 38 维达到上限，也不授权立即开发差异窗口、联合排序或风险门控。

后续若继续，在开发材料中解释纠正与改坏，再决定新增什么信息及为何可能有效。已经使用的确认集合不再是未曝光材料，不能据其结果调参后重复宣称独立验证；正式 Test 的用途也没有因此自动改变。
