## 记录规则

以后每次实验在现有目录下留一份完整记录，并在这里追加一行。一次实验的多个配置／重试写在同一报告的运行表；新的研究问题才另编号。同一报告可记录连续诊断，但必须分清日期、输入、比较对象和结果，不能覆盖上一轮负结果。

每次完整记录至少包括：

| 字段 | 需要写清什么 |
| --- | --- |
| 编号、日期与执行状态 | 实际运行时间；完成／部分完成／失败／中止。只有计划时留在研究计划，不冒充已执行。 |
| 问题与预期 | 要验证的假设；在看结果前明确什么现象支持或反对它。 |
| 输入与数据用途 | 数据版本、实际数量、排除规则、Train／开发／确认身份、既有曝光及标签来源。 |
| 对照与唯一变化 | 比较对象、保持固定的条件、实际改变的因素；多项一起修改时按整体解释。 |
| 复现入口 | 实际命令／配置、代码提交及必要的未提交差异、模型与特征契约、种子、参数、选模规则和必要环境。优先引用已有配置文件。 |
| 实际运行与成本 | 各配置／重试的结束状态、轮数、耗时及计时范围；需要时记录本地资源或请求数量。失败不能折算为效果零分。 |
| 结果与不确定性 | 预定主次指标及分母、同分／缺失、纠正与改坏；适用时保留来源组分布和区间。不把开发结果当独立确认。 |
| 证据与限制 | 报告、模型、候选、统计和日志路径；路径是否本地存在、是否仅历史记录。人工待审就写待审，不把 AI 判断改称人工金标。 |
| 解释与决策 | 分开写观察、推测、已支持的结论，以及一项下一步建议；正结果和负结果都归档。 |

维护位置固定：**本台账登记每次实验，原报告保存详细实证，运行目录保存机器产物，CURRENT_STATUS 维护当前进度，研究计划维护下一步设计。** 不建立重复状态表或额外数据库。

新运行沿用 `runs/post_recall/<实验目的与日期>/` 和已有目录约定；轻量报告进 `docs/reports/`，矩阵、模型、逐题数据和日志保留在运行／模型目录。旧实验缺证据时在原条目补充限制，不为了补档重新训练或评分。更新正式报告后运行 `python3 scripts/build_report_index.py` 及 `--check`；本台账手工维护，生成脚本不会替你发现长报告中的新增实验。
