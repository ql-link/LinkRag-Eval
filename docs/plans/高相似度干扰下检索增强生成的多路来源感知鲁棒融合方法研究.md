> **概念解释｜RAG（检索增强生成）**：RAG 是“先从外部资料中检索证据，再让大模型依据证据生成答案”的系统。本研究只研究其中的检索、融合和排序部分，不直接研究最后的大模型如何组织答案。

> **概念解释｜Query、Chunk 与 Candidate**：`Query` 是用户问题；`Chunk` 是从文档中取出的一个可检索文本单元；`Candidate` 是某个 Chunk 被检索器找出后，在当前 Query 下形成的候选。一个 Chunk 是否正确，必须相对于具体 Query 判断。

> **概念解释｜召回、融合与重排**：召回负责从大语料中尽量“找全”可能相关的候选；融合把多个检索器的候选列表合在一起；重排在较小候选池内重新判断先后顺序。本文主要研究后两步，因此不能把“Gold 根本没被召回”的失败算成重排失败。

## 0. 结论先行

本研究具备明确的问题边界、可验证假设和工程基础，但不能把“LambdaMART 比 Reranker 好”或“保留三路分数和排名”直接写成创新。项目当前的 `candidate_difference_v3` 已经使用三路分数、归一化分数、排名、共同召回、路间排名差、编号/数字/否定/条件覆盖、同文档候选数量与相似度等 38 个线上特征。因此，“来源感知学习融合”属于既有工程能力，论文的方法增量收束为：**在每个候选的少量高相似近邻内，区分事实等价与可观测事实冲突，并用局部冲突风险条件化三路分数/排名优势。**实现上只增加可复用向量上的 Top-M 邻域统计和少量 LTR 特征，不构建持久化候选图，不训练图模型，也不把策略门控或干扰生成另立为研究问题。

> **概念解释｜基线与创新增量**：基线是新方法必须击败的已有方法。由于项目已经有很强的 `LTR-v3`，论文不能把 v3 已具备的能力重新包装成创新；必须证明新增特征相对强基线仍带来稳定、可复现的增量。

> **概念解释｜样本外验证**：在没有参与特征选择、模型训练和阈值调整的新数据上检验方法，称为样本外验证。它用于判断方法是真的能泛化，还是只记住了开发数据。

文献地图提供的启发按“直接进入方法、只用于边界判断”两级处理：

- **直接进入研究设计**：Hagström 等（2025）的相似非 Gold 退化现象、Balancing the Blend（PVLDB 2026）的弱路污染现象、Regulatory DOC2DOC IR（2021）的精确约束启发，以及 RARE（ACL 2026）对高冗余事实评测的提醒；
- **只用于防止夸大创新**：HybRank 的候选协作、MoR/QuDAR 的查询级动态融合、Contextual Relevance 的候选上下文和 R2anker 的重训练路线。当前论文不复现这些工作各自的完整系统，也不把图协作、门控或重训 Reranker 纳入主方法。

### 0.1 冻结的论文定位

本文定位为：

> **语义重排的边界条件研究 + 事实错误型相似拥挤的可控鲁棒性评测 + 冻结 Reranker 条件下的拥挤感知来源融合。**

现有研究常通过重训更强的语义 Reranker 处理 Hard Negative。本研究冻结 Reranker，保留 Dense、Learned Sparse、BM25 的检索路证据，用局部拥挤和可观测事实冲突对现有 LTR-v3 做小幅增量。完整研究只由特定退化问题、因果隔离实验、相对 `LTR-v3` 的低成本方法增量和鲁棒性验证四部分构成。

### 0.2 主创新与必要支撑

本研究的贡献结构收束为“一个主创新、两个必要支撑”：

1. **主创新——局部冲突风险条件化的多路来源感知鲁棒融合**：在现有 LambdaMART v3 之上，只对每个候选的 Top-M 高相似近邻计算局部密度、可观测约束冲突和分路局部 Margin，使融合判断显式依赖“相似性×可观测约束冲突×路由局部判别”；
2. **必要支撑一——事实错误型相似拥挤的操作化与可控构造**：在 Clean 基准外构造“低/高相似度 × 事实等价/冲突”的完整 2×2，并控制数量、强度、类型与候选池大小；
3. **必要支撑二——语义重排由收益转为伤害的边界分析**：用固定候选池确定退化来自排序阶段，并检验相似密度、事实冲突和分路局部优势能否解释错误晋升。

鲁棒性指标、双轨实验和跨数据验证是证明上述贡献成立的证据体系，不单独声称为算法创新。完整候选图、簇级拓扑、Route Fragility、学习门控和强化学习干扰生成均退出当前论文范围；将来如有独立资源，可作为后续研究，而不是本论文“增强包”。

### 0.3 贡献成立的硬条件

- 新方法必须与现有 `LTR-v3` 直接比较；只优于固定融合或某个 Reranker，不足以证明方法创新；
- 必须在至少两个独立 Reranker、两个公开数据来源和一个新内部 Blind 上检验，不能把历史“约 7%”作为新结论；
- 必须同时报告 Stress 改善与 Clean 损失；若以明显伤害 Clean 为代价，不称为鲁棒；
- 高相似事实冲突条件的伤害必须稳定大于高相似事实等价的良性冗余对照，否则不得把普通重复占位写成“事实错误型拥挤”机制；
- 推理期可观测的局部冲突特征必须在分层人工审计样本上具备基本构件效度；只有人工真值能形成特征时，方法不具备部署可用性；
- 完整方法必须同时优于 `LTR-v3`、density-only、query-constraint-only 和容量匹配的无类型局部邻域 D3，并排除收益只来自精确约束硬过滤或候选去重；
- 若拥挤特征相对 `LTR-v3` 没有 Blind 增量，方法贡献不成立，应收缩为“退化机制与评测”型论文，或终止该研究；

若只复用现有内部压测并报告一次“提升约 7%”，本研究不足以支撑《计算机科学》或《数据分析与知识发现》；若完成本文件的最低实验包，国内普通学术期刊可发表性较高；若再增加第三公开领域、跨域验证和一项近邻强基线，则具备冲击更高目标的条件。

### 0.4 文献灵感的采纳准则

| 文献启发 | 当前处理 | 原因 |
| --- | --- | --- |
| 相似非 Gold 会误导 Reranker | 保留为 RQ1 与压力实验 | 直接对应研究现象 |
| 弱检索路污染融合、精确约束可纠错 | 保留为分路 Margin 与四类约束 | 直接对应“多路来源感知” |
| 候选协作图、簇级拓扑 | 收缩为 Top-M 局部统计 | 保留局部上下文信息，避免图工程与大规模边标注 |
| 查询级门控、RL 干扰生成、多个近邻系统全复现 | 移出当前论文 | 分别属于策略学习、数据生成和系统复现，不能直接回答 RQ1—RQ3 |

以后新增灵感必须同时满足三个条件：直接回答 RQ1—RQ3、能够复用现有候选快照/LTR-v3、不会新增一个独立训练或标注子课题；否则只进入相关工作或后续研究。

## 1. 题目、术语与研究边界

### 1.1 中文正式题目

**高相似度干扰下检索增强生成的多路来源感知鲁棒融合方法研究**

题目中的“来源”专指候选来自 Dense、Learned Sparse、BM25 等哪一条检索路，不表示网页权威性、文档出处可信度或引用 provenance。

> **概念解释｜Retriever 与检索路**：Retriever 是“候选检索器”。同一问题可以同时交给多个 Retriever，每一个 Retriever 及其输出列表称为一条检索路。本文的“多路来源”就是这些检索路，而不是新闻、网站或机构的可信来源。

> **概念解释｜Dense、Learned Sparse、BM25**：Dense 把 Query 和 Chunk 编码成稠密向量，擅长识别意思相近但用词不同的文本；Learned Sparse 用模型学习少量重要词项及其权重，兼顾语义与词项可解释性；BM25 是经典词法检索方法，主要依据关键词是否出现、出现频率及词语稀有程度打分。三者错误模式不同，因此可能互补，也可能互相引入噪声。

### 1.2 英文题目

**Beyond Semantic Reranking: Retrieval-Route-Aware Robust Fusion under Similarity Crowding in RAG**

### 1.3 “来源感知”的严格含义

本文的 retriever provenance / retrieval-route provenance 仅指每个候选在检索流水线中的可追溯路由证据：

> **概念解释｜Provenance（来源追踪）**：Provenance 表示“这个结果从哪里、经过什么过程得来”。本文只追踪候选由哪条检索路召回、在该路的分数和排名；不评价文档作者是否权威。

- Dense、Learned Sparse、BM25 的原始分数、归一化分数和分路排名；
- 候选由几路共同召回以及哪些路共同召回；
- 分路之间的排名差、Top1—Top2 间隔、候选列表重合与冲突；
- 固定融合基线中的分数和位置；
- Query 与 Chunk 的编号、版本、数字、否定和条件匹配；
- 候选局部近邻密度、同文档近重复及候选集整体拥挤程度。

它**不表示**网页作者、机构权威性、文档可信等级、引用链或生成答案的出处归因。若未来加入这些信号，应另行定义为 document provenance，不与本文术语混用。

> **概念解释｜原始分数、归一化分数与排名**：不同检索器的原始分数量纲通常不同，不能直接相加。归一化是把分数变换到较可比较的尺度；排名只表示候选在某一路中的相对位置。本文同时保留三者，避免只看一个数而丢失来源差异。

### 1.4 研究对象

研究限定在 RAG 的**候选融合与排序阶段**。主要终点是检索排序质量和抗干扰性，不把生成答案质量作为主指标，也不把检索提升直接解释为答案质量提升。

上游 Dense/Sparse/BM25 召回器、编码器、索引、分词和候选深度在主因果实验中固定。端到端实验只用于验证外部有效性，不与候选池干预实验混成同一个因果结论。

> **概念解释｜上游、下游与端到端**：上游是先发生的召回、编码和建索引步骤；下游是候选融合、重排和生成步骤。端到端实验让整个系统都运行，更接近真实使用，但多个环节同时变化，较难判断究竟是哪一步导致结果变化。

> **概念解释｜外部有效性**：外部有效性关心“在受控实验之外、真实语料和完整系统中是否仍成立”。固定候选池有利于因果归因，语料/索引级实验则用于补充真实系统适用性。

## 2. 项目已有证据及其学术边界

### 2.1 已有正向依据

项目已经提供了较强的研究动机：

- 在同一候选池的 Top60 Clean 复测中，`qwen3-rerank` 相对固定 Hybrid 的 Recall@10 下降 `13.99pp`、Hit@10 下降 `15.44pp`、MRR 下降 `7.37pp`；
- 未曝光 Blind v3 中，来源感知 LambdaMART 相对同候选 Hybrid 的 Recall@10 提升 `8.00pp`，其中相似文档场景提升 `23.33pp`；
- 把 `qwen3-rerank` 分数作为附加特征时，Tune 仅提升 `0.70pp`，Blind v3 反而下降 `0.67pp`；
- Blind v4 的在线 LambdaMART + 短词回退使 MRR 提升 `7.6158pp`，但 Hit@10 置信区间跨 0；
- Blind v5 中整体 MRR 提升 `3.48pp`，但 500 条真实搜索子集 MRR 下降 `0.70pp`，说明平均收益与真实分布收益并不一致。

> **概念解释｜pp（百分点）**：`pp` 是 percentage point，即“百分点”，用于比较两个百分比的直接差值。例如 Recall 从 70% 升到 77%，是提高 7 个百分点（`+7pp`），相对增幅则是 10%；二者不能混写。

这些结果分别记录于 [LambdaMART 实验文档](../experiments/ltr-fusion-v1.md)、[Blind v4 验收](../reports/blind_v4_final_acceptance_2026_07_24.md)、[Blind v5 验收](../reports/blind_v5_production_contract_acceptance_2026_07_28.md)和[当前状态页](../CURRENT_STATUS.md)。

### 2.2 “约 7% 提升”只能作为动机

截图中的“提升约 7%”与项目历史中多个不同指标、不同数据分布的增量接近，但不能混写成一个统一结论：

- Blind v4 是 MRR `+7.6158pp`；
- Blind v3 是 Recall@10 `+8.00pp`；
- Blind v5 是 MRR `+3.48pp`，真实搜索 MRR 反而 `-0.70pp`。

因此正式论文不得写成“已有实验表明本方法普遍提升约 7%”。正确表述是：**既有项目实验观察到语义重排在特定候选分布中明显退化，同时来源感知学习融合在若干封存集合上取得正收益；这些观察用于提出假设，不作为新论文的验证结论。**

> **概念解释｜研究动机与确认性证据**：研究动机用于说明“为什么值得研究”，可以来自历史观察；确认性证据用于支持论文最终结论，必须来自事先冻结的新实验。二者不能混用，否则容易把已经看过的数据当成新验证。

### 2.3 现有 38 维特征已占据的创新空间

当前 `candidate_difference_v3` 已包含：

- 三路原始/归一化分数、倒数排名和缺失标记；
- 路由数量、两两重合、三路共同召回；
- 三路倒数排名差、各路 Top1—Top2 分数间隔；
- 固定 Hybrid 分数和倒数排名；
- Query 长度、数字标记；
- 编号、数字、否定、二元/三元词、多条件覆盖；
- 候选池稀有 Query bigram；
- 同文档候选数量、同文档最大 bigram 相似度和正文长度。

这意味着下列说法不得作为新论文的首创声明：

- “首次保留多路检索分数和排名”；
- “首次用 LambdaMART 融合 Dense/Sparse/BM25”；
- “首次利用编号、数字、否定词或条件匹配”；
- “首次保护固定融合 Top1”；
- “首次根据 Top1—Top2 margin 做回退”。

新方法必须明确增加**候选局部拥挤、可观测事实冲突和冲突条件化分路 Margin**，并通过消融证明它们相对 v3 的独立贡献。

> **概念解释｜LTR 与 LambdaMART**：LTR 是 Learning to Rank，即“让模型学习怎样排序”。LambdaMART 是常用的树模型排序算法，它根据特征学习候选的相对先后，并让靠前位置的排序错误受到更大关注。本文中的 LambdaMART v3 是已有强基线，不等于论文新方法。

> **概念解释｜特征与消融实验**：特征是模型可读取的数字化信号，例如 BM25 分数、数字是否匹配、候选局部近邻数量。消融实验是从完整方法中去掉某类特征后重新评测；如果去掉后明显变差，才说明该部分可能有独立贡献。

## 3. 研究问题与可证伪假设

> **概念解释｜RQ（Research Question）**：RQ 是论文要回答的研究问题。好的 RQ 应明确研究对象、比较条件和可观察结果，而不是只问“方法好不好”。本文用 RQ1—RQ3 分别研究退化现象、退化机制和鲁棒融合方法。

### RQ1：退化现象

在保持上游召回结果、目标等价组和候选池大小不变时，高相似事实冲突 Chunk 的数量和相似度提高，是否导致多种语义 Reranker 的等价组封顶 nDCG、MRR、Hit 和目标组最佳排名稳定退化；且该退化是否显著或稳定大于等量的高相似事实等价冗余？

### RQ2：退化机制

在候选数量与候选池固定时，退化主要由相似密度、重复占位、版本/数字/否定/条件冲突，还是来源支持差异驱动？仅使用 Query、Chunk 正文和三路检索证据形成的局部冲突风险与分路 Margin，能否解释错误候选晋升？

### RQ3：鲁棒融合

在相同候选池上，局部冲突风险条件化的来源融合能否相对语义 Reranker、固定加权、RRF、现有 LambdaMART v3、density-only、query-constraint-only 和容量匹配的无类型局部邻域降低退化曲线面积、Top1 错误翻转和查询级负收益比例？这些收益能否排除普通去重和精确约束硬过滤的解释？

### 主假设

> 当候选池由主题高度相似但精确事实条件冲突的 Chunk 主导时，主要依赖 Query—Chunk 整体语义相关性的 Reranker 更容易将“语义相似的错误共识”提升到前列；候选的局部冲突风险以及每条检索路相对疑似冲突近邻的分数/排名优势，能够提供与整体语义分数互补的判别证据，从而降低排序退化。

该假设允许被否证。若两种以上 Reranker 在两套公开数据上没有稳定退化，或新增拥挤特征不能优于现有 v3，则应停止该研究，不得继续调整定义直到得到正结果。

> **概念解释｜可证伪假设**：可证伪是指预先说明“出现什么结果就认为假设不成立”。如果无论实验结果怎样都能事后解释为成功，这个假设就没有科学检验价值。

> **概念解释｜相关、预测与因果**：相关表示两个现象一起变化；预测表示在新样本上可根据一个现象估计另一个；因果则要求改变某个因素会引起结果变化。本文先用固定候选干预支持有限因果解释，再用样本外预测检验方法是否可用，不能仅凭相关性声称因果。

### 预注册的机制假设

> **概念解释｜预注册**：预注册是在看正式结果之前，先冻结假设、主要指标、对照、统计检验和停止规则。它用于减少“看到结果后再挑有利说法”的研究者自由度。

> **概念解释｜主效应与交互效应**：主效应只问一个因素单独有没有影响，例如“相似度升高是否有害”；交互效应问一个因素的影响是否取决于另一个因素，例如“相似度升高是否只在事实冲突时格外有害”。本文的完整 2×2 正是为了识别这种交互。

- **H1（密度不充分）**：候选相似密度本身不足以稳定预测语义 Reranker 退化；事实等价与事实冲突的高相似候选不应被视为同一处理。
- **H2（交互效应）**：“高相似×事实冲突”的交互对目标等价组排名下移和错误候选晋升的解释力高于单独的相似度或冲突主效应。
- **H3（冲突条件化路由证据）**：候选相对疑似冲突近邻的分路分数/排名优势，比原始 route count 或共同召回更能区分真实佐证与错误共识；本文不声称 Dense、Sparse、BM25 在统计或因果上独立。
- **H4（方法增量）**：局部冲突风险条件化融合相对 `LTR-v3`、density-only、query-constraint-only 和容量匹配的无类型局部邻域在 Blind 与跨数据实验中具有稳定增量，且该增量不能由简单去重或精确约束硬过滤完全解释。

## 4. 方法框架

本方法保留多 Retriever 的来源、排名和分数差异，以低成本学习融合抵抗相似度干扰。框架只分为工程基线与论文方法增量两层：

| 层次 | 内容 | 论文角色 |
| --- | --- | --- |
| 工程基础 | 固定 Hybrid、三路分数/排名、精确匹配、现有 38 维 `LTR-v3` | 强基线与已有能力，不声明首创 |
| 论文新增 | 良性冗余/事实冲突双层构念、Top-M 局部冲突风险、冲突条件化分路 Margin 和拥挤条件化交互 | 主方法贡献，必须相对 `LTR-v3` 与 D1—D3 做消融和 Blind 验证 |

整条逻辑冻结为：先用事实等价良性冗余对照与事实冲突处理组分离“高相似”和“错误关系”，再解释语义重排何时提升错误近邻，最后检验局部冲突风险条件化的来源融合能否比现有来源融合、普通密度、单候选约束和无类型局部邻域更稳健。

### 4.1 统一候选与来源证据

对查询 \(q\)，固定三路候选并集 \(C_q=\{c_1,\ldots,c_K\}\)。每个候选保留：

> **概念解释｜候选并集、候选池与 K**：三路检索结果去重后合在一起形成候选并集，也称候选池。\(K\) 是池中候选数量。固定候选池的意思是：在同一个实验条件下，各方法看到完全相同的一组 Chunk，只允许排序方式不同。

\[
x_{route}(q,c)=
(s_d,s_s,s_b,r_d,r_s,r_b,agreement,disagreement,baseline)
\]

其中 \(s\) 表示分路分数，\(r\) 表示分路排名；缺失候选用显式缺失标记，而不是填入可混淆的普通分数。

> **概念解释｜缺失标记**：某候选可能被 Dense 找到，却没有被 BM25 找到。此时“BM25 没召回”本身就是信息，不能随便填成 0，因为 0 也可能是合法分数；应同时记录缺失状态和值。

候选正文特征继续沿用 v3 的 exact-match、number、negation、condition 和 n-gram 覆盖。论文必须把 v3 定义为强基线，不得把它混入“新方法”后只与固定权重比较。

### 4.2 双层拥挤构念与局部冲突邻域

“Similarity Crowding”不是既有公认标准术语，本文只能把它定义为一个可复现、可检验的操作性构念。本研究不再把高相似密度直接解释为风险，而是区分离线可审计的真实事实关系和推理期可观测的风险代理。

> **概念解释｜构念与操作化定义**：构念是不能直接用一个原始字段测量的研究概念，例如“错误拥挤”。操作化定义是把它变成可计算、可重复的规则，例如用候选间相似度、事实标签和局部密度组成公式。新名词只有被严格操作化并验证后，才具有研究意义。

> **概念解释｜离线真值与推理期代理**：离线分析可以使用人工标签和 qrels 判断候选到底对不对；真实部署时没有这些答案，只能使用文本、分数、排名等可见信息估计风险，这个估计量叫代理。论文必须证明代理与离线真值相关，但不能把真值偷偷输入模型。

#### 4.2.1 离线科学构念

设 \(z(c)\) 为冻结编码器生成的候选表示，\(sim(c_i,c_j)\) 为候选间余弦相似度。为控制实现成本，默认复用上游 Dense 候选向量；只有敏感性分析才使用独立编码器。定义高相似权重：

> **概念解释｜向量表示、余弦相似度与阈值**：编码器把文本变成向量；余弦相似度衡量两个向量方向有多接近，通常越大表示语义越相似。\(\tau\) 是判定“足够相似”的阈值，必须在开发集上确定并冻结，不能看测试结果后调整。

\[
w_{ij}(\tau)=
\mathbb{I}[sim(c_i,c_j)\ge\tau]\cdot sim(c_i,c_j)
\]

对每个候选只保留满足阈值的前 \(M\) 个最相似候选，记为 \(N_M(i)\)。\(M\) 默认只在 `{5,10}` 中选择，先导后冻结；不足 \(M\) 个时以零权重补足，保证不同 Query 的量纲一致。

> **概念解释｜Top-M 局部邻域**：它表示只观察与当前候选最相似的少量候选，而不是连接整个候选池。这样仍能描述“被相似错误项包围”的局部环境，但不需要图数据库、图神经网络或复杂聚类。

对每个候选先冻结 Query 条件化关系 \(r_i\in\{relevant,equivalent,incorrect,unknown\}\)，对应第 6.7 节的四类标签；再对分层抽样的 Top-M 近邻对确认约束关系 \(y_{ij}\in\{constraint\_consistent,conflicting,unknown\}\)：

- `constraint_consistent`：两个候选在 Query 相关约束槽位上取值一致，但不据此判断该共同取值正确；共享同一错误值的候选也可属于此类；
- `conflicting`：两个候选主题相似，但在版本/时间、数字、否定或适用条件上存在影响相关性判断的冲突；
- `unknown`：现有证据不足以稳定判定，不得当作确认性负例。

定义候选的局部高相似密度：

\[
d_i(q)=\frac{1}{M}\sum_{j\in N_M(i)}w_{ij}(\tau)
\]

候选集的良性事实等价冗余与有害事实错误拥挤分别定义为：

\[
BenignRedundancy(q)=
\frac{1}{KM}
\sum_i\sum_{j\in N_M(i)}w_{ij}(\tau)
\mathbb{I}[g_i=g_j]
\mathbb{I}[r_i,r_j\in\{relevant,equivalent\}]
\]

\[
FactErrorCrowding(q)=
\frac{1}{K}\sum_i d_i(q)
\mathbb{I}[r_i=incorrect]
\]

其中 \(g_i\) 是候选的等价组。`BenignRedundancy` 只累计同一相关等价组内部的局部高相似关系，不会把“Gold 被错误项包围”误记为良性冗余。`FactErrorCrowding` 是 Query 条件化的“高密度错误候选质量”，不要求错误候选彼此冲突；多个候选共享同一个错误版本或数字时，仍属于错误共识。近邻对关系 \(y_{ij}\) 只在分层审计样本上人工确认，用于验证规则或轻量抽取器，不要求人工标完全部候选对。上述量用于构件效度、机制分析与良性冗余对照，可使用人工关系标注和 qrels，但严禁直接进入推理模型。

> **概念解释｜良性冗余与错误共识**：良性冗余是多个候选用不同文本重复支持同一正确事实；错误共识是多个候选彼此很像、甚至互相一致，但共同给出不满足 Query 的版本、数字或条件。候选彼此一致不代表它们正确，因此本文必须同时看“与 Query 是否匹配”和“候选之间是否一致”。

#### 4.2.2 推理期可观测估计

对每个候选抽取仅依赖 Query、Chunk 正文和快照元数据的查询条件化约束签名：

> **概念解释｜约束签名与槽位**：约束签名把与正确性有关的信息拆成若干槽位。本文只处理版本/时间、数字、否定和适用条件，避免把通用信息抽取扩成另一个研究课题。

\[
\phi(q,c)=
(version,time,number,negation,condition)
\]

文档 ID、层级和同文档计数继续作为 v3 已有元数据，不包装成新的“约束槽”。合成父项、变换模板、人工等价组或压力池角色均不属于可用信号。

每个槽位同时保留抽取值、槽位类型及其相对 Query 的 `matched/conflicting/missing/unknown` 状态。必须区分：

- **Query 显式约束槽**：Query 已给出版本、时间、数字、否定或条件值，可以判断候选是否匹配；
- **待回答槽**：Query 只询问某个数字或版本而未给出正确值，只能观察候选间是否分歧，不能从 Query 推断哪个候选正确。

待回答槽的候选—Query 错配必须记为 `unknown`，不得因与人工答案不一致而写入推理特征。由确定性规则或冻结的轻量抽取器得到显式槽上的候选—Query 约束错配 \(\hat m_i\in[0,1]\) 和 Top-M 近邻对冲突 \(\hat{\chi}_{ij}\in[0,1]\)。局部风险同时保留可判定的 Query 错配和候选对冲突：

> **概念解释｜显式约束、待回答槽与 unknown**：如果 Query 写明“2025 版”，就能直接判断候选版本是否匹配；如果 Query 问“数值是多少”，Query 本身并没有正确数值，模型只能发现候选数字互相矛盾，不能知道谁正确。后者必须标成 `unknown`，否则会把人工答案泄漏给模型。

`missing/unknown` 必须作为独立状态和缺失标记保留，不得静默编码为“匹配”或“无冲突”。对没有可抽取事实约束的 Query，模型只能依赖密度与路由特征；若此类 Query 上风险不可辨识，应报告适用边界，而不是用人工场景标签补足。

\[
\hat r_{ij}=w_{ij}(\tau)
\left[
\lambda\hat{\chi}_{ij}+(1-\lambda)\frac{\hat m_i+\hat m_j}{2}
\right]
\]

候选级局部冲突风险及 Query 级摘要定义为：

\[
LocalConflictRisk(c_i)=
\frac{1}{M}\sum_{j\in N_M(i)}\hat r_{ij}
\]

\[
ObservableConflictCrowd(q)=
\frac{1}{K}\sum_i LocalConflictRisk(c_i)
\]

最低新特征只包含候选级局部统计：

- `QueryConstraintMismatch(c)`：候选相对 Query 的版本/时间、数字、否定和条件错配；
- `LocalCrowd(c)`：Top-M 近邻的平均相似度与有效近邻比例；
- `LocalConflictRisk(c)`：近邻相似度、候选对冲突和可判定 Query 错配的加权汇总；
- `MaxConflictSimilarity(c)`：与最相似疑似冲突项的相似度；
- `ConflictAdjustedRouteMargin_r(c)`：分别保留候选在 Dense、Learned Sparse、BM25 每条路上相对疑似冲突邻居的归一化分数/排名优势，直接刻画哪条路能在语义近邻之间保留约束判别力；
- 各项对应的覆盖率和缺失标记，防止“没有可抽取约束”被误编码为安全。

> **概念解释｜局部冲突风险与 Margin**：局部冲突风险表示候选周围是否聚集了“文本很像但约束不一致”的近邻；Margin 是当前候选在某一检索路上领先这些疑似冲突近邻多少。二者分别描述候选环境与各路的局部判别力。

实现上不保存图对象或全量候选对标签，也不调用成对 LLM/NLI。对 \(K=150\)、\(M\le10\) 的 Query，最多只对 1500 个有向近邻关系执行轻量约束比较；相似矩阵按 Query 即算即弃。若 Top-M 版本在先导中无增量，不再扩展到聚类、图模型或更多邻居。

其中令 \(N_{conf}(c_i)=\{c_j\in N_M(i):\hat r_{ij}\ge\rho\}\)，每路分数在 Query 内按冻结规则归一化，则可写为：

\[
ConflictAdjustedScoreMargin_r(c)=
\mathbb{I}[c\text{ 被 }r\text{ 召回}]
\left[
\tilde s_r(c)-\max_{c_j\in N_{conf}(c)\cap C_r}\tilde s_r(c_j)
\right]
\]

\[
ConflictAdjustedRankMargin_r(c)=
\mathbb{I}[c\text{ 被 }r\text{ 召回}]
\left[
rr_r(c)-\max_{c_j\in N_{conf}(c)\cap C_r}rr_r(c_j)
\right]
\]

其中 \(r\in\{d,s,b\}\)，\(rr_r\) 是冻结的倒数排名，\(C_r\) 是被路由 \(r\) 实际召回的候选集合。六个分路 margin 必须分别保留路由身份；均值、最小值和最大值只能作为附加聚合，不能用单一求和让弱路抵消强路。路由内疑似冲突邻居为空或候选本身缺失时的值、默认值和缺失标记编码必须在 Tune 前冻结。该特征不读取 Gold，只比较可观测的疑似冲突局部邻域。

只在离线机制分析中，另计算需要 qrels 的 gold/non-gold separation：

\[
Separation(q)=
\max_{c\in Gold_q}sim(q,c)-
\max_{c\notin Gold_q}sim(q,c)
\]

`Separation`、`BenignRedundancy`、`FactErrorCrowding`、Gold 身份、注入数量和人工干扰类型只能用于离线分析，不能进入融合器。主实验在固定的分层审计集上检验 \(\hat m\) 对显式候选—Query 错配、\(\hat{\chi}\) 对 Top-M 候选对冲突标注的构件效度，并报告显式约束槽覆盖率与有/无可判定约束 Query 的选择性性能。`ObservableConflictCrowd` 与查询级 Reranker 伤害的关系只作机制分层，不再单独训练风险分类器。

> **概念解释｜构件效度与增量效度**：构件效度问“代理是否真的测到了事实错配或冲突”；增量效度问“加入该信息后，是否比纯密度、单候选约束和同容量普通邻域方法更好”。前者验证测量是否可信，后者验证它是否值得进入排序模型。

`QueryConstraintMismatch` 对版本、数字、否定和条件的单候选表达与 v3 既有 exact features 存在重叠，本身不属于新创新。论文新增只来自这些约束信号与高相似局部结构、候选对冲突和分路局部优势的条件化交互；消融必须证明它不是重新命名已有 exact features。

\(\tau\)、\(\rho\)、\(M\)、K、\(\lambda\)、向量复用方式、约束抽取器和归一化方式只能在 Tune 上选择并冻结。

### 4.3 来源感知鲁棒融合

最低实现复用 LambdaMART v3 的训练和推理管线，只增加局部拥挤、局部冲突风险和冲突条件化路由证据：

\[
F(q,c)=LTR(
x_{route},
x_{exact},
x_{candidate},
x_{density}(q,C_q,c),
x_{conflict}(q,C_q,c),
x_{conflict\_conditioned\_route}(q,C_q,c))
\]

方法阶梯只保留四个必要层次：

> **概念解释｜诊断基线与方法阶梯**：诊断基线不是为了凑数量，而是逐层排除简单解释。这里依次检查收益是否只来自候选密度、单候选约束匹配，或者只是增加了同等数量的普通邻域特征。

- `LTR-v3`：现有 38 维来源与候选差异特征；
- `D1 = LTR-v3 + density-only`：只增加 Top-M 相似度均值、最大值、有效近邻比例和 Query 平均拥挤度；
- `D2 = LTR-v3 + query-constraint-only`：只增加候选—Query 显式约束错配及覆盖率，不使用候选对冲突；
- `D3 = LTR-v3 + matched-capacity untyped-local`：使用与 M1 相同的学习器、调参预算和新增特征数，但用普通相似度邻域统计及无类型 route margin 替代冲突类型，检验收益是否只是特征更多；
- `M1 = LTR-v3 + local-conflict-route`：加入 `LocalConflictRisk`、`MaxConflictSimilarity`、显式约束覆盖率和六个分路冲突 Margin，作为唯一完整新方法；不读取语义 Reranker 输出。

若 M1 只比 v3 在 Tune 上提高，而 Blind 或跨数据下降，应判定为过拟合，不得将局部冲突特征写成有效贡献。若 M1 不优于 D1—D3，尤其不能优于容量匹配的 D3，则只能把结果解释为普通密度或特征容量收益。

> **概念解释｜Matched-capacity（容量匹配）**：两个模型如果特征数量、学习器复杂度和调参预算差很多，强模型获胜可能只是因为“容量更大”。容量匹配基线尽量保持这些条件相同，只移除真正要检验的类型化冲突信息。

> **概念解释｜过拟合**：模型在 Tune 上表现很好，却在 Blind 或新领域下降，通常说明它学到了开发数据的偶然模式，而不是可泛化规律。

### 4.4 两个独立实验能力（边界已冻结，暂不实现）

为避免研究被 LinkRag 当前存储拓扑、在线服务状态或后续版本升级绑住，正式实验拆成两个只通过不可变产物衔接的能力。这里冻结的是职责和数据契约，不代表现在开始改代码。

> **概念解释｜不可变快照与可重复播放**：不可变快照是生成后不再覆盖修改的一份候选数据文件。任何内容变化都产生新版本。离线实验器反复读取同一快照，就能保证不同方法看到完全相同的输入。

#### 能力 A：候选快照生成器（Candidate Snapshot Generator）

输入是冻结的数据集、基础语料 Chunk、Query/qrels，以及版本明确的 Dense、Sparse、BM25 编码与召回配置；输出是可被离线重复播放的候选快照。它负责：

- 按第 6 节规则物化或接收基础语料 Chunk；
- 以固定深度执行三路召回并构造候选超集；
- 保存候选文本、Gold 标签、三路是否召回、原始分数和原始名次；
- 保存 `relevant_gold` / `relevant_equivalent` / `verified_incorrect_distractor` / `unresolved_possible_false_negative` 四类查询—候选关系，以及 `pool_role`、equivalence group、冲突类型、父 Chunk、变换记录和标注置信度；
- 保存候选池构造方式、模型与代码指纹、参数、数据 revision 和内容摘要；
- 对合成反事实 Chunk 重新计算真实三路证据，绝不人工填写分数或名次；
- 输出版本化、只读且可校验摘要的快照，不在其中比较论文方法。

快照可由钉住旧 SHA 的 LinkRag、完成适配后的新 LinkRag，或接口等价的独立检索器生成；三者不得在同一确认性实验中混用。生成来源必须作为实验条件记录，但在快照形成之后，离线实验不再依赖该 LinkRag 版本能够运行。

> **概念解释｜Revision、指纹、SHA 与内容摘要**：Revision 是数据或模型的明确版本；指纹是一组能识别运行环境的版本信息；SHA/内容摘要是由文件内容计算出的短标识，内容一变标识也会变。它们共同用于证明“这次实验究竟用了哪份数据、代码和模型”。

富快照必须通过模式层产生两个不可混用的投影：

> **概念解释｜数据投影与标签泄漏**：同一份富快照可以裁剪成不同视图。`method_view` 是模型真实可见的数据；`evaluation_view` 含答案和人工标签，只供算指标。如果方法读取了后者，就叫标签泄漏——看似准确，实际部署时无法获得这些信息。

- **`method_view`**：只含 Query/Chunk 正文、生产可见的文档 ID/版本元数据、三路分数/排名/命中标记和由这些字段确定性计算的特征；
- **`evaluation_view`**：含 qrels、Gold/等价/错误关系、`pool_role`、父 Chunk、合成变换/模板、人工冲突类型、注入数量和标注置信度。

融合器和任何特征代码只能接收 `method_view` 类型。合成父子 ID、合成模板 ID 和由人工标签产生的“文档关系”属于 `evaluation_view`，不能以 `document_identity` 名义进入方法。实现时加入泄漏不变性测试：删除、随机置换或脱敏全部 evaluator-only 字段后，同一 `method_view` 的方法分数与排序必须逐值不变。

#### 能力 B：纯离线融合/重排实验器（Offline Fusion and Reranking Experimenter）

输入是不可变候选快照和冻结的方法配置；它在每个条件内把完全相同的候选池交给固定权重融合、RRF、语义 Reranker、`LTR-v3`、D1—D3 和 M1，并输出：

- 每种方法的完整排序和候选级分数；
- Top-M 邻域参数、可观测冲突代理、候选级局部特征，以及对应的配置和摘要；
- 等价组封顶与官方 qrels 两套 Recall/MRR/NDCG、目标等价组最佳排名位移、原始 Gold ID 排名敏感性、错误翻转率、负收益率和退化曲线；
- Query 级成对差值、分组结果、随机种子、运行指纹和审计日志；
- 由同一快照可重复得到的 Clean/Stress 配对结果。

该能力只消费文件化快照，并在方法执行前强制生成 `method_view`；指标与审计器另读 `evaluation_view`，两者不得以无类型字典重新合并。它不访问 Qdrant、SQLite 生产表或 LinkRag 在线召回链。语义 Reranker 可以作为被测模型进行离线推理，但其模型 ID、revision、截断长度和批处理设置必须冻结。

#### 版本边界与实现时机

- 轨道 A 的论文主体不要求先把 LinkRag-Eval 全量升级到最新 LinkRag；只要候选快照完整、来源真实且可复核，即可独立开展排序研究。
- 新建候选快照和轨道 B 的重新入索引实验，需要一个可工作的生成器；可选择钉住可运行旧版本或修复新版本适配，但必须保持同一确认性实验的上游口径一致。
- 不继承会随 LinkRag 变化的隐式默认值。Top-K、权重、阈值、分词器、编码器和候选去重规则全部显式写入快照清单。
- 当前阶段只完成方案与契约冻结，不实现这两个能力。开始先导实验前，先检查现有历史产物能否满足快照必填字段；只有字段不足时才进入实现。

## 5. 如何弱化上游影响：双轨实验设计

### 5.1 轨道 A：候选池干预实验（主要因果证据）

该轨道直接回答融合/重排在相同输入下是否退化：

> **概念解释｜候选池干预与直接效应**：候选池干预是有计划地把某类干扰候选换入固定大小的候选池，同时保持 Gold、K 和其他条件尽量不变。它估计的是“在冻结上游候选证据后，排序方法受到的直接影响”，不是整个真实系统的总因果效应。

> **概念解释｜成对比较**：同一个 Query 在 Clean 和 Stress 下各得到一个结果，再计算二者差值，叫成对比较。因为 Query 自身难度被抵消，通常比比较两组不同 Query 更有统计效率。

1. 先用冻结的 Dense/Sparse/BM25 在足够深度上生成候选超集和所有来源证据；
2. 只保留 Gold 已进入冻结候选池的 Query，防止把上游召回失败算成重排失败；
3. 自然干扰项只从候选超集中选择，保留其冻结的真实分路分数和排名；合成反事实项须用同一冻结编码器、Sparse 编码器和 BM25 口径离线重算三路证据，不能手工伪造分数；
4. 为每条 Query 构造固定大小的主 Stress 池，其中包含目标等价组、最多 50 个主曲线干扰候选，以及按来源路、原始排名、长度和文档族匹配的普通负例；只有饱和压力资格子集额外扩展到 100 个；
5. 在不同 \(n\) 水平下，用 \(n\) 个干扰候选替换等量的匹配普通负例，使候选总数、目标等价组、来源分布和其余控制项保持不变；
6. 分路分数采用冻结原始值，列表内重排后的显示名次与原始分路名次分别保存，避免把实验子集重排误当成上游检索名次；
7. 所有融合和 Reranker 使用完全相同的候选集合；
8. 对每条 Query 的 Clean/Stress 结果做成对比较。

若最大注入数量为 100，\(K_{pool}\) 必须至少为 150，并在实验前冻结。不能一边把 Reranker 限制在 Top50，一边声称测了 100 个进入其输入的干扰项。

#### 5.1.1 Clean + 完整 2×2 因果对照

为区分普通密度、重复占位与事实冲突，轨道 A 必须包含下列对照：

> **概念解释｜Clean、Stress、处理组与对照组**：Clean 是没有目标压力干扰的基准候选池；Stress 是加入特定干扰后的压力条件；处理组接受研究中的关键变化，例如高相似事实冲突；对照组用于回答“如果只有高相似但事实仍正确，会怎样”。

> **概念解释｜完整 2×2 因子设计**：这里有两个因素——相似度（低/高）和事实关系（等价/冲突），两两组合得到四个条件。普通负例 Clean 另列。完整组合可以分别估计两个因素的影响及其交互，缺一个格子就不能严格估计完整交互。

| 条件 | 候选相似度 | 事实关系 | 主要用途 |
| --- | --- | --- | --- |
| 普通负例 | 低 | 错误/不相关 | Clean 基准 |
| 低相似事实等价 | 低 | 等价/可替代证据 | 完整因子设计，估计事实关系主效应和交互；从措辞差异较大的替代证据中选择 |
| 低相似事实冲突 | 低 | 版本/数字/否定/条件等冲突 | 隔离事实错误主效应 |
| 高相似事实等价 | 高 | 等价/可替代证据 | 良性冗余对照，隔离相似密度与重复占位 |
| 高相似事实冲突 | 高 | 版本/数字/否定/条件等冲突 | 核心处理条件 |

Clean 使用普通负例；其余四类候选构成“低/高相似度 × 等价/冲突”的完整 2×2，并应尽可能按来源路、原始排名区间、长度、文档族与父 Chunk 匹配。核心机制效应是“高相似×事实冲突”交互，不是单独的 Stress—Clean 差。若某数据源无法得到足量、经核验的低相似等价证据，则该数据源只报告预注册简单对比，不进入交互效应估计。

#### 5.1.2 低成本机制核验

机制证据优先来自完整 2×2、错误类型分组和 M1 的特征组消融，不再单独构造簇替换或全组合来源 Knockout。必要控制只保留：

- **来源支持分层**：区分单路召回、两路召回和三路共同召回的错误候选，报告 M1 是否只在某一来源组合有效；
- **分路 Margin 消融**：一次移除全部冲突条件化分路 Margin，检验收益是否确实来自来源证据；不逐路穷举所有组合；
- **顺序/批次敏感性控制**：仅对一次接收多个候选的 listwise/setwise Reranker，使用至少 3 个预先冻结的随机排列重复评分并报告方差；逐候选独立打分的 cross-encoder 标记为不适用，不为凑实验而重复。

> **概念解释｜Pointwise、Cross-encoder、Listwise 与 Setwise**：Pointwise/Cross-encoder 通常一次独立给一个 Query—Chunk 对打分，其他候选的顺序不应改变该分数；Listwise/Setwise 一次同时查看多个候选，判断可能受候选组合和出现顺序影响，因此需要顺序敏感性控制。

这些结果只用于机制解释，不把事后知道哪条路有害的结论直接变成测试时特征或选择规则。

这一轨道把上游检索结果物化为版本化候选快照，将其视为已知、固定和可检验的实验条件。LinkRag 版本只作为快照生成指纹，不作为方法间变化因素；快照一旦冻结，所有排序方法都在纯离线条件下重复播放。这能最大程度弱化上游影响，是论文关于“语义重排退化机制”和“融合抗干扰性”的主要证据。

### 5.2 轨道 B：语料/索引级干预实验（外部有效性证据）

在较小子集上把相同干扰 Chunk 真正加入独立 eval 语料和索引，重新执行 Dense/Sparse/BM25、融合和重排。它回答真实系统中干扰文档进入索引后，结论是否仍成立。

轨道 B 同时包含上游召回变化和下游排序变化，因此只报告端到端结果和分阶段归因，不能用它单独证明融合算法的因果效果。至少拆分：

- Gold 是否进入三路并集；
- Gold 在每一路和融合前的位置；
- 融合/重排后的 Gold 位置；
- 干扰候选由哪一路召回并在哪一阶段晋升。

### 5.3 两轨结论边界

| 结论 | 轨道 A | 轨道 B |
| --- | --- | --- |
| 相同候选下某 Reranker 是否退化 | 主要证据 | 辅助证据 |
| 来源感知融合是否更抗干扰 | 主要证据 | 外部验证 |
| 干扰语料是否改变上游召回 | 不回答 | 主要证据 |
| 真实端到端 RAG 检索鲁棒性 | 局部回答 | 主要证据 |

## 6. 干扰集合构造

### 6.1 三层 Chunk 定义

论文中的“Chunk”不能混用，固定分成三层：

> **概念解释｜Corpus Chunk、Candidate Chunk 与 Distractor Chunk**：Corpus Chunk 是语料中的原始检索单元；Candidate Chunk 是它针对某条 Query 被召回后，加上分数和排名的状态；Distractor Chunk 是经核验会干扰当前 Query 的候选。三者不是三份不同文本，而是同一文本在不同实验层次上的身份。

| 层次 | 定义 | 是否包含检索证据 |
| --- | --- | --- |
| 基础语料 Chunk（Corpus Chunk） | 从公开 corpus record 或内部原始文档物化出的最小检索单元 | 否 |
| Query 候选 Chunk（Candidate Chunk） | 某条 Query 下进入候选超集的基础 Chunk，加上三路分数、名次和命中标记 | 是 |
| 压测干扰 Chunk（Stress/Distractor Chunk） | 经核验为不满足 Query 事实条件的自然或合成候选，并带干扰类型和来源标注 | 是 |

同一基础 Chunk 可以对不同 Query 成为 Gold、普通负例或干扰项；标签属于 `query_id × chunk_id`，不能只挂在 Chunk 本身。

### 6.2 基础语料 Chunk 如何产生

> **概念解释｜确定性切分**：确定性切分表示同一输入文档、同一配置每次都会得到完全相同的 Chunk 边界和 ID。这样重新运行实验时 qrels 不会因为切分漂移而失效。

#### 公开检索数据集：原始记录直通

- 对 `T2Retrieval`、`MedicalRetrieval` 等已提供 corpus 与 qrels 的数据集，将 corpus 中一个带稳定 ID 的原始 record 直接视为一个实验 Chunk，不再用 LinkRag 二次切分。
- 保留原始 `corpus_id`、标题、正文、数据 revision 和文件摘要；内部 `chunk_id` 可由 `dataset_id + revision + corpus_id` 确定性映射，但必须同时保留原始 ID。
- 这样 qrels 仍精确指向同一个评测单元。若因超长文本必须再切分，应另建派生数据版本，并重新建立 passage 级 qrels；不能把原文档标签自动复制给所有子 Chunk。

#### 内部原始文档：一次性确定性切分

- 先完成文本解析、编码统一和明显模板噪声清理，再调用一个钉住版本的结构化 Chunking 配置；优先复用 LinkRag `ChunkingEngine.aprocess`，但也允许接口等价的独立实现。
- 切分器代码 SHA、解析器、最大长度、重叠、标题继承、表格/列表处理、语言分词口径必须在先导实验前确定，随后对所有方法保持不变。
- `chunk_id` 按 `dataset_id + document_id + ordinal` 确定性生成；同时保存原文档 ID、文档版本、起止位置、ordinal、文本摘要和 chunker 指纹。
- 训练、Tune 和 Blind 按原始文档族和版本分组，禁止同一文档的相邻块或新旧版本跨集合泄漏。
- Chunking 不是本文方法变量。主结果不得为某个排序方法单独调整 Chunk 大小或重叠；不同切分策略只能作为额外敏感性分析，不能与主方法收益混算。

因此，基础语料的物化路径固定为：

```text
公开数据：corpus record ───────────────→ Corpus Chunk
内部数据：原始文档 → 解析/清理 → 固定切分 → Corpus Chunk
                                           ↓
                    三路冻结召回 → Candidate Chunk → Clean/Stress 快照
```

### 6.3 Gold、普通负例与干扰 Chunk 如何产生

> **概念解释｜Gold、qrels 与 relevance grade**：Gold 是人工或数据集确认的正确证据；qrels 是“Query—文档相关性标签表”；relevance grade 是相关程度等级。它们是评测真值，只能用于构造和算分，不能作为模型输入。

> **概念解释｜正例、负例、Hard Negative 与 False Negative**：正例是满足 Query 的候选；负例是不满足 Query 的候选；Hard Negative 是表面非常像正确答案、但关键事实不对的困难负例；False Negative 是实际上相关却被误标成负例的样本，会错误惩罚好方法。

1. **Gold Chunk**：公开数据以 qrels 为准；内部数据由问题—证据对齐得到，允许一问多 Gold。Gold 的身份必须在检索和排序实验前冻结。
2. **候选超集**：对全部 Corpus Chunk 使用固定 Dense、Sparse、BM25 在足够深度分别召回，再取去重并集；每条记录保留三路真实分数、原始名次和是否命中。
3. **自然 Hard Negative**：从候选超集中选择“语义或词法高度相似、但不满足版本/数字/否定/条件等事实约束”的原始 Chunk。未出现在 qrels 中只表示“未标为相关”，不自动等于不相关；高相似候选必须经人工核验，疑似漏标相关项应补标或排除。
4. **同文档/近重复干扰**：从相邻 Chunk、旧版本、同模板记录或近重复候选组中选择，仍须确认其对当前 Query 不构成正确答案。
5. **受控反事实 Chunk**：从 Gold 或同主题原始 Chunk 出发，一次只改变一个可核验事实单元，如版本、数字、否定或适用条件；保存父 Chunk、变更前后片段、变换类型和错误理由。可由模板或 LLM 辅助生成，但必须人工复核，且生成模型不能作为唯一裁判。
6. **事实等价高相似项**：从多正例、等价证据组或经人工确认的近重复中选择，必须对当前 Query 提供相同或可替代事实，用作高相似良性冗余对照；不得把未标注候选自动视为等价证据。
7. **普通负例**：从候选超集中选择不属于 Gold、等价证据或压力干扰的候选，并按检索来源、原始名次区间、长度和文档族匹配，用于在不同干扰强度下做等量替换。

所有合成反事实 Chunk 都必须进入与真实语料相同的编码、分词和检索过程，重新得到 Dense/Sparse/BM25 证据。禁止根据期望结论手工指定其分数、排名或来源标记。

> **概念解释｜反事实与原子变换**：反事实是在尽量保持其他内容不变时，只改变一个关键事实，观察结果是否变化；原子变换表示一次只改版本、数字、否定或条件中的一个。这样更容易把排序退化归因到具体机制。

> **概念解释｜自然样本与合成样本**：自然样本来自真实语料，现实性较强但控制较弱；合成样本由规则或模型构造，容易精确控制变量，但可能带有人工痕迹。二者应分开报告并相互验证。

### 6.4 候选快照与压力池生成

> **概念解释｜候选超集与压力池**：候选超集是用较深召回得到的“大备选库”；压力池是从超集中按实验规则选出的固定大小候选集合。先有超集再抽取压力池，可以避免每个方法各自得到不同候选。

候选快照的最小必填字段为：

| 字段组 | 必填内容 |
| --- | --- |
| Query | `dataset_id`、revision、split、`query_id`、原始文本、文本摘要 |
| Chunk | `chunk_id`、原始 corpus ID、`document_id`/文档族/版本、ordinal、文本、文本摘要 |
| 标签 | relevance grade、`relevant_gold` / `relevant_equivalent` / `verified_incorrect_distractor` / `unresolved_possible_false_negative`、`pool_role=ordinary_negative/stress_distractor/benign_redundancy_control`、equivalence group、自然/合成标记、干扰/冲突类型、父 Chunk、冲突事实片段、可核验理由、标注置信度 |
| 三路证据 | 每一路的 retrieved flag、raw score、original/counterfactual rank、`observed/recomputed` 证据来源；缺失值语义必须显式 |
| 构造信息 | 超集深度、去重规则、Clean/Stress 条件、替换配对、pool version/hash |
| 指纹 | chunker、parser、Dense/Sparse/BM25、代码 SHA、配置和随机种子；Reranker 指纹写入离线实验运行清单 |

轨道 A 的压力池按以下顺序产生：

1. 先生成比最终输入更深的三路候选超集；主曲线最终 `K_pool` 至少为 100，运行 100 个干扰的饱和压力子集时 `K_pool` 至少为 150。
2. 只把 Gold 自然进入冻结超集的 Query 纳入轨道 A；不得为了保留样本而手工塞入 Gold。被排除 Query 的数量、上游覆盖率和分布必须报告，并在轨道 B 中继续统计。
3. 为每条 Query 建立固定大小的 Clean 池和最大 Stress 池；两者保持相同 Gold 和候选总数。
4. 主退化曲线使用 `n=0/5/10/20/50`；只有具备至少 100 个合格干扰且不额外放宽标签标准的 Query 才进入 `n=100` 饱和压力敏感性分析。所有条件都用 n 个压力干扰替换 n 个匹配普通负例，不向候选池无限追加项目。
5. 每个数据集 × 相似度 × 事实关系分层预先冻结候选资格、匹配距离和抽样优先级；不得根据被测方法结果挑选“更有效”的干扰。
6. 每个 Query 建立 1 条预注册的主嵌套替换链，满足 `D5⊂D10⊂D20⊂D50`；在分层抽取的 20% Query 上增加第 2 个随机种子检查抽样敏感性。`D100` 只扩展符合资格的链并单独报告，不改变主 nAUDC 的 cohort。
7. 同一 Query、同一压力条件和同一替换种子下，所有被比较方法接收逐 ID 完全相同的候选集合；只有排序策略变化。
8. 在生成任何方法结果前冻结主曲线共同 cohort；无法获得 50 个合格干扰的 Query 数量、可构造率、排除原因和分布必须报告，不能在高剂量时静默删去困难样本。
9. 每个快照写入清单和内容摘要并转为只读。任何 Chunk、标签或三路证据变化都必须产生新的快照版本，不能覆盖旧结果。

候选集合在不同压力条件之间会按预先设计发生变化，这是受控干预；它在同一条件的方法之间必须严格一致，这是公平比较。轨道 A 估计的是**条件于冻结上游证据和预定义压力分布的排序阶段直接效应**，不是对任意真实语料污染过程的无条件因果结论。

> **概念解释｜随机种子、嵌套替换链与共同 Cohort**：随机种子使随机抽样可重复；嵌套链表示 20 个干扰条件包含前面 5、10 个干扰，而不是重新抽一批；共同 cohort 是在主曲线全部剂量下都能完成实验的同一批 Query。这样剂量曲线的变化不会被样本更换混淆。

> **概念解释｜敏感性分析**：敏感性分析用另一种合理口径重新计算结果，例如只做到 `n=50` 或使用官方 qrels。若结论在多种口径下方向一致，可信度更高；若不一致，就必须报告结论依赖哪些选择。

### 6.5 核心变量

| 变量 | 冻结取值 |
| --- | --- |
| 干扰数量 | 主曲线 0、5、10、20、50；100 仅作饱和压力敏感性分析 |
| 相似度强度 | 低、中、高；由冻结编码器在 Tune 上确定分位区间 |
| 事实关系 | 等价、冲突、未知；确认性主结果只使用已人工核验的等价/冲突项 |
| 干扰类型 | 确认性主类型为版本/时间错误、数字错误、否定错误、条件缺失；近重复和同文档只作为来源属性分层 |
| 检索/排序策略 | Dense、Sparse、BM25、固定融合、RRF、两个语义 Reranker、LTR-v3、D1/D2/D3、M1 |
| 数据来源 | 新内部压力集 + 两个公开数据集 |

不建议机械运行完整的 `6 数量 × 3 相似度 × 6 类型` 全因子组合。最低实验采用：

1. **主退化曲线**：使用四类事实冲突的平衡混合池，运行 0/5/10/20/50；
2. **良性冗余对照实验**：固定数量为 20，运行低/高相似度 × 事实等价/冲突的完整 2×2；
3. **机制实验**：固定数量为 20，分别报告四类冲突、来源支持分层和三组必要消融；
4. **高剂量敏感性**：只对资格充足的共同子集运行 100 个干扰，不把它纳入主方法成败门槛。

这样既保留因果解释，又避免低预算团队承担无必要的全排列成本。

### 6.6 自然与合成干扰并存

每个公开数据集同时使用：

- **自然 Hard Negative**：从冻结的 Dense/Sparse/BM25 深层候选并集中挖掘，默认复用冻结 Dense 表示划分相似度带；人工确认其与 Query 主题相关但不满足事实条件。qrels 未标注只能作为待审候选，不能单独充当“不相关”证据；
- **受控反事实 Chunk**：在 Gold 或同主题 Chunk 上只改变版本、数字、否定、条件等最小事实单元；
- **同文档干扰**：从同一文档的相邻 Chunk、旧版条款或上下文不完整 Chunk 中选择；
- **近重复候选组**：保留长度、文风和主题，控制信息差异，避免简单格式伪影。
- **事实等价近重复**：从多正例或经人工确认的可替代证据中构造良性高相似对照，与冲突近重复分开报告。

合成 Chunk 必须明确标注 `synthetic_counterfactual`，不能冒充公开数据原始文档。自然和合成结果分别报告，不能用合成集的高收益替代自然集结论。

### 6.7 标签与质量控制

> **概念解释｜人工复核、双人复核与仲裁**：单人复核负责逐条检查；双人独立复核让两位标注者在互不影响下判断；意见不一致时由预定规则或第三人仲裁。这样可以量化标签是否稳定，而不是默认人工判断一定正确。

- 每个已确认干扰候选必须明确写出“不相关/错误”的可核验理由；每个等价候选必须记录可替代证据理由和 `equivalence_group_id`；
- 查询—候选关系只允许 `relevant_gold`、`relevant_equivalent`、`verified_incorrect_distractor`、`unresolved_possible_false_negative` 四类；普通负例与压力干扰都可属于 `verified_incorrect_distractor`，但必须用独立的 `pool_role` 区分其在实验池中的作用；`unresolved` 不进入确认性负例；
- 100% 通过结构规则和单人内容复核；
- 至少 20% 按数据集、相似度和干扰类型分层双人独立复核；
- 最高相似度带、所有等价良性冗余对照、所有分歧项和所有可能的 false negative 必须由第二人复核；
- 报告 Cohen's \(\kappa\) 或 Krippendorff's \(\alpha\)、分歧数量和仲裁规则；
- 不能只用生成干扰项的同一个 LLM 判定其是否错误；
- 训练、调参和 Blind 中不得复用同一基础 Query、证据文档族或变换模板实例。

候选—Query 关系对所有进入确认性压力池的候选执行上述复核；候选对不做 \(O(K^2)\) 全量人工标注。Top-M 近邻代理的构件效度使用按“数据集 × 事实关系 × 相似度 × 冲突类型”分层抽取的固定审计集，样本量由先导中的类别比例与目标 CI 宽度确定，并在正式方法训练前冻结；同一 Query/文档族内的近邻对视为相关样本。

> **概念解释｜Cohen's κ 与 Krippendorff's α**：二者都是标注者一致性指标，会扣除“碰巧一致”的部分。κ 常用于两名标注者；α 更容易处理多名标注者、缺失值或不同数据类型。数值越高通常表示标注规则越清楚，但仍应同时报告分歧案例。

## 7. 数据集与划分

### 7.1 冻结的数据组合与使用角色

| 数据 | 角色 | 最低规模与要求 |
| --- | --- | --- |
| `Lo/rerankers-and-lexical-similarities`（优先使用 DRUID 子集） | 外部复现“相似候选下语义 Reranker 失效”现象；对应 RQ1/RQ2 | 使用带 `is_gold_chunk`/`is_helpful_chunk` 的有效样本；固定 dataset revision；仅作现象验证，不因缺少三路分数而强行用于来源融合主实验 |
| 新内部 Stress Blind v6 | 项目现实性与复杂版本/编号/同文档干扰 | 至少 100 条未曝光 Query；不得复用 Blind v4/v5 调参 |
| C-MTEB `T2Retrieval` | 通用中文搜索 | 至少 100 条有效 Query；固定 revision 与 qrels |
| C-MTEB `MedicalRetrieval` | 术语密集、条件相近的领域检索 | 至少 100 条有效 Query；固定 revision 与 qrels |

中文主实验与内部 Blind 的起始目标为至少 300 个唯一 Query；`rerankers-and-lexical-similarities/DRUID` 作为额外的英文现象复现集，不用来补足这 300 个样本。300 是低成本起始规模，不是保证统计功效的硬上限；最终确认性样本量由先导实验的成对效应和方差决定。

> **概念解释｜功效分析**：功效分析根据预期效应大小、数据波动和显著性标准，估算需要多少 Query 才有较大概率发现真实效应。样本太少容易把真实差异判成“没有差异”，样本过多则浪费标注和计算成本。

这 300 条用于标准 Clean 排序评测和可构造率审计，不表示每条 Query 都人工构造 50 或 100 个干扰并运行全部因子。低成本分阶段预算为：

1. 全部有效 Query 运行 Clean 基线与三路候选快照；
2. 先导后按数据集、约束覆盖率和错误类型分层，以功效分析冻结“确认性压力核心”；主退化曲线只在该核心上运行；
3. 完整 2×2、逐类型和特征组消融在核心的预注册分层子集上运行；`n=50` 只在能满足资格规则的共同 cohort 上运行，`n=100` 另作可选敏感性分析；
4. 进入任一确认性压力分析的候选仍须 100% 内容复核，不能通过扩大未审候选量换取样本数。

因此，总 Query 数与最重压力条件的 Query 数是两个不同预算参数；后者由先导功效分析和可构造率在看方法结果前冻结。

数据组合按下列流程使用：

1. 在 `rerankers-and-lexical-similarities/DRUID` 上复现已有语义 Reranker 相似性退化，确认本项目的模型和指标实现没有偏离既有事实；
2. 在 `T2Retrieval + MedicalRetrieval` 的公开 Query、Corpus 和 qrels 上重新执行冻结的 Dense/Sparse/BM25，生成来源证据完整的候选快照；
3. 从三路候选超集中挖掘并核验自然 Hard Negative，再围绕 Gold 构造事实错误型反事实 Chunk；
4. 在新内部 Stress Blind v6 上做未曝光确认性测试，既有 Blind 只作历史动机；
5. 主文分别报告“现成自然候选”“公开数据压力扩展”和“内部 Blind”，不得将三者混成一个总分掩盖域差异。

### 7.2 可选增强数据

| 数据 | 纳入条件 | 用途与边界 |
| --- | --- | --- |
| C-MTEB `EcomRetrieval` | 预算允许且 revision/qrels/许可证审计通过 | 第一优先增强；型号、规格、数字和条件差异适合构造事实错误型相似干扰 |
| `DuReader-Retrieval` | 能承担大语料召回成本，或先冻结可复现子集 | 多检索器池化与人工标注降低测试 false negative 风险，作为高质量中文外部验证；不进入最低包 |
| `RedQA`（RARE） | 公开下载物、revision、许可证和 qrels 结构均完成审计 | 高相似、高冗余语料的相关外部基准；其重点是冗余感知和多跳覆盖，不能替代本文的事实错误干扰与多路来源融合实验 |

C-MTEB 当前提供上述检索数据和 qrels；正式接入前仍需固定数据 revision、文件摘要、许可证和再分发条件。任何公开 qrels 中未标相关的高相似候选，都只能视为“待审负例”，必须先处理漏标相关项风险。

### 7.3 划分纪律

> **概念解释｜Train、Tune、OOF、Blind 与 OOD**：Train 用于拟合模型；Tune 用于选特征、阈值和超参数；OOF 是开发集内部的折外预测；Blind 是开发期间完全不看的最终确认集；OOD（域外）是来自不同领域或分布的数据，用于检查跨域泛化。

> **概念解释｜数据泄漏与分组切分**：如果同一文档的新旧版本、相邻 Chunk 或同一反事实模板同时出现在训练和 Blind，模型可能靠记忆取得虚高成绩。分组切分要求这些相关样本整体进入同一集合。

> **概念解释｜Seal（封存）与揭盲**：封存表示 Blind 的数据、标签和运行规则被冻结；揭盲是第一次查看最终结果。揭盲后再调模型，就会失去 Blind 的确认性资格。

- 数据集内部按 Query、Gold 文档族和干扰模板三重分组划分 Tune/Blind；
- 同一原始 Chunk 生成的多个反事实版本不得跨 Fold；
- 同一文档的新旧版本不得跨训练和测试；
- 所有阈值、相似度带、Top-M、特征和模型超参数只在 Tune/OOF 上选择；
- Blind 每个版本只运行一次并 seal；揭盲后只能用于报告，不得回调；
- 现有 Blind v4/v5 仅可作历史动机，不进入新方法选参或最终显著性结论。

## 8. 对比方法与消融

### 8.1 最低基线

> **概念解释｜无监督基线、学习基线、诊断基线与新方法**：无监督基线不使用相关性标签学习参数，例如 RRF；学习基线用训练数据学习排序，例如 LambdaMART；诊断基线 D1—D3 用于排除更简单的解释；M1 是本文唯一拟检验的新方法。

> **概念解释｜Fixed Weighted Fusion 与 RRF**：固定加权融合先把各路分数归一化，再按固定权重相加；RRF（Reciprocal Rank Fusion）不直接比较分数，而把候选在各路的倒数排名相加。RRF 对分数量纲较不敏感，但不能自动判断某条路当前是否不可靠。

> **概念解释｜Semantic Reranker**：语义 Reranker 在小候选池中进一步读取 Query 与 Chunk 的语义关系并重新打分，通常比单纯词法匹配更强，但也可能把“语义很像、事实条件错误”的候选排得过高。

| 编号 | 方法 | 作用 |
| --- | --- | --- |
| B1 | BM25 | 词法精确匹配基线 |
| B2 | Dense | 语义检索基线 |
| B3 | Learned Sparse | 学习稀疏基线 |
| B4 | Fixed Weighted Fusion | 当前稳定生产基线 |
| B5 | RRF | 无监督秩融合基线 |
| B6 | Semantic Reranker A | 第一种独立模型家族 |
| B7 | Semantic Reranker B | 第二种独立模型家族 |
| B8 | LambdaMART v3 | 现有 38 维强基线 |
| B9 | Local Similarity Dedup/Quota | 按 Top-M 相似邻域做简单去重或配额，检验收益能否由普通冗余抑制解释 |
| B10 | Exact-Constraint Hard Filter | 仅基于 `method_view` 中 Query 显式给出的版本、数字、否定和条件做确定性过滤/降权；待回答槽保持 unknown，检验学习方法是否必要 |
| D1 | v3 + Density-only | 只加入 Top-M 相似度及 Query/Local crowding，不使用约束冲突或冲突条件化路由优势 |
| D2 | v3 + Query-Constraint-only | 只加入推理期显式约束错配，排除收益来自更强单候选约束抽取 |
| D3 | v3 + Matched-Capacity Untyped Local | 用同等数量的无类型局部相似度和普通 route margin 匹配 M1 容量 |
| M1 | v3 + Local Conflict Route | 加入局部冲突风险、最大冲突相似度和六个分路冲突 Margin |

两个语义 Reranker 必须来自不同训练或架构家族，不能只更换同一 API 的模型尺寸。模型 ID、版本、量化、最大长度、截断和推理日期必须冻结。

> **概念解释｜独立模型家族**：两个模型只有参数量不同、但训练数据和架构基本相同，不能算独立证据。选择不同架构或训练来源的 Reranker，是为了检验退化现象是否只属于某一个模型系列。

> **概念解释｜量化、最大长度与截断**：量化是用更低精度表示模型参数，以节省显存和提高速度，但可能改变打分；最大长度是模型一次能读取的 token 上限；超过上限后删除部分文本叫截断。三者都会影响排序结果，所以必须记录并冻结。

### 8.2 必要消融

- 去除 `LocalCrowd`，只保留约束与路由特征；
- 去除 `LocalConflictRisk/MaxConflictSimilarity`，只保留普通邻域密度与路由特征；
- 去除全部 `ConflictAdjustedRouteMargin`，检验来源条件化是否必要。

自然冲突、合成冲突和事实等价良性冗余仍分开报告，但不各自扩展一套模型。只有 M1 同时相对 B8 与 D1—D3 具有样本外增量，才能支持“局部冲突风险条件化来源融合”这一方法贡献；若 B9/B10 已解释全部收益，应将结论收缩为简单去重或约束过滤。

### 8.3 最优期刊增强基线

> **概念解释｜强基线与近邻工作基线**：强基线是当前已知有竞争力的方法；近邻工作基线是与论文创新最接近的方法。新方法若只击败弱基线，却没有与最接近的研究比较，创新结论通常不够可信。

若目标锁定《计算机科学》或《数据分析与知识发现》，在官方代码、数据接口和计算资源可直接复用的前提下，只增加 **一个** 最接近的方法基线：优先 HybRank；若其复现成本明显高于 M1 本身，则改用 QuDAR 类局部 Margin 加权。MoR、完整候选协作图和 Top1 策略选择只放在相关工作与局限中，不同时展开。

若无法复现原模型，应说明接口或资源原因，并保留容量匹配的 D3；不能声称已经击败未实际运行的方法。

## 9. 指标与统计计划

### 9.1 构件有效性指标

方法进入排序主实验前，先独立检验推理期可观测冲突代理是否成立：

> **概念解释｜Accuracy、Precision、Recall、F1 与宏平均**：Accuracy 是所有样本中预测正确的比例，但类别极不平衡时可能虚高；Precision 关心被判为冲突的样本有多少真的冲突；Recall 关心真实冲突被找回多少；F1 是 Precision 与 Recall 的调和平均。宏平均（Macro Average）先分别计算每个类别的指标，再给各类别同等权重求平均，因此不会让数量最多的类别完全主导结果。

> **概念解释｜PR-AUC**：PR-AUC 汇总不同阈值下 Precision 与 Recall 的权衡；在“真正冲突的近邻对较少”的类别不平衡场景中，它比 Accuracy 更能反映冲突代理是否有用。

- **候选/近邻对构件效度**：在人工核验的候选—Query 关系和 `constraint_consistent/conflicting/unknown` Top-M 近邻对上，报告 \(\hat m\) 与 \(\hat{\chi}\) 的 PR-AUC、宏平均 F1 和分类型召回；`constraint_consistent` 审计样本必须包含“共享同一错误值但彼此一致”的候选对，类别不平衡时不以 Accuracy 为主指标；
- **查询级机制关联**：按 `ObservableConflictCrowd` 低/中/高三档报告同一 Reranker 的 Clean→Stress `EG-nDCG` 退化、EG-Top1 翻转和目标等价组排名位移；该分析用于解释风险随局部冲突增加是否上升，不另训练风险分类器；
- **方法增量效度**：比较 D1—D3 与 M1 的 Blind 排序增量，确认事实冲突信息提供超出纯密度、单候选约束和同容量无类型局部统计的信息；
- **良性对照判别**：高相似事实等价候选组不应被系统性判为高冲突；若无法区分良性冗余和错误共识，方法构件判定失败。

人工近邻对标签只用于构件验证，不进入测试时输入；M1 仍只用排序训练集的 relevance/qrels 学习。所有阈值和模型选择均在 Tune/OOF 冻结。

### 9.2 常规排序指标

> **概念解释｜@k**：指标后的 `@k` 表示只看排序前 k 个结果。例如 Hit@10 只检查前 10 名，nDCG@10 只计算前 10 名的排序质量。

> **概念解释｜Hit、Recall、MRR 与 nDCG**：Hit@k 只问前 k 名有没有至少一个相关结果；Recall@k 问全部相关证据中找回了多少；MRR 主要看第一个相关结果出现得多靠前；nDCG 同时考虑相关等级和排名位置，越相关且越靠前贡献越大。

- 等价组封顶的 `EG-Hit@1/5/10`；
- 等价组封顶的 `EG-Recall@5/10`；
- 等价组封顶的 `EG-MRR@10`；
- 等价组封顶的 `EG-nDCG@10`；
- 基于数据集官方 qrels 的标准 Hit、Recall、MRR、nDCG，作为并列敏感性结果。

等价项不得被忽略，也不得作为多个重复正例无限增加收益。对每个 Query，将 `relevant_gold` 与 `relevant_equivalent` 按 `equivalence_group_id` 归组；每组 gain 取该组冻结 relevance grade 的最大值，经核验的合成等价项继承父等价组而不新建 gain。排序中同一等价组第一次出现时获得该组 gain，后续成员 gain 为 0，IDCG 也按唯一相关等价组计算。`EG-Recall@k` 统计命中的相关等价组比例，`EG-Hit@k` 统计是否命中任一相关等价组，`EG-MRR@k` 使用第一个相关等价组的名次。

> **概念解释｜Gain、DCG、IDCG 与 nDCG**：Gain 是相关结果带来的收益；DCG 让靠前结果贡献更大；IDCG 是该 Query 在理想排序下能达到的最大 DCG；nDCG = DCG/IDCG，因此通常位于 0—1。本文按等价组封顶，避免同一正确事实的重复文本被多次奖励。

> **概念解释｜EG（Equivalence-Group-Capped）指标**：EG 指“按等价证据组封顶”。同一正确事实即使有很多近重复 Chunk，也只记一次收益。这样既不会把等价证据误判为负例，也不会因为复制了很多正例而机械抬高指标。

若一个 Query 需要覆盖多个不可替代事实，它们必须属于不同等价组；不能把所有正例粗暴并成一组。公开数据原始 qrels 若无法可靠映射 equivalence group，则标准官方指标继续报告，但该 Query 不进入需要等价良性冗余对照的确认性 2×2 分析。

确认性压力实验的主连续指标冻结为 `EG-nDCG@10`，主离散失效指标唯一冻结为 `EG-Top1 正确→错误翻转率`；`EG-Hit@10` 翻转为次要离散指标。官方 qrels 的标准 `nDCG@10` 仍作为外部可比结果。多正例数据不能沿用只返回命中与首个相关倒数排名的简化 `_metrics`。

### 9.3 鲁棒性指标

> **概念解释｜鲁棒性**：鲁棒性不是只看 Clean 平均分高不高，而是看条件变难、干扰增多时性能下降多少，是否出现大量原本正确却变错误的 Query，以及最坏分组是否仍可接受。

- 目标等价组最佳成员的排名位移；原始 Gold ID 的排名位移只作敏感性分析；
- Top1 正确到错误的翻转率；
- 干扰 Chunk 晋升率；
- 基线正确而新方法失败的 Hit-loss rate；
- 查询级 Win/Tie/Loss 和负收益比例；
- 最坏 10% 查询的平均差值；
- 数据集 × 干扰类型 × 相似度的最坏分组表现；
- Clean—Stress 性能权衡；
- 退化曲线面积。

设 \(M(q,n)\) 为注入 \(n\) 个干扰项时的 `EG-nDCG@10` 或其他预注册指标，定义正向退化量：

\[
D(q,n)=M(q,0)-M(q,n)
\]

主曲线对 \(n\in\{0,5,10,20,50\}\) 用梯形法计算并按最大干扰数量归一化：

\[
nAUDC_{0:50}(q)=\frac{1}{50}
\sum_t \frac{D(q,n_t)+D(q,n_{t+1})}{2}(n_{t+1}-n_t)
\]

`nAUDC` 越小表示整体退化越弱；若为负，表示干扰条件下反而提高，仍须检查是否由标签漏标、候选替换规则或偶然正例引起。

> **概念解释｜退化曲线与 nAUDC**：把横轴设为干扰数量、纵轴设为相对 Clean 的性能下降，就得到退化曲线。nAUDC 是曲线下面积的归一化版本，汇总所有剂量下的总体伤害；越小表示整体越抗干扰。

> **概念解释｜Win/Tie/Loss、负收益率与最坏 10%**：Win/Tie/Loss 按 Query 统计新方法变好、不变或变差；负收益率是变差 Query 的比例；最坏 10% 专门观察受伤最严重的 Query，避免平均提升掩盖少数严重失败。

主 `nAUDC_{0:50}` 对每个 Query 使用同一条预注册嵌套替换链和完整剂量点，只在共同 cohort 上计算；不得把不同 n 的不同 Query 集合拼成一条曲线。分层 20% Query 的第二随机种子只用于抽样敏感性分析。具备 `n=100` 条件的共同子集另报 `0—100` 曲线，不与主结果混算。

为隔离“相似”与“事实冲突”，先在固定数量下定义高相似条件的简单差分：

\[
\Delta_{\text{conflict}>\text{equiv}}
=
\bigl[M(\text{clean})-M(\text{high-sim conflict})\bigr]
-
\bigl[M(\text{clean})-M(\text{high-sim equivalent})\bigr]
\]

该值显著大于 0 才支持“事实冲突型拥挤的额外伤害”，不能用高相似候选数量本身替代这一对照。

进一步用完整 2×2 定义机制交互：

\[
\Delta_{\text{interaction}}
=
\bigl[M(\text{low-sim conflict})-M(\text{high-sim conflict})\bigr]
-
\bigl[M(\text{low-sim equivalent})-M(\text{high-sim equivalent})\bigr]
\]

\(\Delta_{\text{interaction}}>0\) 表示相似度升高对事实冲突条件造成的额外伤害大于其对等价条件的影响，是 H2 的直接检验。只有具备完整 2×2 和可靠等价组标注的数据源进入该交互的确认性汇总。

### 9.4 统计检验

> **概念解释｜置信区间、统计显著与效应量**：置信区间表示估计值的不确定范围；统计显著通常表示数据不太支持“差异为零”；效应量表示差异实际有多大。样本很多时很小的差异也可能显著，因此三者应一起报告。

> **概念解释｜Bootstrap**：Bootstrap 通过反复有放回地重采样 Query，估计指标差值的波动和置信区间。本文按 Query/文档族分组重采样，是为了保留同组样本之间的相关性。

> **概念解释｜McNemar exact**：McNemar exact 用于同一批 Query 上两个方法的成对 0/1 结果，例如一个方法 Top1 正确而另一个错误的次数是否明显不对称。

- 主连续指标、`nAUDC_{0:50}`、2×2 交互和 M1 相对各强基线的差值，统一报告按 Query/文档族分组的成对 bootstrap 95% CI；
- Top1 正确→错误翻转使用 McNemar exact；
- Top-M 近邻代理的 PR-AUC/F1 也按 Query/文档族分组重采样，不把同一 Query 内近邻对当独立样本；
- Holm 校正只覆盖预注册的四个主方法比较：M1 对 LTR-v3、D1、D2、D3；数据集和错误类型分组以效应量与 CI 为主，不扩展大量事后显著性检验；
- 同时报告绝对变化、置信区间、Win/Tie/Loss 和最坏分组，不用“趋势看起来单调”替代预注册的剂量曲线。

> **概念解释｜多重比较与 Holm 校正**：同时检验很多模型、数据集和干扰类型时，即使都没有真实差异，也容易偶然出现“显著”。Holm 校正会逐步收紧判断标准，控制整体误报风险。

### 9.5 成本与资源指标

> **概念解释｜p50、p95、增量成本与 Cold Start**：p50 是一半请求能达到的延迟，p95 关注较慢的尾部请求；增量成本只计算在已有检索结果上新增方法的开销；Cold Start 则把向量重新编码、模型加载等不能复用的成本也算进去。

最低报告同时覆盖 FixedFusion、LTR-v3、D3、M1 和两个语义 Reranker：

- 单 Query Top-M 邻域、特征构造和排序的 p50/p95 wall-clock latency；
- 峰值 CPU/GPU 内存、批大小、线程数、设备和候选 K；
- 约束抽取、候选相似矩阵、route margin 与模型打分的分阶段耗时；
- 语义 Reranker 调用次数、输入 token 数和外部 API 成本（若有）；
- 复用上游 Dense 向量的增量成本，以及无法复用时从文本重新编码的 cold-start 成本，两种口径分开。

M1 默认不读取 Reranker 输出。只有在相同硬件和 K 下，M1 的增量 p95 延迟与峰值资源低于全量语义 Reranker，且调用次数为 0，论文才可使用“低成本”表述；否则改写为“无需重训 Reranker 的局部冲突感知融合”，不声称成本优势。

## 10. 最低可发表实验包与增强实验包

> **概念解释｜最低可发表包与增强包**：最低可发表包是支撑核心 RQ 和主要贡献不可缺少的证据集合；增强包用于提高论文上限，但失败时不应推翻已经成立的核心研究。把两者分开可以控制学生团队的时间和预算。

### 10.1 最低可发表包（RQ1—RQ3）

下列“主曲线”“完整 2×2”和机制实验均指先导后由功效分析冻结的确认性压力核心/分层子集；约 300 条总样本不要求机械运行全部重条件。各实验必须报告相对全体有效 Query 的覆盖率和选择流程。

1. 新内部 Stress Blind + `T2Retrieval` + `MedicalRetrieval`；
2. 两个独立语义 Reranker；
3. 固定候选池的 0/5/10/20/50 主退化曲线；`n=100` 只作资格子集敏感性分析；
4. 固定 `n=20` 的低/高相似度 × 事实等价/冲突完整 2×2；
5. 版本/时间、数字、否定、条件缺失四类冲突和来源支持分层；

7. 固定分层审计集上的候选—Query 与 Top-M 近邻对构件效度；

10. 分组成对 bootstrap CI、McNemar exact 和四个主比较的 Holm 校正；

13. 完整的数据、模型、split、环境和结果 manifest。

> **概念解释｜Manifest（实验清单）**：Manifest 是一份机器可读的实验“装箱单”，记录本次运行使用的数据版本、切分、模型、参数、代码提交、环境和输出文件摘要。它让别人能准确重建同一次实验，也能发现结果是否来自不同版本的混用。

该包完成且结果支持假设时，足以形成一篇有明确现象、机制和方法增量的中文论文；若新增方法只在内部合成集有效，应主动降级投稿目标。

### 10.2 可选增强包（不改变 RQ1—RQ3）

> **概念解释｜Leave-one-domain-out 与跨域迁移**：Leave-one-domain-out 是用若干领域开发模型，把一个从未参与训练的领域留作测试；它比随机切分更能检验方法是否只适用于熟悉领域。

- 增加 `EcomRetrieval`；
- 在复现成本可控时增加 HybRank 或 QuDAR 类基线中的一个；
- 做 leave-one-domain-out 或 train-two-test-one 跨域迁移；
- 增加 `n=100` 饱和压力和第二随机种子的覆盖；
- 发布可复现的干扰构造脚本、元数据和不受版权限制的派生标注；
- 在新 Blind 上只运行一次预注册模型。

### 11.2 撞车结论

- **未发现与中英文拟题完全相同的公开论文题名**，但精确题名无命中不等于没有概念撞车；
- “语义 Reranker 会被相似干扰误导”已经有直接文献，不能声称首次发现；
- “利用 sparse/dense 上游相似度与候选上下文重排”已经被 HybRank 覆盖，不能声称首次提出；
- “查询级自适应多检索器融合”已经被 MoR、QuDAR 等覆盖，因此本文明确不把门控作为研究问题；
- “Similarity Crowding”作为本文操作性术语尚有命名空间，但密度本身不是充分创新；必须区分事实等价的良性冗余与事实冲突的错误共识，并证明 M1 相对 D1—D3 有独立排序增量；
- 当前可辩护空隙是：**在冻结现成 Reranker 的条件下，用 Top-M 局部冲突风险和冲突条件化分路 Margin 打破整体语义分数对事实差异不敏感的问题，并以良性冗余对照/事实冲突处理实验验证低成本鲁棒融合。**

## 13. 先导实验与 Go/No-Go 门禁

> **概念解释｜先导实验**：先导实验是正式投入大量标注和开发前的小规模验证，目的是估计现象是否存在、效应大小和数据波动，不用于反复调定义追求正结果。

> **概念解释｜Go/No-Go 门禁**：Go 表示证据达到预定标准，可以进入下一阶段；No-Go 表示核心前提不成立，应停止或收缩研究；Inconclusive 表示证据不足，既不能当作成功，也不能简单当作失败。

### 13.1 低成本先导实验

正式开发前先设计一个不超过 100 条 Query 的验证包：

- 内部、T2Retrieval、MedicalRetrieval 各取分层样本；
- 两个语义 Reranker；
- 干扰数量先取 0、20、50；
- 相似度取低、高两档，与完整 2×2 的因子水平保持一致；
- 条件至少包含 Clean 普通负例，以及低/高相似度 × 事实等价/冲突的完整 2×2；
- 冲突类型先取版本/时间、数字、否定、条件缺失四类；近重复作为表面形式，必须再区分事实等价或冲突；
- 比较固定融合、RRF、语义 Reranker、LTR-v3；
- 计算不带学习调参的初版 Top-M 冲突代理，并审计它能否区分事实等价与冲突、其高风险分层是否对应更大 Reranker 退化；
- 只验证现象、关键对照和低成本代理是否成立，不在此阶段优化新排序模型。

### 13.2 Gate A：现象与代理门禁

在开发 M1 前同时满足下列条件才 Go。默认最小实际效应在首次先导运行前冻结为：\(\epsilon_{phen}=0.02\) `EG-nDCG@10`、代理相对 prevalence 的 PR-AUC 增量 \(\epsilon_{prev}=0.05\)、相对 similarity-only 的增量 \(\epsilon_{sim}=0.02\)。若团队希望修改，必须在看到任何先导结果前写明业务/统计理由并产生新研究记录版本。

> **概念解释｜最小实际效应 ε 与 Prevalence 基线**：ε 是团队事先认定“即使统计显著，也至少要达到这么大才值得继续”的效果门槛；Prevalence 是正类在数据中的比例，如果模型的 PR-AUC 只等于 prevalence，通常说明没有比按比例猜测提供更多区分能力。

1. 在 `n=20` 的高相似条件，合并分层的 \(\Delta_{conflict>equiv}\ge\epsilon_{phen}\)，分组 bootstrap 90% CI 下界大于 0；
2. 两个 Reranker × 三个来源的 6 个单元中至少 4 个方向为正，且必须同时覆盖两个 Reranker 和至少两个来源；
3. 从 `n=0→20→50` 的退化方向在至少 4/6 个单元为正，不能只由 `n=50` 单端点驱动；
4. LTR-v3 相对语义 Reranker 的 `EG-nDCG@10` 保护在合并结果至少为 `+0.01`，且方向要求同第 2 条；
5. 不使用 qrels、Gold 身份或注入元数据的初版代理，在冻结分层审计集上满足 `PR-AUC - prevalence ≥ 0.05` 且 `PR-AUC - similarity-only ≥ 0.02`，并在至少两个来源方向一致；
6. false negative 复核后上述效应仍成立，固定候选实验排除了上游召回变化解释。

若点估计达到门槛但 CI 或跨来源规则未满足，结果记为 `Inconclusive`，不得边开发 M1 边继续调定义；只能先按功效分析新增一次预注册确认样本，或收缩为评测/机制研究。

### 13.3 Gate B：方法贡献门禁

Gate A 通过后才开发 M1。M1 冻结后必须同时满足：

1. 在确认性 Stress/Blind 上，M1 相对 `LTR-v3` 与 D1—D3 的主 `nAUDC_{0:50}` 改善均具有成对 95% CI 下界大于 0，且各主数据来源方向非负；
2. Clean `EG-nDCG@10` 相对 LTR-v3 的非劣界冻结为 \(\delta_{clean}=0.01\)，成对 95% CI 下界必须大于 `-0.01`；
3. M1 的主要收益不能被简单局部去重/配额或可观测硬约束过滤完全解释；
4. 方法输出通过 evaluator-only 字段置换不变性测试，且不读取注入数量、干扰类型、人工关系或 Gold 身份。

任一项失败即停止“新方法”扩展；若 Gate A 仍成立，可收缩为退化机制/评测论文。以下情况直接判为 Gate A No-Go：只有一个 Reranker 或内部合成集复现；良性冗余对照与事实冲突伤害不可区分；退化可由候选漏召、截断、API 失败或 qrels 漏标解释；只有 oracle 标签才能构造有效局部冲突特征。

> **概念解释｜非劣性界 δ**：非劣性检验不是要求新方法在 Clean 上一定更好，而是要求它“最多只能差一个可接受的小幅度”。这里 `δ_clean=0.01` 表示 Clean EG-nDCG 的下降不能超过预先允许的 0.01。

> **概念解释｜CI 下界大于 0 或大于 −δ**：差异的置信区间下界大于 0，表示在考虑不确定性后仍支持新方法更好；下界大于 `−δ`，表示最坏合理情况下也没有差到超过非劣界。

## 14. 允许与禁止的论文结论

> **概念解释｜结论边界与外推**：结论边界规定实验最多能支持多强的说法；外推是把有限数据上的结果推广到更广模型、领域或系统。本文只能对预定义候选、模型和数据条件作结论，不能写成普遍规律或安全保证。

### 在实验成立后允许

- 在预定义高相似干扰条件下，多种语义 Reranker 出现可重复排序退化；
- 相对高相似事实等价良性冗余对照，高相似事实冲突造成额外退化，表明伤害不能仅由候选密度解释；
- 可观测局部冲突风险与冲突条件化分路 Margin 和退化相关，并在分层审计中具有基本构件效度；
- 相对冻结 v3 与 D1—D3，M1 降低了 `nAUDC_{0:50}`、Top1 翻转和查询级负收益率；
- 方法在两个以上公开中文数据集和新内部 Blind 中保持方向一致；
- 在第 9.5 节成本门槛同时成立时，可表述为：在既定模型和候选预算下，低成本来源感知融合比全量语义重排更稳定。

### 无论结果如何都禁止

- “首次发现语义 Reranker 会被 Hard Negative 欺骗”；
- “首次提出 sparse/dense 来源感知重排”；
- “证明 LambdaMART 普遍优于神经 Reranker”；
- “证明检索改进必然提升生成答案质量”；
- “提供了形式化安全保证”或“彻底解决相似度拥挤”；
- 未经事实等价良性冗余对照就把退化归因为“高相似密度”或“错误共识”；
- 使用人工关系标签、注入元数据或 Gold 身份得到的 oracle 结果，冒充可部署方法结果；
- 把单一内部集合、单一 Reranker 或一次约 7% 增量外推为通用结论；
- 隐瞒合成 Chunk、历史 Blind 已曝光或现有 v3 已包含大量同类特征。

## 16. 研究冻结记录

> **概念解释｜研究冻结记录**：冻结记录列出当前版本不再随意改变的题目、假设、数据、方法阶梯、指标和停止规则。若以后确需改变，应产生新版本并说明原因，避免实验结果反过来修改研究问题。

1. 冻结中文题目为“高相似度干扰下检索增强生成的多路来源感知鲁棒融合方法研究”；英文题目冻结为 “Beyond Semantic Reranking: Retrieval-Route-Aware Robust Fusion under Similarity Crowding in RAG”；
2. 现有 LambdaMART v3 是强基线和工程资产，不是新论文的首创方法；
3. 冻结论文定位为“语义重排边界条件 + 良性冗余/错误共识的可控对照 + 冻结 Reranker 下的局部冲突风险条件化来源融合”；
4. 冻结一个主创新：Top-M 局部冲突风险与冲突条件化分路 Margin；其最低成立标准是同时相对 `LTR-v3` 与 D1—D3 在 Blind 和跨数据实验中表现出稳定增量；
5. 冻结两个必要支撑：Clean + 低/高相似度 × 事实等价/冲突完整 2×2、等价组封顶指标，以及语义重排由收益转为伤害的边界分析；
6. 冻结推理期方法只能使用 `method_view` 中的候选文本、生产可见元数据和三路分数/排名；qrels、Gold 身份、人工关系标签、`pool_role`、注入数量、父项和变换类型只能进入 `evaluation_view`，并以字段置换不变性测试防泄漏；
7. 冻结方法阶梯为 `LTR-v3 → D1 density-only / D2 query-constraint-only / D3 matched-capacity untyped-local → M1 local-conflict-route`，简单局部去重/配额和硬约束过滤必须作为解释性强基线；
8. 冻结当前论文的排除项：不构建持久化候选图或 GNN，不使用簇级拓扑和 Route Fragility，不开发学习门控，不使用强化学习生成干扰，不要求同时复现 HybRank、MoR、QuDAR；
9. 冻结两个独立能力：候选快照生成器只负责物化可复核的上游输入，纯离线融合/重排实验器只消费快照并比较排序方法；当前只冻结契约，暂不实现；
10. 冻结双轨实验：候选池干预为主要因果证据，语料/索引干预为外部有效性证据；
11. 冻结 Chunk 产生规则：公开数据原始 corpus record 直通，内部文档使用钉住版本的一次性确定切分；所有方法共享同一基础 Chunk 与候选快照；
12. 冻结干扰产生规则：自然负例须处理 qrels 漏标风险，合成反事实须保留父项和原子变更记录，所有合成项必须重算真实三路证据；
13. 冻结数据组合：`rerankers-and-lexical-similarities/DRUID` 用于英文现象复现，`T2Retrieval + MedicalRetrieval` 用于中文公开主实验，新内部 Stress Blind v6 用于最终确认；三类结果分别报告；
14. `EcomRetrieval` 为第一增强数据，`DuReader-Retrieval` 和审计通过后的 `RedQA` 为条件性增强，不纳入最低包；
15. 既有 Blind 和“约 7%”只作研究动机，不能进入新论文的确认性结论；
16. 冻结两条互斥投稿路线：路线 A 为英文 arXiv +《计算机科学》→《数据分析与知识发现》→《软件导刊》→《软件工程》→《现代信息科技》；路线 B 为英文 arXiv + JIIS → IJIT → IJMLC；正式投稿前只选择其中一条；
17. IEEE Access 冻结为路线 B 中有预算且时效优先时的付费替代选项，不进入默认投稿序列，也不与其他期刊同时投稿；
18. 正式实现新方法前，先完成不超过 100 条 Query 的 Go/No-Go 先导实验；当前仅冻结方案与实验契约，不改代码。
