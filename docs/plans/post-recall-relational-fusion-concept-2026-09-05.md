## 1. 要回答的问题

**三路召回已经结束。当两个候选很相似、但关键细节不同，明确比较这些差异，能否帮助融合／重排正确使用已有的三路证据？**

拆成两个可分别失败的问题：

1. 显式表示“哪个对象、时期对应哪个条件”，是否比现有特征更有用？
2. 在已经利用这些对应关系之后，根据候选对的差异调整三路证据的使用方式，是否还有增益？

第二个问题是本草案较强的方法假设。第一个问题成立，不能自动证明第二个。成对比较、局部交换和增加特征都只是实现手段，不能单独当成创新点。

## 2. 固定研究边界

输入固定为同一 Query、Dense / Learned Sparse / BM25 三路返回的候选、各路原始分数与顺序，以及这些候选本来就有的正文。输出仅改变候选顺序。

不改召回器、召回深度或切块，不补检索，不读取父文档，不给本方法单独增加时间／来源字段。未召回正确候选的情况不能靠本方法修复。所有方法共用相同候选快照。

当前 `RouteHit` 实际提供 `chunk_id / doc_id / dataset_id / score / source`，排名由列表位置得到；没有结构化年份或来源权威度。ID 只能标识／分组，不能解释成年份或可靠性。不得把评测中的变体类型、生成谱系或 gold 标签当作在线特征。

负责人提出的财报例子仍属于研究边界，但必须区分：

| 情况 | 本阶段可以做什么 |
| --- | --- |
| 年份在已返回正文里，只是没有被正确绑定到目标对象 | 可以尝试利用可见细节修正排序 |
| 两段数字不同，但年份在全部可用输入中都缺失 | 可以记录差异；不能仅据数字判断谁对应目标年份 |
| 两段来自不同年份，分别真实 | 研究与 Query 的适用性，不能直接标成一真一假 |
| 同一对象、时期、指标和单位下数值不一致 | 可以识别冲突；若没有方向证据，仍不能判定哪段为真 |

三路分数可以作为统计上的相关性证据，不是事实真伪的证明。若两种可能情况给算法的全部输入完全一样、正确答案却相反，任何仅使用这些输入的方法都无法保证区分。

## 3. 代码核查与已完成的小检查

核查对象是 [v3 特征构造](../../src/linkrag_eval/retrieval/learning_to_rank/experiment.py) 和 [在线排序](../../src/linkrag_eval/retrieval/learning_to_rank/online.py)。v3 有 38 个特征，已经使用三路分数／排名／缺失标记、整路前两名差距、数字与条件覆盖、整池词频、同文档相似度等。因此不能声称“现有方法完全不看候选上下文”。

它没有直接表示的是：**这一对候选在哪个对象／条件上不同，这个差异与双方的逐路优势怎样关联。** 缺少显式表示不等于模型完全不能间接利用相关信号。

### 已执行：手工构造的特征表示检查

Query：`标准版在2026年是否允许离线导出？`

| 文本 | 正文 |
| --- | --- |
| A | 标准版：2026年适用，允许离线导出。专业版：2025年适用，不允许离线导出。 |
| B | 标准版：2025年适用，不允许离线导出。专业版：2026年适用，允许离线导出。 |

A 明确提供“标准版—2026年—允许”的对应关系；B 的 2026 年描述属于专业版，不能直接回答标准版在该年的权限。

在两个候选的 ID、各路分数和排名固定时，交换 A/B 正文后，`build_online_features` 返回的整个矩阵完全相同：38 个特征中变化数为 0。同一确定性 v3 模型因此无法仅从这些特征对这次正文交换作出不同响应。

**这个结果只证明特征表示存在一个具体盲点。** 分数是手工固定的，实际召回器可能对正文变化产生不同分数；没有运行真实检索或模型效果评测。它也不能证明成对机制优于单候选条件分析，更不能证明关系与三路证据的交互有效。

## 4. 一个足够具体的候选实现

### 4.1 先找值得比较的候选对

在 v3 初始排序的一个固定前部范围内，用正文字符二元组重合度找近似候选，保留固定数量的候选对。字符二元组就是连续两个字符构成的片段；这里只用于筛选比较对象，不作为“人类语义相似度”的量尺。

先导实现可从前 20 个候选、最多 20 对开始；这是资源预算起点，不是已优化／冻结参数。若主指标是 nDCG@10，比较范围应允许跨越第 10 名。所有修正方法共用这组候选对，不能让完整方法单独挑更容易的样本。

### 4.2 只提取可见、可定位的细节关系

初版先覆盖有明确局部表达的年份、版本和否定／许可条件：分句后对齐相同的对象与属性，记录不同值，并保留支持该判断的原文片段。分句／字符串规则做不到可靠对齐时输出 `unknown`，不能悄悄假定拥有完整的语言理解能力。

关系至少区分：可对齐的取值差异、适用范围差异、未检出相关差异、无法判断。最后两项都不等于“语义等价”。同一数字分别属于利润和收入时，不能当成同一事实的冲突；“2025年不允许”与“2026年允许”也不是同范围矛盾。

同时分别记录两段对 Query 已知条件的匹配情况。Query 正在询问的答案值不能当作已经知道的条件；例如问“利润多少”不能因为某个数更常见就将其设为目标值。

这个提取器是尚待检验的组件。初版不使用额外模型或外部上下文，其覆盖面可能很窄；不能靠人工关系标签替代部署时的自动输出。

### 4.3 比较：这种差异下，应怎样理解三路的相对优势？

直观例子：Dense 给两段几乎相同的分数；BM25 更偏向包含目标年份的一段。如果年份确实属于目标对象，这个差距可能有用；如果它属于段落中的另一个对象，单纯的数字命中就可能误导。**是否应改变某一路的作用，以及改变多少，必须从独立训练数据学习，不能事先规定“数字题就信 BM25”。**

一个可检验的最小形式是：

\[
L_{ij}=A(q,c_i,c_j,h_{ij},\Delta b_{ij})
       +\sum_r \beta_r\Delta e^r_{ij}
       +\sum_r(\gamma_r^\top h_{ij})\Delta e^r_{ij}.
\]

- `L_ij`：支持候选 i 排在 j 前面的分数。
- `A`：利用相同的关系提取结果、Query 兼容性和原 v3 分差得到的修正；它不新增逐路分差输入。
- `h_ij`：这一对的差异类型、对齐状态等关系信息，交换 i/j 后保持不变。
- `Δe`：同一路对 i/j 的分数或排名优势，交换双方后变号。分数沿用同一归一化口径。令 `o_i^r` 表示该路是否返回 i，则分差通道定义为双方均返回时的 `s_i^r - s_j^r`，否则为 0，并以对称掩码 `o_i^r o_j^r` 区分“未测得”与“确实相等”；排名通道同理。命中差单列为 `o_i^r - o_j^r`，交换后也变号；双方命中总数可进入对称关系信息。求和可枚举三路的这些通道，不能将单边缺失标记直接作为有方向的加分项。
- 最后一项：允许“候选关系 × 逐路优势”发生交互，正是需要检验的部分。

`A` 也必须交换双方后变号，例如采用 `f(i,j,h,Δb) - f(j,i,h,-Δb)`。完整模型因此满足 `L_ji = -L_ij`，但这并不保证多个候选之间没有循环偏好。

若最后一项没有增益，就没有证据支持额外加入这种显式逐路交互。若关系对所有候选对都相同，最后一项也可能退化成普通分数重加权。`A` 已含 v3 分差，而 v3 本身使用三路信息，因此对照不能解释成“完全没有路由条件化”；可识别的是显式逐路交互项相对这些对照的样本外增量。

### 4.4 最多一次局部交换

初版只从原始排序的候选对中选择一个符合规则、最支持反转的候选对，交换其位置，其余位置保持不变；没有合适候选对时保持原序。关系无法对齐时不触发这项细节修正。不迭代交换，暂不引入全局图排序。

一次交换是为了便于分析改对／改错的原因，不是“最优排序”的主张，也不保证不会改坏。决策阈值应在独立 Dev 上按整个 Query 的选择流程确定；模型分数或 sigmoid 输出不能直接称为校准过的置信度。它也修不了需要连续多步调整的错误。

## 5. 用四个版本回答核心问题

| 版本 | 允许使用的信息 | 回答的问题 |
| --- | --- | --- |
| 原 v3 | 原有 38 特征 | 完整修正相对现有方法有多少总收益？ |
| 兼容性修正 | `A`；同样的关系与 Query 条件分析，原 v3 分差 | 是否读懂条件归属就足够？ |
| 相加修正 | `A + Σ β Δe` | 新增逐路分差仅以固定权重相加是否足够？ |
| 完整方法 | 再加入关系与逐路优势的交互 | 显式逐路交互相对这些对照是否有样本外增益？ |

三种修正版本共用候选对、提取器、交换次数限制和阈值选择程序。保持训练信息与调参预算可比；交互模型参数更多时，补一个规模相当的普通特征模型检查是否只是容量收益。不能用一个刻意弱化的兼容性模型证明交互必要。

v3 应在相同训练划分上训练，历史冻结模型可另列作运行参考。校正层使用的训练期 v3 分数应来自该 Query family 未参加训练的预测，避免把训练集上的过好分数交给第二层。一个 family 的原文、改写和干扰变体必须留在同一划分。

先用这组对照做探索。若有稳定增益，再选择公开近邻方法作外部比较；内部 v3 与消融足以帮助淘汰假设，但不足以证明相对现有研究的创新或优越性。

## 6. 精简实验依据，而不是降低严谨性

当前先导只需直接核对三件事：

1. **问题存在于实际候选中吗？** 在允许使用的已曝光 Dev 上找出“正候选已召回，但被相似且不适用的候选压住”的真实例子，按可用输入检查能否判断。手工例子不能估计发生率。
2. **自动表示抓得到吗？** 检查差异提取的正确性和覆盖率，并记录未触发／误触发；只检查方法实际使用的判断，不要求先验证一套跨领域通用七分相似度量表。
3. **哪部分真正有用？** 比较上述四个版本，允许结果否定较强主张。

已有 28 个 Internal v6 Dev 接纳 family 全属 `detectable_only`，不能据此声称已备齐可判方向的评测集。未解决的标签不是真值，未标注候选也不自动作为负例。不恢复或利用已删除的 R2 仲裁后结果，不查看封存 Blind 来挑方法。

进入效果验证前，要有与 Query 适用性对应的可信相关性标签；候选对优劣来自相关性，而不是“两个字符串不同”。真实例子与合成压力例分别报告，人工判断只用于标签／审计，不作为在线方法输入。原始语料与变体之间的事实真值须另有依据。

建议主指标为每个 Query 的 nDCG@10；辅助报告 Top1 正确数、改好／改坏／不变数、交换覆盖率和总延迟。全部 Query 都计入总体结果，不能只在触发修正的子集报收益。置信区间按独立 Query family 重采样，不能把同一 family 的大量变体当成大量独立证据。时间成本应包括配对、细节提取和决策，不只计算模型预测。

解释应随结果收缩：只优于 v3，不能直接宣称交互创新；兼容性修正已达到同等表现，就优先保留较简单方法；只在合成模板有收益，就只主张该受控场景。样本量不足或区间宽时报告不确定，不用一串额外门槛把它包装成确定结论。

## 7. 与已有研究的距离

下表来自对方法部分的定向核查，不是穷尽查新；2026 年两项为预印本，不能据此保证新颖性。

| 已有工作 | 已覆盖的内容 | 本草案必须额外说明什么 |
| --- | --- | --- |
| [HybRank，ACL Findings 2023](https://aclanthology.org/2023.findings-acl.880/) | 利用稀疏／稠密检索相似度与候选间协作做重排 | 泛称“候选关系＋多路信息”不够，需验证具体细节关系的作用 |
| [PRP](https://arxiv.org/html/2306.17563v2) | 成对比较、输入换序检查及滑动窗口局部排序 | 成对比较／交换不是独立新意 |
| [CoDeR，2026 预印本](https://arxiv.org/html/2606.13204v1) | 学习约束兼容性；Seq 变体在原候选池上筛选／融合 | 必须比较单候选约束兼容性，不能只用“召回后处理”区分 |

候选贡献表述：**研究并实现一种利用近似候选的可见细节关系，调整逐路相对证据作用的局部排序修正方法；通过相同信息条件下的对照，检验显式逐路交互的额外价值。** 这仍是待证的研究计划，不是已取得的贡献。

## 附：特征表示检查的复现代码

在仓库根目录使用 `.venv/bin/python -B` 执行以下代码；只构造内存数据，不访问数据库、召回服务或模型。它不属于正式效果实验。

```python
import numpy as np
from linkrag_eval.retrieval.learning_to_rank.experiment import (
    FEATURE_NAMES, build_online_features,
)

query = "标准版在2026年是否允许离线导出？"
a = "标准版：2026年适用，允许离线导出。专业版：2025年适用，不允许离线导出。"
b = "标准版：2025年适用，不允许离线导出。专业版：2026年适用，允许离线导出。"
routes = {
    route: [
        dict(chunk_id="toy-a", doc_id=1, dataset_id=1, score=score, source=route),
        dict(chunk_id="toy-b", doc_id=2, dataset_id=1, score=score-0.1, source=route),
    ]
    for route, score in [("dense", 0.8), ("sparse", 5.0), ("bm25", 8.0)]
}
ids1, x1 = build_online_features(
    query=query, routes=routes, candidate_contents={"toy-a": a, "toy-b": b},
)
ids2, x2 = build_online_features(
    query=query, routes=routes, candidate_contents={"toy-a": b, "toy-b": a},
)
print(len(FEATURE_NAMES), ids1 == ids2, np.array_equal(x1, x2))
# 核查时输出：38 True True
```
