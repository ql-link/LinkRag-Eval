## 2. System boundary and parallel ranking design

### 2.1 LinkRag and LinkRag-Eval

LinkRag is the operational RAG system in which the ranking pattern was observed. LinkRag-Eval is an isolated evaluation project with its own SQLite result store and evaluation-prefixed retrieval assets. It is designed to consume official LinkRag candidate/ranking contracts where necessary but does not treat serving history as research data or write research artifacts into serving stores. The Eval-only adapter has now been migrated away from the removed `BucketRouter`, and the CI configuration has been updated to the audited LinkRag revision (`861f2481…`). Python 3.11 unit/contract/import-boundary checks, fixed-vector LTR-v3 replay, and the required live-stack checks pass locally. This remains a preflight rather than a formal snapshot because both repositories must be clean and a remote green CI run must be recorded. A machine-readable `contract-lock.json` records both clean repository commit/tree identities, candidate-contract signature, LTR feature/model hashes, runtime dependencies, backends, and a redacted configuration digest. A dirty-worktree preflight may record tracked-diff and untracked-content hashes for diagnosis but cannot release the formal snapshot gate.

The term *source* in the original Chinese title means **retrieval route**. It does not mean author, publisher, institutional provenance, or credibility. The English study therefore uses *retrieval-route-aware*.

### 2.2 Implemented retrieval-to-ranking path

| Stage | Audited LinkRag behavior | Scientific implication |
| --- | --- | --- |
| Route retrieval | BM25 uses Manticore. Dense and learned-sparse retrieval use two named vectors in Qdrant. Each route has an ordered raw-hit list and its own candidate depth; dense and sparse also have score-threshold overrides. | These are three heterogeneous evidence routes over two storage backends, not three calibrated truth probabilities. |
| Coarse fusion | BM25 and sparse scores receive `log1p`; dense scores remain unchanged. Scores are min–max normalized within route, missing-route contribution is zero, and weights are renormalized across routes with hits. Default BM25/sparse/dense weights are `0.15/0.15/0.70`. | The operational coarse baseline is fixed weighted-score fusion, not RRF. RRF is an offline comparator. |
| Candidate contract | A readiness gate removes unavailable chunks before outward truncation. Internal `candidate_hits` retain the complete visible, deduplicated, coarsely fused pool; `route_hits` retain ordered per-route raw hits, with rank derived from list position. Neither field is public API output. | Research snapshots can preserve actual route evidence instead of reconstructing it from a final score. |
| Final ranker: `active` | Local LambdaMART v3 replaces remote semantic reranking. Ranker-level model/contract failure, inference error, internal budget overrun, or the frozen low-confidence short-query rule returns the LTR bundle's own weighted fallback. | This is the current development configuration and strongest project-derived baseline. |
| Final ranker: `baseline` | The LTR bundle's frozen weighted fallback is returned without local model inference or remote semantic reranking. | This isolates learned-ranking value. |
| Final ranker: `off` or `shadow` | The legacy remote reranker may run only for datasets that enable it. In `shadow`, sampled requests admitted by the bounded executor attempt local LTR on a separate frozen request; only completed tasks yield a comparison, and none changes the served order. | Semantic reranking and local route-aware LTR are alternative final-ranking branches, not serial stages. |

For `active` and `baseline`, the frozen candidate profile requires all three routes, sets the executable dense and sparse thresholds to zero, and chooses route depths by query type. BM25 has no runtime score-threshold override; its `0.0` value exists only in the serving-contract metadata. A missing or failed required route fails closed; a successfully executed route with zero hits is recorded as empty.

Coarse fusion and LTR fallback are two distinct weighted orders. Recall coarse fusion operates on the candidate-profile output with default weights `0.15/0.15/0.70`. The LTR fallback computes each route's contribution using frozen dense/sparse/BM25 thresholds `0.30/0.20/0.0`. A candidate below one route's threshold can still receive contributions from other qualifying routes; only a candidate with no qualifying route contribution receives a zero baseline score and enters the ordered tail. The two weighted orders may therefore differ without changing the candidate set.

The legacy semantic-rerank branch groups candidates by dataset and uses that dataset's frozen RERANK binding. Results fill the original dataset-specific slots, so scores from different models are not pooled. A provider/model-call failure preserves fusion order within the affected dataset's slots while other groups may still be reranked. By contrast, expiry of the outer whole-rerank timeout discards the unfinished result and returns the content-present fusion-order prefix truncated to `top_n`. Invalid and duplicate result indices are discarded; if any legal scored items remain, they are reranked and that group's unscored tail retains fusion order, whereas no legal index triggers group-level fallback. A required but missing binding is prevalidated as an error—even before final-mode selection—rather than replaced silently.

Serving modes do not naturally receive equal candidate windows. `active` and `baseline` use the complete internal `candidate_hits` after missing-content removal; the `off`/`shadow` serving branch passes the outward-truncated `response.hits` to the remote reranker. The common immutable window below is therefore a deliberate research control, not a claim that the serving branches are natively input-equivalent.

The research comparison is offline and parallel:

`three-route evidence → fixed coarse fusion → immutable candidate snapshot → {coarse-weighted baseline, RRF, reranker A, reranker B, LTR-v3, D1–D3, A0, M1} → evaluation-only labels and metrics`

M1 is an alternative final ranker after coarse fusion. It neither calls a semantic reranker nor consumes reranker scores. “Reducing reranker damage” means lower ranking loss on the same snapshot, not post-processing the reranker's output.

### 2.3 Why LTR-v3 closes much of the apparent novelty space

The frozen `candidate_difference_v3` contract has 38 inference-visible features:

| Feature family | Existing information |
| --- | --- |
| Route evidence | Raw/log/normalized scores, reciprocal ranks, and missing-route flags for dense, sparse, and BM25 |
| Cross-route and list context | Route overlap, pairwise rank gaps, per-route Top-1/Top-2 margins, and frozen weighted-baseline score/rank |
| Query form and query–candidate constraints | Query length/digit flag; identifier, number, negation, condition, ordinary bigram/trigram, and distinctive-bigram coverage |
| Candidate context | Same-document candidate count, maximum normalized character-bigram Jaccard similarity, and log content length |

Qrels, Gold identity, and historical scenario labels are not inference inputs. The bundle also freezes the feature signature, serving contract, checksums, and test vectors.

Consequently, multi-retriever LambdaMART, route scores/ranks, exact factual cues, ordinary route disagreement, and global score margins are not new contributions. M1 can add only typed candidate-to-neighbor conflict and route-relative margins against suspected conflicting neighbors. Its novelty depends on held-out incremental value over LTR-v3, capacity-matched untyped-local D3, and capacity-matched surface-only A0, not on renaming existing v3 features or combining known ingredients.

The available environment includes approximately 50,000 restored chunks, historical runs, an embedding cache, a BM25 index, and access to current remote vector retrieval. These assets reduce engineering uncertainty but do not provide the frozen query–qrel manifests, equivalence groups, verified conflict labels, provenance fields, or Dev/Gate A/Gate B cohorts required for confirmation.

## 4. Claim–estimand–falsifier ledger

The current research question is:

> With candidate size, Gold evidence, and recorded upstream evidence fixed across ranking methods, does similarity interact with factual relation so that conflicting near-neighbors cause more damage than equivalently similar valid evidence; can method-visible signals identify the subset in which corrective reordering is justified; and, only in that subset, does an M1 final ranker that does not consume reranker scores pass the full frozen comparator family, including novelty-critical LTR-v3, matched-capacity untyped-local D3, and matched-capacity surface-only A0?

| Claim | Role and estimand | Falsifier and surviving route |
| --- | --- | --- |
| **C1: equivalence-controlled degradation** | Primary phenomenon claim. At fixed dose, estimate the continuous similarity × factual-relation interaction, the matched high-similarity conflict-versus-equivalence contrast, and the dose degradation profile. | C1/Gate A is `Go` only when both pooled point estimates clear their frozen practical-effect thresholds and both two-sided 90% confidence-interval lower bounds exceed zero, with the frozen cross-cell replication rule. A non-positive point estimate or a two-sided 90% interval upper bound below the applicable practical threshold is `No-Go`; a positive estimate that has not passed while its interval still covers meaningful benefit is `Inconclusive`. A visually suggestive curve cannot substitute for these rules. |
| **C2: observable conflict and conditional adjudication** | Diagnostic claim. First test conflict detection; then test held-out identification of the correct member within natural conflict sets using explicit query constraints and route-relative evidence. Report coverage, discrimination, calibration, and increment over prevalence/majority, similarity-only, v3-only, untyped-local, and surface-only evidence. | Detection without correct-member evidence supports only a conflict-risk analysis. If adjudication lacks held-out incremental value across at least two main datasets, M1 is not developed. Unidentifiable cases retain frozen LTR-v3 order. Exact thresholds remain TBD before Gate A. |
| **C3: M1 incremental method value** | Conditional secondary claim after Gate A. M1 extends v3 with typed local disagreement and per-route score/rank margins against suspected conflicting neighbors. The novelty-critical comparisons are M1 vs LTR-v3, capacity-matched D3, and capacity-matched surface-only A0, with D1 density-only and D2 query-constraint-only as diagnostics. | C3 fails if any required Gate B comparison fails. The 11-item nAUDC family contains fixed fusion, RRF, both semantic rerankers, LTR-v3, D1–D3, A0, local deduplication/quota, and exact-constraint filtering. M1 must beat every item under the Holm-p plus Bonferroni-lower-bound rule; LTR-v3/D3/A0 must also reach the practical threshold. A separate three-item common-risk-set Top-1 family must satisfy the frozen non-inferiority margin, and Clean non-inferiority must pass its one-sided bound. C1/C2 may survive. |
| **M0: representation-gap explanation** | Optional mechanism-consistent diagnostic using natural and controlled minimal pairs: test whether factual-unit changes preserve dense similarity while learned sparse or BM25 separates them more strongly, and whether this predicts reranker flips after surface controls. | Absence of the gap removes this mechanism narrative only. It does not negate C1 and cannot establish causal truth reliability for a retrieval route. |

The primary continuous endpoint is equivalence-group-capped nDCG@10 (EG-nDCG@10), which caps the reward from multiple chunks supporting the same factual equivalence group at one group-level gain. A method-specific correct-to-incorrect Top-1 flip rate is descriptive: its risk set is the queries for which that method's Clean Top-1 belongs to a correct equivalence group. A within-method conflict-versus-equivalence test uses that shared Clean risk set; an M1-versus-baseline test uses the intersection on which both methods are Clean-correct. Method-specific rates with different denominators are not directly subtracted. For each novelty-critical baseline, Gate B computes the macro-pooled M1-minus-baseline flip-rate difference at doses 5, 10, 20, and 50 on one risk set held fixed across doses, then uses the maximum of those four differences as its single safety estimand. Every bootstrap replicate recomputes the four differences before taking the maximum. Its Bonferroni simultaneous upper bound must remain below frozen \(\delta_{flip}\). For each baseline and dataset, Clean-correct coverage is the equal-family mean of the within-family proportion of primary-cohort queries on which both methods are Clean-correct; eligible-family count is the number of families containing at least one such query. Both must clear preregistered floors. An empty or insufficient set is `Inconclusive`, not omitted. McNemar's exact test and all four transition cells are unadjusted diagnostics only; non-significance is not evidence of non-inferiority. Robustness over 0, 5, 10, 20, and 50 distractors is summarized by nAUDC: the trapezoidal area under the per-query EG-nDCG@10 degradation-from-clean curve, divided by the maximum dose; smaller values indicate less accumulated degradation. Official qrel-based nDCG, MRR, Recall, and Hit metrics remain mandatory so that the equivalence-aware metric cannot conceal conventional performance.

| DRUID subset | Required English phenomenon/construct replication where labels permit; outside the three-dataset Gate A denominator and Gate B method denominator |

The planned Gate A replication matrix is two independently trained or architecturally distinct rerankers × the three main datasets: six cells. A cell is positive only when both its preregistered cell-specific interaction estimate and its matched high-similarity conflict-minus-equivalence estimate are greater than zero. Per-cell significance is not required; uncertainty is adjudicated by the pooled co-primary tests. At least four cells must be positive while covering both rerankers and at least two datasets. Gate B uses the held-out T2Ranking and cMedQA2 cohorts plus Internal v6-Blind. MedicalRetrieval is excluded from the confirmatory denominator because its fixed upstream repository and derived card do not provide a clear data license. If licensing, qrel quality, qualified-conflict yield, or annotation cost later invalidates a main dataset, any reduced denominator and new replication rule must be versioned, powered, committed, hashed, and externally timestamped before Gate A results are read; at least two independent main datasets remain mandatory. Datasets cannot be removed because their effect is unfavorable.

At dose 20, one analysis row is a query × target-equivalence-group × factual-relation × matched-pressure-chain × reranker condition. The exposure is the arithmetic mean of the 20 candidate-level target-group similarities, standardized with dataset-specific Dev parameters; one pool-level degradation outcome is never copied to 20 candidate rows. Equivalent and conflicting chains are matched on their candidate-similarity distributions. Query family is the highest bootstrap cluster and retains all repeated rows. Each reranker × dataset cell obtains its own interaction estimate under these same exposure, common-support, outcome, and pairing rules; its matched high-similarity contrast is also computed within cell. Each family has equal total weight within a cell. The two pooled C1 estimands are the unweighted arithmetic means of the six cell-specific interaction estimates and six cell-specific high-similarity contrasts. Every dataset-stratified family bootstrap replicate recomputes all cells and both equal-weight means using the same sampled family indices. These cell estimates also serve the direction-replication rule; they are not six additional significance tests. An inestimable required cell makes the pooled C1 test `Inconclusive` rather than allowing post hoc reweighting; minimum cell size and the paired-bootstrap fallback are frozen before Gate A.

### 4.2 Multiplicity and practical importance

C1 uses an intersection–union gate: the continuous similarity-by-factual-relation interaction and the matched high-similarity conflict-minus-equivalence contrast are both necessary. Neither can rescue failure of the other. Dose shape, adjacent similarity bands, conflict-type strata, and individual reranker/dataset cells are supportive or sensitivity analyses rather than alternative significance routes. The high-similarity contrast retains a working practical-effect threshold of 0.02 EG-nDCG@10; a separate minimum interaction effect per one standard deviation of condition-level mean similarity will be derived from Dev variance and interpretability, powered, and frozen before Gate A. For C1, the point estimate must clear the practical threshold and the confidence-interval lower bound must clear zero; the interval is not required to clear the practical threshold.

C2 is tested only after C1 passes. It has exactly ten directional comparisons in one family: two tasks (conflict detection and correct-member adjudication) × five comparator classes (prevalence/majority, similarity-only, v3-only, untyped-local, and surface-only), each on one preregistered primary metric. Untyped-local uses untyped neighborhood similarity/density and ordinary local margins; surface-only uses length, edit distance, overlap, punctuation/format, and text-derived template similarity, so they are distinct. These are diagnostic classifiers, not the post-Gate-A ranking methods D1–D3/A0. Within each dataset, examples are weighted so that each query family has unit total weight; each method-minus-comparator metric difference is then averaged equally across the frozen eligible datasets. Gate B nAUDC and Clean differences use the same hierarchy: average queries within family, families within dataset, and datasets with equal macro weight. The same dataset-stratified family resamples are reused across all methods, comparisons, and doses, and each bootstrap replicate recomputes the full estimand. Gate B's primary Stress population is the frozen high-similarity verified-conflict chain, with a nonzero-natural dataset-specific natural/synthetic quota fixed from Dev qualification rates before Gate A; low-similarity, equivalent, mixed-relation, origin-stratified, and dose-100 results cannot substitute for it. Gate B has an 11-comparison nAUDC family and a three-comparison Top-1 non-inferiority safety family. For each superiority family, the same query-family clustered bootstrap samples produce (i) Holm step-down adjusted one-sided p-values and (ii) separately constructed Bonferroni family-wise 95% simultaneous lower and upper bounds. For family size \(m\), these use each effect distribution's \(\alpha/m\) and \(1-\alpha/m\) quantiles. The lower bound is used for positive confirmation; the upper bound is used only to declare a positive-looking effect clearly below its practical threshold. A confirmatory superiority comparison requires adjusted \(p<0.05\) and a simultaneous lower bound above zero. The Top-1 safety family uses Bonferroni simultaneous upper bounds against \(\delta_{flip}\). The memorandum deliberately does not call an ordinary or ad hoc interval a “Holm-adjusted CI,” nor present the two one-sided bounds as a single two-sided 95% interval. Bootstrap count, seed, and family membership are frozen before Gate A; unadjusted intervals are descriptive only.

## 5. Validity-threat matrix

| Reviewer objection | Design response | Defeating result or bounded conclusion |
| --- | --- | --- |
| A relevance-trained reranker making factual errors is predictable. | C1 does not count isolated errors. It estimates additional harm beyond equally similar valid evidence, the continuous interaction, dose accumulation, conflict heterogeneity, and replication. | Failure of the interaction or matched contrast ends the factual-conflict method route. Success is limited to the tested model/data/conflict ranges. |
| “Source-aware” implies credibility. | Use *retrieval route* consistently. Route scores and ranks are predictive observables, not authorities. | No claim about publisher credibility, provenance, or truth-source reliability is permitted. |
| M1 may be v3 with renamed neighborhood features. | Compare LTR-v3, D1 density-only, D2 query-constraint-only, D3 matched-capacity untyped-local, A0 matched-capacity surface-only, and M1 with the same learner, data, missing-value scheme, feature count, tuning budget, and computational budget. Also compare local deduplication/quota and exact-constraint filtering. | If M1 fails the frozen held-out rule against any novelty-critical comparator—LTR-v3, D3, or A0—the typed-conflict method claim is withdrawn. |
| Synthetic edits create a construction–detection loop. | Separate natural and synthetic results. Require a natural-only held-out analysis; group-split query/document/version/template families; use leave-one-conflict-type-out tests; compare with method-visible edit-distance/overlap/punctuation/length controls; retain exact transformation-template identity only as an evaluator-side oracle; permute relation labels and pseudo-types. A0 may compute template similarity only deterministically from `method_view` text. Freeze task-specific Gate-A bounds \(\boldsymbol\epsilon_{surf,A}\), a natural-only reverse-effect margin \(\delta_{nat}\), and the Gate-B nAUDC bound \(\epsilon_{M1}\). Gate A judges the common isolation checks, the natural-only high-similarity contrast, the surface diagnostic, and label/pseudo-type permutation; it does not wait for post-Gate-A A0/M1 ranking or route-assignment tests. | Group/leakage failure invalidates the run. The natural-only check passes only with minimum coverage, a positive point estimate, and the lower end of a two-sided 90% interval above \(-\delta_{nat}\) (equivalently, a one-sided 95% lower bound); a clearly meaningful reverse effect fails, while remaining uncertainty is `Inconclusive` and does not authorize M1. Surface comparisons require their metric-specific practical-effect bounds, Holm-adjusted p-values, and Bonferroni simultaneous lower bounds; a Bonferroni simultaneous upper bound below the practical threshold defines clear low efficacy. Label/pseudo-type persistence beyond tolerance defeats C2. Held-out-type failure is non-gating: it limits cross-type generality but does not erase a valid C1 for tested types. Gate-B A0 or route-permutation failure/inconclusiveness defeats C3. |
| Disagreement does not identify which candidate is correct. | Separate detectable, conditionally adjudicable, and unidentifiable cases. Learn the support rule on Dev; test correct-member identification on held-out natural conflicts. Preserve LTR-v3 order outside demonstrated support. | If route/query evidence detects conflict but cannot identify the correct member, no corrective fusion branch is justified. A degradation/identifiability paper may remain. |
| Route evidence may encode popularity, duplication, or index bias. | Control for v3 route features, untyped local margins, document frequency, length, duplication, same-document context, and surface similarity; stratify by dataset/conflict/origin; permute candidate-to-route assignments. | Route evidence is reported as held-out association, never as causal factual reliability. Failure under cross-dataset or route permutation removes the route mechanism and M1 branch. |
| Two rerankers cannot support a universal statement. | Require two distinct families and at least two independent datasets; freeze model identities before confirmation. A third family is optional external validation. | Conclusions name the tested families, languages, datasets, conflict types, candidate budgets, and dates. No universal semantic-reranker claim is made. |
| The literature gap and any “first” claim are not established. | Treat the current map as targeted, update retrieval-stage factual-conflict, context/knowledge-conflict, counterfactual-RAG, DRUID descendants, redundancy-aware reranking, and relevance-versus-correctness searches before submission. | The gap wording is search-bounded and is weakened or removed when closer work is found. No priority claim attaches to individual ingredients. |

The gap is not asserted through the conjunction of every design choice. The two self-standing contributions are narrower: C1 estimates a controlled equivalence-versus-conflict interaction on a fixed candidate pool, and C2 tests a detectable/conditionally-adjudicable/unidentifiable partition using inference-visible evidence. C3 is conditional incremental value over LTR-v3, matched-capacity D3, and matched-capacity surface-only A0. Each contribution has its own estimand and falsifier; none relies on a generic “first to combine” claim.

Selective prediction is deferred because making risk–coverage the primary output would change the research question and system interface. The proposed `unknown` rule is only a restraint on unsupported reordering, not a claim of calibrated abstention.

## 6. Experimental logic, gates, and feasibility

### 6.1 Isolation and analysis

The principal Track A experiment uses immutable candidate snapshots. Every ranker receives the same query, chunk texts, identifiers, and dense/learned-sparse/BM25 evidence. At each dose, stress candidates replace matched ordinary negatives rather than enlarge the pool; candidate count, Gold equivalence groups, and group gains remain fixed. Synthetic candidates receive genuinely recomputed route evidence before snapshot freezing.

`method_view` contains only inference-visible query, text, metadata, route scores/ranks, and deterministic features. `evaluation_view` contains qrels, Gold/equivalence/conflict labels, pool role, parent edit, and dose. Removing or permuting `evaluation_view` must not change any method score or order.

A smaller Track B inserts validated distractors into a separately versioned corpus/index and tests end-to-end external validity. Track B cannot substitute for Track A's ranking-stage effect because indexing changes candidate supply. Its failure does not retroactively negate a valid fixed-pool C1/C2/C3 estimate; it requires withdrawal of index-level, end-to-end, deployment-robustness, and production-generalization claims and explicit reporting of the Track A/Track B mismatch. If Track B is not run, the same external-validity claims are unavailable.

Query, document, version, and transformation-template families are group-separated across Dev, Gate A, and Gate B. Dev may change rules. Gate A tests C1/C2 without D1–D3/A0/M1 ranking-model development. Only a Gate A `Go` permits those methods to be trained. Gate B evaluates frozen methods once on held-out cohorts.

### 6.2 Decision consequences

| Result | Required action |
| --- | --- |
| C1 interaction or matched control fails | Stop the factual-conflict method route; do not redefine similarity or conflict after seeing the result. |
| C1 holds but conflict measurement fails | Remove the diagnostic explanation and M1; retain only independently valid phenomenon findings. |
| Conflict is detectable but correctness is not adjudicable | Preserve LTR-v3 order; report the detectable/unidentifiable boundary; do not develop M1. |
| Gate A passes but any required Gate B comparison fails, including LTR-v3, D3, or A0 | Withdraw C3; C1/C2 may support an analysis/evaluation paper. |
| M1 improves Stress but violates frozen Clean non-inferiority | Report the trade-off and failed gate; do not claim a generally safer final ranker. |
| Track A/Gates pass but Track B is null or negative | Retain only the supported fixed-pool ranking claims; withdraw end-to-end and deployment-generalization claims. |
| All frozen Gate A and Gate B conditions pass | Claim C1, supported portions of C2, and a scope-limited secondary C3 method contribution. |

Gate A sample size is determined by calibration and grouped power analysis, not an arbitrary 100-query cap. If the required sample exceeds the frozen annotation or compute budget, the outcome is `Inconclusive` or the claim is narrowed; evidence thresholds are not reduced to force `Go`.

For the current study ID, `No-Go` is terminal. A non-positive necessary point estimate or the applicable efficacy upper bound below its practical threshold is `No-Go`: C1 uses the two-sided 90% interval upper end, multiplicity-controlled C2/C3 comparisons use the Bonferroni simultaneous upper bound, and the natural-only check uses its explicit reverse-effect rule. A positive estimate that has not passed while its applicable bound still includes meaningful benefit is `Inconclusive`. Only Gate A `Inconclusive` permits at most one power-justified extension that preserves the estimand, labels, dataset denominator, and thresholds; its scope, cap, stopping point, and pooled analysis are timestamped before the added outcomes are read. Gate B is one-shot: failure or inconclusiveness withdraws C3, and no supplementary Blind sample may be pooled into a later pass. Choosing instead to narrow the paper does not convert the same Gate to `Go` and does not authorize M1. A later protocol using new definitions, datasets, or splits is a new study and cannot be pooled with a failed Gate A to retroactively declare this study successful.

Before Gate A is unlocked, the sequence is fixed: generate and qualification-check the immutable Gate A snapshots without reading confirmatory rankings; freeze a root manifest over protocol, analysis code, data/split, snapshot, and configuration hashes; bind code and protocol to clean commits/tags; compute the root SHA-256; externally timestamp that root hash (OSF Registries by default); then save the timestamp receipt as an append-only sidecar that references but is not included in the root hash. The Gate A run manifest records both identifiers. Only protocol metadata and hashes are registered when data cannot be disclosed.

For Gate B, define \(\Delta^{nAUDC}_{M1>b}=nAUDC_b-nAUDC_{M1}\), so a positive value favors M1. The 11-comparison method family comprises fixed fusion, RRF, the two rerankers, LTR-v3, D1–D3, A0, local deduplication/quota, and exact-constraint filtering. All methods must have complete Clean and 5/10/20/50 outputs on the same primary cohort. Query values are averaged within family, families within dataset, and the frozen datasets with equal macro weight; every bootstrap replicate recomputes this hierarchy. Every prespecified pooled comparison requires a Holm-adjusted one-sided \(p<0.05\) and a Bonferroni family-wise 95% simultaneous lower bound above zero; the novelty-critical LTR-v3, D3, and A0 pooled point estimates must additionally reach the pre-M1 frozen \(\epsilon_{M1}\). For every main dataset and every novelty-critical baseline, the dataset-specific point estimate must be non-negative, without requiring 11-by-three separate significance tests. The three Top-1 safety estimands are the worst, over doses 5/10/20/50, macro-pooled M1-minus-baseline flip-rate differences on pair-specific Clean-correct intersections; each must have a Bonferroni simultaneous upper bound below pre-M1 \(\delta_{flip}\), and every baseline-by-dataset risk set must clear frozen eligible-family and coverage floors. Clean EG-nDCG@10 against LTR-v3 uses the same macro weights and a query-family-clustered one-sided 95% lower bound (equivalently the lower end of a two-sided 90% interval), which must exceed \(-0.01\). Route-assignment permutation must remove the route-specific increment within frozen tolerance. Failure or inconclusiveness of any required comparison withdraws C3 rather than changing the threshold.

Reproducibility requires versioned corpus/query/qrel manifests, grouped split manifests, equivalence/conflict annotations, immutable snapshots, code/model/data fingerprints, complete query-level rankings, and replay checks. Natural hard negatives, all highest-similarity candidates, all equivalent candidates, and suspected false negatives receive enhanced review. Synthetic items retain the parent chunk, exact edit, type, rationale, and recomputed retrieval evidence.

Public-corpus releases will use stable record IDs, permitted qrel amendments and annotations, split/construction scripts, and replayable score manifests subject to source/model licenses. Copyrighted text and internal raw data will not be redistributed without permission. If the public result cannot be independently rebuilt or replayed, a resource contribution will not be claimed.

## 7. Review resolutions and remaining calibration items

| Review issue | Resolution |
| --- | --- |
| C1 primary, C3 secondary | Adopted. C1 survives independently if its own gate passes; C3 failure cannot be relabeled as method success. |
| Construction–detection circularity | Natural-only, grouped-family/template, surface, permutation, and held-out-type controls now have explicit failure consequences. Numerical equivalence/tolerance bounds remain Dev-calibrated quantities. |
| Truth identification | Adopted as detectable/conditionally-adjudicable/unidentifiable. Corrective reordering is prohibited outside held-out support. |
